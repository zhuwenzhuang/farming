# Farming v2.2.56

[简体中文](./v2.2.56.zh_cn.md)

Milestone codename: **BOUNDARY**

This patch release makes Agent, Session, Browser, and Project Files ownership more explicit while removing file-tree feedback loops and large-directory failure modes.

## Reliable Agent and Session actions

- Agent Sessions can now be marked for durable follow-up. The flag survives restart, archive and restore, and runtime changes, appears in Project counts, and is intentionally not inherited by a Fork.
- Detached Provider Session rows now resume in place, while Archive removes a row only after the Provider mutation succeeds. Concurrent Resume and Archive actions are serialized through one exact Session identity so they cannot undo each other.
- Chat refresh no longer temporarily resets the model picker, and stale Code or CRT clients perform at most one no-cache reload after a protocol upgrade before reconnecting to current backend state.

## Faster, stable Project Files

- Large expanded trees now use a bounded virtual row projection with one native Project scrollbar. Sticky context is derived only from structural rows and viewport input, preventing rendered overlays from feeding back into their own source state. File and Agent reveals share one revocable scroll owner, so stale delayed work cannot pull the tree away from newer navigation or direct user input.
- Directory structure loads independently from Git and ignored decorations. Very large decoration reads are split at both protocol-message and subprocess-argument boundaries instead of failing or remaining pending above 4,096 entries.
- Project Files search now uses Farming's version-pinned native ripgrep 15.2.0 through one bounded, cancellable path with explicit failure instead of system or WebAssembly fallbacks.
- Exact read-only files outside every Project open directly without expanding Files or attempting an impossible tree reveal; reconnect and ordinary file reveals retain their authoritative target.
- Creating a file or folder keeps its parent expanded through the authoritative refresh. Renaming an expanded directory moves its open descendants with it, and keyboard file activation keeps focus in the tree so follow-up rename, menu, and delete commands remain available.

## Resource ownership and packaging

- Every Browser Resource now belongs to one active Agent and appears only in that Agent's Resource section. Upgrade migration cleans the runtime and profile of retired Project-owned Browser rows before removing their persisted identity.
- Project Archive preserves manually and dynamically pinned Sessions; explicit Project removal remains the operation that cleans up the Project's owned work.
- Agent rows have more consistent compact spacing, and a subject-neutral editorial systems-sketch style capsule is available for architecture and process illustrations.
- The managed Codex ACP Adapter is updated from 1.6.0 to 1.6.2 with the reviewed Farming patch and immutable runtime digest retained. Release preparation and publication now reuse the same tested exact-SHA artifacts.
- Standalone Linux arm64 CLIs now carry architecture-neutral bundled JavaScript and are executed with a native PTY smoke under arm64 emulation before publication.

## Upgrade

```bash
npm install --global farming-code@2.2.56 && farming daemon
```
