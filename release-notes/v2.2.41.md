# Farming v2.2.41

[简体中文](./v2.2.41.zh_cn.md)

Milestone codename: **DOC**

This release makes supervising many Agents at once fast and predictable. The backend shares Agent runtimes and streams state incrementally, Chat renders live work progressively, and every interface now explains what to do when frontend and backend versions drift apart.

## Runtime scalability

- ACP Agents in the same project share runtime processes and provider connections instead of each starting their own, reducing startup time and memory with many concurrent Agents.
- Turn results and adaptive titles persist asynchronously, so finishing work no longer blocks the next prompt.
- Repository worktree discovery is shared and refresh concurrency is bounded, keeping large Projects responsive.
- Slash command discovery is cached per provider and workspace.
- A stale ACP runtime host is detected and reported instead of silently degrading sessions.
- Shared runtime session summaries merge into existing state instead of replacing it, so a partial update no longer drops fields it did not carry.

## State streaming

- The Agent list arrives as a progressive snapshot followed by exact incremental mutations, so large inventories render quickly and stay consistent.
- Activity, session previews, and Chat revision updates are scoped to what each browser is actually viewing, cutting idle traffic without missing updates.
- Project summaries are maintained incrementally and delivered first, and Farming CRT scopes its updates to the focused Agent.

## Chat

- Transcripts render progressively, and a live answer holds a stable snapshot while its Turn runs, publishing the final text once the Turn settles. Live progress stays visible in the process area, and readers who prefer reduced motion receive every update immediately.
- Reading position stays where you left it while an answer streams, so scrolling back to read is no longer undone by the next revision.
- A transcript delta that extends a session is appended directly instead of forcing a full reload, so the first Turn of a new session appears without a checkpoint round trip.
- The process disclosure keeps a single open state per Turn and collapses automatically when that Turn completes.
- Recovered sessions restore their titles, fork origins appear as transcript events, and transcript reads are coalesced during recovery.
- The commit prompt is clearer, live progress streams while an Agent works, and Review and commit stays unavailable until the current Turn finishes.

## Supervision

- Agent archive actions are unified across menus with consistent icons, and archive confirmations acknowledge process exit where required.
- Agent details show Browser and Computer resource counts, multi-browser activity previews are supported, and preview streaming is limited to the front card.
- Browser tabs opened from Chat stay bound to their explicit Resource instead of becoming stopped duplicates, and opening a full Browser Viewer reveals the owning Agent's Resource row.
- Browser resources and their shared runtime are reclaimed when their owning Agents stop.
- Hover previews keep their Browser and Computer counts current while the preview stays open.
- An Agent dragged to the end of its Project stays there instead of being pulled back into the paginated rows.
- Share links copy in one step from the QR panel.

## Installation and updates

- Farming Server verifies its package image before starting and fails with an explicit missing-file error instead of serving a partially installed runtime.
- An npm update prepares startup runtimes in staging before publishing the new package image, so a failed preparation never leaves a published version that cannot start.

## Product documentation

- Farming now ships a bilingual product documentation site with task-oriented setup, feature, workflow, and operations guides backed by current product screenshots.
- The README exposes the documentation as a primary entry point alongside the language switcher.

## Compatibility

- The browser protocol advances to version 8. On a version mismatch, every interface now shows an actionable upgrade prompt naming which side to update, including released clients connecting to a newer backend.
- `farming` control help is side-effect free.

## Upgrade

```bash
npm install --global farming-code@2.2.41 && farming daemon
```
