# Farming v2.2.27

[简体中文](./v2.2.27.zh_cn.md)

This is primarily a transactional-consistency release. It systematically closes concurrency and recovery races across Agent lifecycle, ACP Chat, Project Files, Settings, updates, and Terminal runtime.

Farming now applies ACID-style rules inside each authoritative ownership domain: persist intent before external side effects, serialize conflicting operations, fence stale generations, atomically replace committed files, never replay an ambiguous network outcome, and recover interrupted transitions after restart.

## Highlights

- Agent Create, Update, Delete, and Archive now use a lifecycle journal as write-ahead metadata history. Conflicting operations serialize or join, completed requests are deduplicated by operation identity, external mutations wait for startup recovery, and restart recovery consumes unfinished intent without launching a duplicate Runtime.
- ACP Prompt, Steer, Cancel, queued follow-ups, configuration changes, and child-Session control now have explicit Agent, Binding, Turn, and operation owners. Per-Agent admission preserves message order; duplicate cancellation joins one request; stale Bindings and late updates cannot mutate replacements; ambiguous failures are not automatically replayed.
- ACP Fork preserves the exact source revision, child transcript, patch decisions, provider identity, and cleanup responsibility. A process loss or unproven cleanup fails visibly instead of silently creating a second child or losing the identity that still needs cleanup.
- Browser commands capture request ownership before their first asynchronous boundary. Late responses cannot clear newer loading state, steal focus, overwrite a replacement Agent or file, or submit the same Create, Rename, Delete, Settings, or main-page membership operation twice. Timed-out or disconnected requests reconcile from authoritative state instead of guessing whether the write committed.
- Project Files mutations serialize per canonical workspace, recheck content or directory versions inside that queue, write through unique temporary files, flush before close when supported, and atomically rename completed content into place. The browser's revisioned working copy preserves newer drafts when older saves finish, while uncertain mutations use bounded authoritative rereads and are never automatically replayed.
- Agent persistence now separates low-frequency lifecycle and process-ownership metadata in `agent_*.json` from high-frequency ACP, attention, and read state in `agent_*.state.json`. Each record file is replaced atomically through a temporary file, legacy records migrate to stable `agent_*` identities on first mutation, and hot state writes cannot overwrite safety-critical process identity or lifecycle history.
- Restart and upgrade recovery now use precise Runtime ownership. Legacy ACP records resume their exact saved Provider Session under the default configuration; newly owned processes retain cleanup identity; packaged daemons record the actual listening Server PID; and Native PTY Hosts use private socket listeners plus inode-owned public links so overlapping Server generations cannot strand or delete a live Terminal Runtime.
- npm and Bundle updates prepare in staging while the current Server remains available. Applying the prepared version is a separate restart transition, and a failed npm directory switch restores the previous package before restart.

## Changed

- Codex collaboration activity appears as a compact named `updated` / `finished` Chat timeline linked to its exact Process evidence.
- A readable absolute file path clicked in Terminal output can open in the read-only Project Files surface, including line and column targets. The request authorizes only that exact file; it does not authorize browsing its parent directory, and writes remain workspace-scoped.

## Consistency boundary

These are ACID-style guarantees within Farming's declared owner: one Server process, its persisted Agent records, and its serialized per-resource operations. Farming does not claim a distributed transaction with another Farming Server, arbitrary external filesystem writers, or a remote Provider. When an external outcome cannot be proven, the operation stops visibly and converges through authoritative rereading rather than unsafe replay.

## Known limitation

- When an older Codex Session was created in another Codex surface, Provider history may omit its collaboration graph, Agent names and statuses, or Fork lineage. Farming restores the conversation and Process evidence it receives, but does not reconstruct missing collaboration metadata from generic tool calls.
