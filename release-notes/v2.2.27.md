# Farming v2.2.27

[简体中文](./v2.2.27.zh_cn.md)

This release consolidates every shipped product change since `v2.2.21`. It closes the remaining Agent, ACP, Terminal, Project Files, settings, and update race windows while keeping older ACP and Terminal Sessions automatically recoverable across restart and upgrade.

## Fixed

- Serializes ACP prompt, steer, cancellation, and queued-message admission per Agent. Ambiguous failures are never replayed, definite turn-end failures preserve message order, and messages submitted during cancellation start at most once after the previous Turn reaches a terminal state.
- Gives every observed ACP child Session an isolated control owner. Duplicate stops join one provider request, parent cancellation includes children proven active, stale bindings cannot mutate replacements, and late updates cannot reopen completed child state.
- Automatically restores ACP Chat records created before process-group identities existed. Upgrade recovery resumes the exact saved Provider Session without per-Session operator confirmation, while newly started ACP processes immediately persist the precise identity used by later cleanup.
- Journals Agent Create, Update, Delete, and Archive before external side effects and recovers unfinished operations without launching duplicate runtimes. Frequently updated ACP and attention state is separated from lifecycle and process-ownership metadata.
- Preserves exact ACP Fork state and provider identity for Codex and process-owned Claude forks, including bounded child transcripts, patch decisions, startup rollback, and failed-cleanup reporting.
- Fences Project Files saves, Create, Rename, Move, and Delete across browser and backend owners. Late responses cannot steal newer UI state, uncertain mutations reconcile from authoritative filesystem reads without replay, and newer drafts survive older save completions.
- Closes remaining request-ownership races in Farming Code, CRT, Agent Home settings, main-page Session membership, and daemon control. Packaged daemons now run directly under the recorded Server PID so stop and release smoke verify the actual listener rather than a shell wrapper.
- Keeps live native Terminal Sessions reachable when Farming server generations overlap. Each native PTY host owns a private listener and publishes the stable config-bound socket as a hard link; an obsolete host cannot remove a replacement host's link when it exits.
- Recovers a missing public native-host link only when exactly one matching private listener is live. Multiple matches fail visibly, and controlled rotation waits for the exact private listener to exit before starting its replacement.
- Upgrades safely from `v2.2.23` hosts whose legacy `ping` omitted the private path by resolving the listener through the shared socket inode. Removing the public link is never treated as proof that the old host stopped.

## Changed

- npm and Bundle updates prepare into staging while the current server remains available. Applying a prepared update is a separate restart action, and a failed npm package-directory switch restores the previous package before restart.
- Codex collaboration activity appears as a compact named `updated` / `finished` Chat timeline. Selecting an event expands and focuses its exact Process evidence without exposing internal collaboration events as writable Agents.
- Readable absolute file paths rendered by a Terminal open directly in the read-only Project Files surface, including line and column targets. The backend accepts only the exact readable file; directories, missing files, and unreadable paths remain rejected, while write operations remain workspace-scoped.
