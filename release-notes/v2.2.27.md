# Farming v2.2.27

[简体中文](./v2.2.27.zh_cn.md)

This note consolidates the product changes shipped after `v2.2.21` into the latest valid release.

## Fixed

- Restores ACP Chat records created before process-group identities existed under the default configuration. After an upgrade, Farming resumes the exact saved Provider Session through the normal ACP load path instead of requiring per-Session operator confirmation; strict cleanup diagnostics can still opt out explicitly.
- Bounds main-page Session membership and Agent Home settings requests to 15 seconds. An uncertain main-page mutation is reconciled from authoritative Settings, and an uncertain Agent Home save reloads the authoritative value instead of assuming whether the write committed.
- Serializes CRT Settings writes, applies the same 15-second request bound, and reloads authoritative Settings after a failed or timed-out save so a late response cannot silently overwrite newer UI state.
- Makes daemon ownership stable across environments by recording process identity from locale-independent UTC `ps` output. Packaged daemons now launch through `/usr/bin/env` directly, so the persisted PID belongs to the actual listening Server rather than a shell wrapper.
- Keeps live native Terminal Sessions reachable across overlapping Farming Server generations. Each Native PTY Host listens on a private socket and publishes the stable config-bound socket as a hard link; shutdown removes the public link only when its inode still belongs to that Host.
- Recovers a missing public native-host link only when exactly one matching private listener is live. Multiple candidates fail visibly, and runtime rotation waits for the exact private listener to disappear instead of treating removal of the public link as proof that the old Host stopped.
- Upgrades safely from `v2.2.23` Hosts whose `ping` response did not include the private socket path by matching the public and private socket `dev + ino` identity before rotation.

## Changed

- A readable absolute file path clicked in Terminal output can open in the read-only Project Files surface, including line and column targets. The request grants access only to that exact readable file; it does not authorize browsing its parent directory, and all write operations remain workspace-scoped.

## Known limitation

- When an older Codex Session was created in another Codex surface, provider history may omit its collaboration graph, Agent names and statuses, or Fork lineage. Farming restores the conversation and Process evidence it receives, but does not reconstruct missing collaboration metadata from generic tool calls.

## Verification

- Main-page Session, Agent Home, CRT Settings, daemon identity, and packaged Server PID ownership tests
- Native private-socket discovery, ambiguous-host rejection, replacement ownership, legacy-host rotation, controller fencing, and concurrent same-home Codex recovery tests
- Project Files terminal-link, exact external-file router, state-model, and browser regression coverage
