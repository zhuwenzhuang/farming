# Farming v2.2.22

[English](https://github.com/zhuwenzhuang/farming/blob/main/release-notes/v2.2.22.md)

里程碑代号：**TRANSACTIONS**

本次发布收敛 Agent 生命周期、结构化 Chat、Project Files、设置与更新流程中的竞态窗口，同时保留旧 ACP Session 的升级恢复能力。

## 修复

- 按 Agent 串行 ACP Prompt、Steer、Cancel 与排队消息准入。明确的 Turn 结束类 Steer 失败会保留消息顺序，不明确的失败绝不重放；Cancel 期间提交的消息只会在旧 Turn 到达终态后启动一次。
- 为每个已观察到的 ACP 子 Session 建立独立 Control Owner。重复停止合并为一个 Provider 请求；父级 Cancel 会包含仍能证明活跃的子 Session；旧 Binding 不能修改 Replacement，迟到更新也不能重新打开已到终态的子 Session。
- 自动恢复尚未持久化 Process Group Identity 的旧 ACP Chat。升级时直接加载精确的已保存 Provider Session，不要求用户逐个确认；新启动的 ACP 进程会持久化后续清理使用的精确身份。
- Agent Create、Update、Delete 与 Archive 在外部副作用前写入 Lifecycle Journal，并在重启后恢复未完成操作而不重复启动 Runtime。高频 Agent 状态与生命周期、进程所有权元数据分开存储，避免热写覆盖安全关键身份。
- 在浏览器和后端 Owner 上 Fence Project Files 的保存、创建、重命名、移动与删除。迟到 UI 响应不能夺取新状态；结果不确定的 Mutation 只通过权威文件系统读取收敛，不自动重放；较新的草稿不会被较早完成的保存清除。
- Codex 与进程内持有 Fork 的 Claude 均保留精确 ACP Fork 状态和 Provider Identity，包括有界子 Session Transcript、Patch Decision、启动回滚与清理失败报告。
- 为首页 Session 与 Agent Home 请求增加有界超时，串行 CRT 设置保存，并从权威设置收敛结果不确定的响应。Daemon Process Identity 在不同 Locale 下保持稳定。
- Packaged Daemon 直接运行在持久化的 Server PID 下，使 Linux Stop 与发布 Smoke 校验真正的监听进程，而不是 Shell Wrapper。

## 调整

- npm 与 Bundle 更新会先在当前服务继续可用时准备到 Staging。应用已准备版本需要再次确认重启；npm 目录切换失败时会在重启前恢复旧包。
- Codex 协作活动现在会在 Chat 中显示为紧凑的具名 `updated` / `finished` 时间线。选择事件会展开并聚焦它对应的精确 Process 证据，但不会把内部协作事件伪装成独立的可写 Agent。
