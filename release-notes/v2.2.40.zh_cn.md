# Farming v2.2.40

[English](./v2.2.40.md)

里程碑代号：**ANCHOR**

本次发布增强了 Chat 在后台运行、重连和 Server 重启过程中的连续性，同时持久保留用户明确设置的 ACP Session 配置，并提升 Agent 生命周期操作的安全性和可监督性。

## Chat 连续性

- 未打开的 Chat Transcript 可以提前准备，用户返回已完成的 Agent 工作时无需再次等待完整加载。
- 恢复后的 Transcript 现在通过同一个带 Checkpoint 的 Revision 边界切换，缓存与权威条目会一次性出现，不再重复或局部替换。
- Transcript Snapshot 刷新时会保留阅读位置，包括后台完成和重连路径。
- ACP Transcript 在保留 Provider 原始顺序的同时，以一致方式聚合紧凑的进度和工具摘要。

## Session 配置与恢复

- 用户明确修改的 ACP Session 配置（包括 Codex Fast 模式）会在重连、Server 重启、权限重启以及 Chat/Terminal 切换后继续保留。
- 未设置显式 Override 的 Session 仍继承所选 Agent Home 中的 Provider 默认配置。
- 可恢复的空闲 ACP Session 在延迟恢复过程中保留精确的 Checkpoint 和进程身份边界。
- Provider Fork 行为、Worktree 准入和持久化恢复元数据现在使用同一个权威能力契约。

## Agent 监督体验

- Adaptive Agent Title 可以通过安装后的 CLI 正确路由并跨重启持久化；高频更新会被合并，且不会覆盖用户指定的标题。
- Project 和 Agent 排序使用持久化的后端事务，Project 也支持拖动排序。
- Chat 新增 Agent Review and Commit 操作，并复用现有 Review 与 Workspace 所有权边界。

## Runtime 安全性

- Browser 和 Computer 能力共享带身份认证的 HTTP MCP Endpoint，不再为每个 Agent 重复启动 MCP 子进程。
- Browser Runtime 输出保留现在具有明确上限，同时保留活跃 Agent 恢复所需的核心证据。
- `farming stop` 会先尝试有界的优雅退出，必要时才升级为经过进程身份复核的强制终止。

## 升级

```bash
npm install --global farming-code@2.2.40 && farming daemon
```
