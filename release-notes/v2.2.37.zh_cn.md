# Farming v2.2.37

[English](./v2.2.37.md)

里程碑代号：**BEACON**

这是 v2.2.35–v2.2.37 开发线的规范门禁版本，也是该开发线上第一个仅在精确候选 Revision 通过完整 CI 后才发布的版本。本页合并了已下线的 v2.2.35 与 v2.2.36 GitHub Release 变更信息；它们的 Git Tag 与 npm 记录继续作为历史 Provenance 标识保留。

## 发布安全

- 发布提交对应的完整 `CI` Workflow 全部成功是第一条、不可绕过的发布门禁。任何 Job 缺失、运行中、取消或失败都会阻断发布；修复后必须形成新的候选 Revision，并重新开始发布验收。
- Release Workflow 会独立等待与候选 SHA 精确绑定、由 Push 触发的 CI Run，只有该 Run 成功才允许继续，否则严格关闭。
- 预发布指南要求解决每一个失败的 CI Check，并把生产依赖审计加入快速源码门禁。
- npm 来源校验会对 Registry 短暂的元数据传播窗口做有界重试，同时一旦发现版本属于另一个 Git Revision 就立即失败。
- 内置 `tar` 依赖升级到 `7.5.22`。

## 安装、更新与实例隔离

- 每个 Farming Server 独占一个规范化配置目录，并拒绝冲突 Owner。不同安装可以安全隔离认证、Session、Runtime 状态和更新元数据，同时继续使用外部共享的 Workspace 与 Provider Home。
- npm 安装使用隔离的 Package Version 生命周期完成更新。候选包先暂存和校验，修改安装目录前会证明精确 Server 进程已经退出且端口已释放；陈旧 Updater Metadata 也会被安全协调，源码与 Standalone 安装不会被误当作 npm 部署。
- npm 包携带经过审核的生产依赖集合，全新安装和更新使用包内确定的依赖图，不依赖无关的全局环境状态。

## Agent 完成通知

- 页面处于后台时，Farming 可以在 Agent 完成后通知用户。ACP Chat 使用权威 Prompt `stopReason`；Terminal Session 消费标准 BEL 与 OSC 通知协议，OpenCode 使用其支持的 OSC 99 集成。
- 通知正文使用 Agent 最新可见回答或 Terminal 提供的消息，不再展示笼统的完成文案。点击通知会回到精确 Agent，并关闭冲突的 Overlay。
- 通知权限是显式的 Agent 设置。多个后台 Tab 会协调发送，同一个完成 Turn 只产生一次通知。

## Chat、Plan、History 与导航

- ACP 浮动 Plan 只属于 Live Turn：仅当最新 Turn 仍在运行且 Plan 未完成时显示；Prompt 完成、失败、取消、进程丢失或后续 Prompt 开始时都会清理陈旧 Plan。
- History 展示完整 Resume ID，标记已经在主页面存在的精确 Session，并在恢复后打开对应 Agent，而不是继续停留在 History；焦点位于 History 搜索框时，Escape 会返回工作区。
- ACP Composer 菜单支持 Escape 关闭并恢复输入焦点；展开的 Usage 面板也遵循同一键盘约定，可用 Escape 收起。
- 新建 Codex Chat Agent 会在首个 Turn 仍运行时就使用首条任务生成标题，不再一直显示通用的 `Codex` 并等到任务完成。
- 空 Workspace 的无效启动保持立即可编辑；Project 分页按钮上的方向键不再误切换当前 Agent。Agent 与 Session 的分页控件会向辅助技术暴露不同名称和隐藏数量。
- 关闭 Settings 或 Extension 详情后，键盘焦点会回到打开它的控件。
- Project 选项菜单打开期间暂停 Project 与 Agent 的 Hover Detail。鼠标打开菜单时不再预选第一项，键盘仍可从第一项开始导航。
- 鼠标经过 Git Branch Row 时不再同时高亮父 Project 标题；Agent Provider 图标也调整为更轻、与文字基线更协调的尺寸。
- Provider 专属控件由实际协商能力决定，不会仅凭 Provider 名称展示不受支持的 Session Mode 或操作。

## Code 与 CRT 交互

- 触摸屏 Viewport 上的 Agent Row 不再启用 HTML Drag-and-Drop，点击 Agent 可以稳定完成选择并关闭移动端侧栏。
- 隐藏 Main Agent 仍在启动时新建 Agent，会保持聚焦用户请求的 Agent，不再误打开 Main Agent Terminal。
- CRT 不再把 Main Agent 引导弹窗重新覆盖到已经存活的 Agent 上，包括权威状态晚于初始空状态到达的情况。
- 打开 Agent Home 配置时会保留真实 Provider Home 身份，并直接在编辑器中打开文件，不再借用无关 Project 身份重建路径。
- File Tree 的定位与焦点恢复可以容忍延迟布局和虚拟化；内联重命名会在 Tree Renderer 更新后重新取得焦点，避免点击被粘性目录或 Editor Layer 拦截。
- File Editor Tab 会预留实测的 Action Bar 宽度，窄布局下 Tab 内容不再被操作按钮覆盖。

## Codex Terminal

- 模型控件以后端 Provider Adapter 精确声明的 Terminal Profile 能力为准，不再因为 Codex 重绘 Composer 时 Terminal Screen Observation 短暂退化为通用 Process 而消失。
- 真实 Codex 发布门禁会先等待目标模型操作可用，再发送键盘选择，避免尚在收敛的 Profile 更新静默丢弃验证操作。

## Browser、Terminal 与休息体验

- Browser Viewer 的输入队列和 JPEG Frame Backlog 有明确上限，快速指针、Viewport 与 Stream 活动不会无限积累陈旧工作。
- Terminal Path 处理会考虑互相重叠的候选路径、排除显式 HTTP(S) URL 的 Workspace Path 解析，并依次尝试可用目标，全部失败后再恢复 Terminal 焦点。
- Chromium 与 iPhone WebKit 的发布浏览器检查采用确定性验证，覆盖 Terminal Output、触摸导航、文件操作、Plugins、CRT 引导与 Farming Pet 黑洞生命周期。
- Farming Pet 黑洞休息场景拥有更连续的吸引、引力透镜、吸积盘、辐射和蒸发过程；最后一分钟的归位更顺滑，并增加生产形态的流畅度保护测试。
- 黑洞生命周期浏览器门禁在 Renderer 已产生有界 E2E Timing 状态后，不再请求冗余的软件 WebGL Frame，避免较慢的 CI Runner 超时，同时保留完整的生命周期断言。

## 工程可靠性

- ACP Chat 可以在 Adapter 异常退出后重新连接，无需放弃当前 Provider Session。恢复过程会合并并发请求，保留原 Runtime 作用域和 Transcript Revision，绝不重放断连时执行中的 Prompt，并允许在 Replacement 就绪后重试已经明确失败的 Composer 请求。
- 开发构建会原子替换锁定版本的 Codex ACP Adapter，Playwright Server 使用隔离的 Config Root，避免构建或嵌套测试关闭父 Farming 实例的存活 ACP 连接。
- ACP Client Terminal 在发布 PTY 退出前会等待一个有界的尾部数据静默窗口，因此与进程退出同时到达的最后输出仍会保留在 Chat 的有序 Tool Result 中。
- 可选的 Ghostty Debug Renderer 只使用 Farming 已审核的浏览器 Vendor 资源；正常安装、构建和 Qoder Session 不再携带或解析 `ghostty-web` 生产依赖。
- TypeScript 与 ESLint Ownership 覆盖更多 Backend、Extension Frontend、Script 与测试源码；自动测试发现检查可防止维护中的测试静默落在质量门禁之外。
- Release 与 Runtime 回归覆盖包含多配置目录隔离、Package 安装与更新恢复、通知解析和投递、响应式侧栏、陈旧 Plan 完成、Browser Rendering Backpressure、真实 Codex Runtime 切换、Terminal 输入性能和完整浏览器矩阵。

npm install --global farming-code@2.2.37 && farming daemon
