# Farming v2.2.41

[English](./v2.2.41.md)

里程碑代号：**DOC**

本次发布让同时监督大量 Agent 变得快速且可预期。后端共享 Agent 运行时并以增量方式流式同步状态，Chat 渐进渲染实时工作，并且当前后端版本不一致时，每个界面都会给出明确的升级指引。

## 运行时可扩展性

- 同一项目内的 ACP Agent 共享运行时进程和 Provider 连接，不再各自启动独立进程，大量并发 Agent 下的启动时间和内存占用显著降低。
- Turn 结果与自适应标题改为异步持久化，收尾工作不再阻塞下一条消息。
- 仓库 worktree 发现结果共享、刷新并发受限，大型 Project 保持响应。
- Slash 命令发现按 Provider 与工作区维度缓存。
- 过期的 ACP 运行时宿主会被检测并明确报告，而不是让会话静默降级。
- 共享运行时的会话摘要改为合并进既有状态而非整体替换，局部更新不会再丢掉其未携带的字段。

## 状态流式同步

- Agent 列表先以渐进快照送达，随后应用精确的增量变更，大规模清单能快速渲染并保持一致。
- 活动、会话预览和 Chat 修订更新按每个浏览器实际查看的范围投递，在不漏更新的前提下削减空闲流量。
- Project 摘要增量维护并优先送达，Farming CRT 的更新聚焦于当前查看的 Agent。

## Chat

- 转录渐进渲染；实时回答在其 Turn 运行期间保持稳定快照，Turn 结束后再发布最终文本。实时进度仍在过程区域可见，偏好减少动效的读者会立即收到每次更新。
- 回答流式输出时阅读位置保持不动，往上翻阅不会再被下一次修订打断。
- 延续会话的转录增量直接追加，不再强制整体重载，新会话的第一个 Turn 无需一次检查点往返即可呈现。
- 过程展开对每个 Turn 只保留一份开合状态，并在该 Turn 完成时自动收起。
- 恢复的会话保留原有标题，fork 来源以转录事件呈现，恢复期间的转录读取会被合并。
- 提交提示更加清晰，Agent 工作时实时进度持续流式展示；当前 Turn 结束前「审查并提交」保持不可用。

## 监督

- Agent 归档操作在各菜单间统一并使用一致的图标，需要时归档确认会等待进程退出。
- Agent 详情展示 Browser 与 Computer 资源数量，支持多浏览器活动预览，预览流仅限于最前面的卡片。
- 从 Chat 打开的 Browser 标签页会保持与显式 Resource 的绑定，不再变成已停止的重复标签；打开完整 Browser Viewer 时会显示所属 Agent 的 Resource 行。
- Agent 停止时会回收其名下的 Browser 资源及共享运行时。
- 悬浮预览在打开期间会持续更新其中的 Browser 与 Computer 数量。
- 拖动到 Project 末尾的 Agent 会留在末尾，不会再被拉回分页行内。
- 分享链接可在二维码面板中一步复制。

## 安装与更新

- Farming Server 启动前会校验自身的包镜像，缺失文件时以明确错误失败，而不是用未完整安装的运行时对外服务。
- npm 更新先在暂存目录准备启动运行时，之后才发布新的包镜像，准备失败不会留下一个无法启动的已发布版本。

## 产品文档

- Farming 现在提供正式的双语产品文档站，以当前产品截图配套任务导向的安装、功能、工作流与运维指南。
- README 将产品文档与语言切换并列为主要入口。

## 兼容性

- 浏览器协议升级到版本 8。版本不匹配时，每个界面都会给出可操作的升级提示并指明应更新哪一侧，包括已发布客户端连接更新后端的场景。
- `farming` 控制命令的帮助输出不再产生副作用。

## 升级

```bash
npm install --global farming-code@2.2.41 && farming daemon
```
