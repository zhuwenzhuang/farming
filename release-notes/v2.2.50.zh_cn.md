# Farming v2.2.50

[English](./v2.2.50.md)

里程碑代号：**CONVERGENCE**

本次发布增强了 Agent 在重启与 Runtime 切换过程中的连续性，为 Chat 与 Files 增加精确只读链接，并统一了不同主题、Provider 与 Live Resource 的工作区体验。

## 更可靠的 Agent 连续性

- 完整重启现在会按精确归属对账 Farming-owned Process，并恢复持久化的 Chat 与 Terminal Session，避免留下 Missing、Zombie 或长期 Pending 的 Agent Row。
- ACP Cold Recovery 使用有界并行准备；即使 Agent 数量较多，History 与 Session Inventory 仍能保持响应。
- Usage History 缓存重建现在会快速让出前台读取，并以有界后台批次继续执行；即使本地历史较大，Daily 与 Hourly Activity 在同步期间也可正常使用。
- Terminal 到 Chat 的替换和 ACP Host Recovery 都绑定到精确 Provider Session，防止过期异步结果覆盖当前会话。

## 保留上下文的分享与导航

- Chat Answer 与 File Viewer 现在可以复制精确只读链接，保留所选 Turn，或当前 File、View、Line 与 Column；原位置发生变化时会执行有界降级。
- 移动端 Project 与 Agent Navigation 现在是真正的 Modal，支持键盘焦点约束、Escape 关闭，并阻止误触后台操作。
- Structured Chat Transcript 引用的外部图片现在可以直接在会话中预览。

## 更统一的工作区体验

- Paper Appearance 的输入框现在通过底色与外围清晰区分；Review 也会完整跟随 Light、Dark 与 Paper 外观注册表，不再退化为固定 Light 样式。
- 深层与 Compact Files Tree 保持稳定的 Icon、Label 和 Status 列，保留真实祖先 Context，继续有界展开单子目录链，并避免直接展开时发生滚动跳动。
- Provider-native Plugin 可以正确加载生产 Raster Icon，保持 Source Navigation 原子性，并一致地向 Composer 暴露 Slash Command。
- 托管 clangd 与 JDTLS 可以从经过完整性校验的上游稳定版本更新；更新检查失败时继续使用缓存 Runtime。较慢的偶发 Hover 也不会再留下空白或 Loading Popover。

## 一致的 Provider 与 Live Resource

- Provider Capability、History Behavior、Composer Choice、Terminal Control 与 Session Identity 现在遵循同一份 Adapter-owned Definition，提升 Codex、Claude、OpenCode、Qoder 与 Qwen 之间的行为一致性。
- 新建 Chat Session 统一使用 Farming-managed ACP Runtime；已有 Legacy Session 继续保留精确的持久化 Runtime Identity 用于恢复，Native Terminal 的 Executable Selection 仍保持独立。
- Browser 与 Computer Resource 按精确 Owner Identity 对账和清理。Browser Launch 使用 Canonical Workspace；Agent 缺失或归档后不会遗留过期 Row、Profile 或 Desktop Container。
- 当中间 npm Registry 状态滞后时，更新检查会向权威 npm Registry 重试。

## 升级

```bash
npm install --global farming-code@2.2.50 && farming daemon
```
