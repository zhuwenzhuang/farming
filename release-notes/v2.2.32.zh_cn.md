# Farming v2.2.32

[English](./v2.2.32.md)

里程碑代号：**TYPESCRIPT**

这个版本完成了 Farming 的全量 TypeScript 迁移，正式支持 Qwen Code，并以这次迁移为基础，对 Agent 工作流、扩展、Browser、Computer、Chat、Terminal、Review、Files 与移动端体验做了一轮覆盖面较大的产品与可靠性收敛。

## Qwen Code 与 Agent 工作流

- **Qwen Code 现在是 Farming 正式支持的 Coding Agent。** Farming 会发现系统中的 `qwen` 可执行文件，支持它的 `QWEN_HOME`，可启动 Terminal 与 ACP Chat、注入 Farming Bootstrap、读取可恢复的 Session History、继续已有工作，并在 Chat 与 Terminal 之间切换；Qwen 在启动菜单、侧边栏、History 与 Provider Settings 中也拥有独立身份。Fork 继续由能力协商决定，只有 Live ACP Agent 协商出标准 `session/fork` 后才会出现。
- Project 菜单为受支持的 Coding Agent 新增直接启动 Chat 的快捷入口；明确要使用结构化 Chat 时，不再必须先启动 Terminal。
- 即使 Agent CLI 暂时不可用，已注册的 Agent Home 仍然可见。Home 选择、Provider 配置、危险权限跳过 Flag、Runtime Dependency、History 与启动身份都会保持绑定到用户选择的精确 Home。
- 实验性的 JSON Chat 与 Codex App Server 路径已经移除。新建和恢复的结构化 Chat 统一使用受支持的 ACP 路径；Terminal 继续使用直接 PTY 路径。

## 扩展、Browser 与 Computer

- **插件 → 扩展**现在是按 Agent Home 与扩展类型分组的只读目录。它支持 Agent Plugins v1，以及 Codex、Claude、Qoder 原生格式和 Skill、MCP、Hook、Plugin、Command 布局；展示 Provider 自己维护的已配置、已启用或已停用状态，并可打开精确来源文件，不会再维护一套 Farming 私有 Enablement。
- Browser Resource 现在由 Agent 所有。同一 Agent 下的多个命名 Browser Tab 共享一个 Browser Session，并可通过 UI、ACP Capability Projection 与按需的 `farming browser` Bridge 使用。
- Computer Use 是独立的 Agent 能力，拥有一台可见、由 Agent 所有且可由人观察的 Computer。它不再隐藏在 Browser 自动化内部，因此桌面生命周期与 Browser Tab 生命周期可以分别理解和控制。
- **Isolated Browser**把同一套锁定版本的 `agent-browser` Runtime 与 Agent 可见的 Computer Container 组合起来。它需要显式准备，在容器内使用经过校验的 Managed Chromium，并让 Browser 自动化和可观察桌面绑定到同一个精确 Runtime Identity。
- Browser 与 Computer 的轻量 Resource Metadata 统一通过每个页面唯一的版本化控制 WebSocket 传输，并在重连时发送权威快照、之后发送带 Revision 的更新。JPEG 与 noVNC Stream 仍然独立且按需连接；不会新增 Browser 或 Computer 专用 EventSource。
- 扩展与 Capability 页面在打开时会重新取得权威结果，不再把上次访问留下的快照当成当前答案。

## Chat 与协作

- ACP 工作进行期间，已接受的 Steer 与排队 Follow-up 会保留在同一条有序 Transcript 中。排队消息在投递前可以编辑、立即发送或丢弃。
- Settings 现在可以选择工作进行时发送的新消息默认采用 **Queue** 还是 **Steer**；Command/Ctrl+Enter 会临时采用相反行为。不能安全地在 Turn 中途应用的 Session Setting 会等 Agent Idle 后再生效，而较新的选择会覆盖较旧的待应用设置。
- 收起的过程区只显示当前正在运行的一条命令。完成后的中间过程不再留下层叠残影；Tool Evidence、Permission、Form、Plan、协作活动、文件变更与 Terminal 细节仍然可以按需展开。
- ACP History Replay 会保留图片与其他 Media，Transcript 中的图片也可以打开查看大图。
- Composer Draft 与附件在导航和 Runtime Replacement 期间更可靠地保留，包括排队 Follow-up 编辑与后台 Chat 连续性场景。

## Review、Files 与 Terminal

- Chat 文件变更卡片继续提供精确的 ACP Change Review。Git 比较在工作区存在修改时打开 Working Copy Diff；工作区干净时则自动变为 **Git Diff · Last Commit**。
- 当 Chat 或其他 Surface 打开文件时，Project Files 只保留一个显式 Reveal Owner，避免目录树与 Project List 争抢焦点或滚动位置。深层目录在展开、滚动、折叠、刷新与重载后保持稳定。
- Terminal 重新挂载时会隐藏停放 xterm 的旧 Buffer，直到当前权威 Checkpoint 提交。快速恢复不再闪出短暂 Loading；恢复较慢时仍会展示有界进度与重试状态。
- 打开前台 Terminal 时会优先中止低优先级 Usage 与 Session Prefetch；Browser/Computer Resource 状态也不再通过额外长期控制连接与 Terminal 争抢请求资源。

## TypeScript 里程碑与发布可靠性

- Farming 维护的 Backend Runtime、共享 Browser Protocol、Classic Browser、Frontend Bridge、Script、Usage Scanner 与测试源码现在统一通过仓库级 TypeScript 门禁。发行包仍然只携带生成或 Bundle 后的 JavaScript，不要求用户运行 TypeScript。
- Runtime Binding、Provider Capability、Lifecycle Journal、Workspace Root、ACP Checkpoint、Terminal State、Update Management、Resource Inventory 与 Release Tooling 都拥有显式类型边界，不再依赖松散共享的 Runtime Shape。
- Backend 测试成为正式的 TypeScript 检查面。Production-shaped 的桌面 Chromium 与 iPhone WebKit 覆盖长 Chat、Terminal、Files、Permission、Authentication、Fork、后台连续性、Runtime Switch、Browser 与 Computer 流程。
- App Bundle 与单文件 CLI 会在 tracked source archive 创建后显式携带生成的 Backend、Browser、Computer 与 ACP Runtime Module，确保干净 Release Runner 发布的是 Packaging 与 Dogfood 部署实际验证过的同一份生成代码。

## 产品打磨

- Project 与 Agent Row、Hover Preview、Menu、Settings、状态展示、文件 Diff、内容字号、Dark Mode、窄屏布局与移动端控件完成一轮协同的交互和视觉打磨。
- Farming Pet 休息提醒改为显式的延迟交互模型，并补充回归覆盖。

npm install --global farming-code@2.2.32 && farming daemon
