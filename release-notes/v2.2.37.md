# Farming v2.2.37

[简体中文](./v2.2.37.zh_cn.md)

Milestone codename: **BEACON**

This is the canonical gated release for the v2.2.35–v2.2.37 development line and the first release in that line published only after the exact candidate revision passed the complete CI gate. It consolidates the change information from the retired v2.2.35 and v2.2.36 GitHub Release entries; their Git tags and npm records remain historical provenance identifiers.

## Installation, update, and instance isolation

- Each Farming Server owns one canonical configuration directory and rejects conflicting ownership, allowing separate installations to isolate authentication, sessions, runtime state, and update metadata while still using shared external workspaces and Provider Homes.
- npm installations update through an isolated package-version lifecycle. Candidate packages are staged and verified before activation, exact process identity and port release are proven before mutation, and stale updater metadata is reconciled without treating source or standalone installations as npm-managed deployments.
- The npm package carries its reviewed production dependency set, so fresh installations and updates use the exact packaged dependency graph instead of unrelated global state.

## Agent completion notifications

- Farming can notify the user when an Agent finishes while the page is hidden. ACP Chat follows the authoritative Prompt `stopReason`; Terminal sessions consume standard BEL and OSC notification protocols, with OpenCode using its supported OSC 99 integration.
- Notifications use the Agent's latest visible answer or terminal-provided message instead of generic completion copy. Clicking a notification returns to the exact Agent and closes competing overlays.
- Notification permission is an explicit Agent setting. Background tabs coordinate delivery so one completed Turn produces one notification instead of duplicates.

## Chat, Plan, History, and navigation

- The floating ACP Plan is a live-Turn surface. It appears only while the latest Turn is running and the Plan is incomplete; Prompt completion, failure, cancellation, process loss, and the start of a later Prompt clear stale Plan state.
- History shows complete Resume IDs, marks exact sessions already represented on the main page, and opens the matching Agent instead of leaving History visible. Escape from the History search field returns to the workspace.
- ACP Composer menus close with Escape and restore input focus. The expanded Usage panel follows the same keyboard convention and collapses with Escape.
- New Codex Chat Agents receive a first-task title while their initial Turn is still running instead of remaining generically labeled `Codex` until completion.
- Invalid empty-workspace starts remain immediately editable, and Project pagination buttons no longer let Arrow keys switch the active Agent. Agent and session pagination controls expose distinct names and hidden counts to assistive technology.
- Closing Settings or an Extension detail returns keyboard focus to the control that opened it.
- Project and Agent hover details pause while the Project options menu is open. Pointer-opened Project menus do not preselect the first action, while keyboard navigation remains available from the first item.
- Git branch rows no longer highlight the parent Project title on hover, and Agent provider icons use a lighter size aligned to the label baseline.
- Provider-specific controls remain capability-driven, preventing unsupported session modes or actions from appearing merely because of the Provider name.

## Code and CRT interactions

- Agent rows no longer enable HTML drag-and-drop on touch viewports, so tapping an Agent reliably selects it and closes the mobile sidebar.
- Starting a new Agent while the hidden Main Agent is still launching keeps focus on the user-requested Agent instead of opening the Main Agent terminal.
- CRT no longer reopens Main Agent onboarding over an existing live Agent, including when authoritative state arrives after the initial empty render.
- Opening an Agent Home configuration preserves its actual Provider Home identity and opens the file directly in the editor instead of reconstructing it through an unrelated Project identity.
- File-tree reveal and focus recovery tolerate delayed layout and virtualization. Inline rename reclaims focus after the tree renderer updates, avoiding clicks intercepted by sticky directory or editor layers.
- File editor tabs reserve the measured width of their action bar, preventing narrow layouts from placing tab content underneath controls.

## Codex Terminal

- Model controls follow the backend provider adapter's exact Terminal-profile capability instead of disappearing when a transient terminal-screen observation falls back to a generic process while Codex redraws its composer.

## Browser, terminal, and rest experience

- Browser Viewer input and JPEG frame backlogs are bounded so rapid pointer, viewport, and stream activity cannot accumulate unbounded stale work.
- Terminal path handling considers overlapping path candidates, excludes explicit HTTP(S) URLs from workspace-path resolution, and falls back through viable targets before restoring terminal focus.
- Farming Pet's black-hole rest scene has a more continuous attraction, lensing, disk, radiation, and evaporation sequence, with smoother final-minute convergence.

## Upgrade

```bash
npm install --global farming-code@2.2.37 && farming daemon
```
