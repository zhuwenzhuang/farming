# Farming v2.2.24

[简体中文](./v2.2.24.zh_cn.md)

This patch completes native Terminal recovery across overlapping Farming server generations and makes readable absolute file paths in Terminal output directly openable in Project Files.

## Fixed

- Keeps each native PTY host reachable through a private listener even if an older Farming generation removes the public config-bound socket link. A restarting server restores that link only when exactly one matching private host is live; multiple matches fail visibly instead of selecting a runtime arbitrarily.
- During controlled runtime rotation, resolves a `v2.2.23` host's private listener by matching the public and private socket inode when the legacy `ping` response omits that path, then waits for that exact listener to exit. Removing the public link cannot be mistaken for proof that the old host stopped.
- Keeps the `v2.2.23` socket-ownership guarantee: an obsolete fixed host cannot delete a replacement host's public link when it shuts down.

## Changed

- Readable absolute file paths rendered by a Terminal can open directly in the read-only Project Files surface, including line and column targets. The backend accepts only the exact readable file; directories, missing files, and unreadable paths remain rejected, while all write operations stay workspace-scoped.

## Verification

- Native private-socket discovery, ambiguous-host rejection, replacement ownership, restart recovery, controller fencing, and transactional rotation tests
- Project Files terminal-link and exact external-file router tests
- TypeScript typecheck, ESLint, backend checks, packaged CLI smoke, and Linux/macOS release artifact smoke

npm install --global farming-code@2.2.24 && farming daemon
