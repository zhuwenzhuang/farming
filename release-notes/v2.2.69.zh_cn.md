# Farming v2.2.69

[English](./v2.2.69.md)

里程碑代号：**TETHER**

TETHER（系缆）让每个被监督的对象都拴在自己的归属上：复制的分享变成短而持久的
链接，活跃的 Codex 会话通过它自己的运行时归档，已被接受的 ACP 回调始终绑定在
接受它的那条连接上。

## 分享

- 复制的只读链接变成短链接，不再是超长的签名查询 URL。链接只包含一个不透明
  code；打开时后端把已存储的只读能力写入 HTTP-only cookie，并跳转到精确的上下
  文位置。
- 保留被分享能力原有的过期时间、目标与只读模式。打开、预览或再次分享都不会消耗
  或延长链接；被委托的链接不会超过父凭证的有效期；服务端重启会重新加载已持久化
  的链接，但不会为其续期。
- 未知、已过期或已失效的链接返回明确的 `410`；`HEAD` 不产生副作用；分享响应使用
  no-store 与 no-referrer。
- 继续支持旧的只读查询 URL，并在应用加载前从可见地址栏移除其凭证。
- Chat 回答操作与 File Viewer 复制同一个短链接，并仍会撤销自己不展示的 QR
  ticket。

## Chat 与 ACP 可靠性

- Host 到 Controller 的回调在传输层接受后保持 pending，即使 socket 报告背压。
  只有匹配的 Controller 结果才能完成回调；断连或有限的回调超时会以明确的“不确定
  结果”结束，而不是静默丢弃或重放。
- 为 Controller 结果与被替换的传输加栅栏：Controller 身份或代次变化会使其此前的
  回调与 fork 预留失效；连接替换会拒绝旧连接的待处理请求并重置分帧；已脱离的
  socket 的数据或终止事件无法影响其替代连接。
- 序列化失败不会留下待处理请求或截止时间，也不会使本来健康的连接失效。

## 历史归档

- 活跃的 Codex ACP 会话先通过官方 app-server 操作归档，再释放其 writer。首次提交
  prompt 即让会话可归档；从未提交过的空会话不需要改动 History；归档失败或超时保持
  阻塞，不会换一个进程重放。
- 显式重试与重启恢复先读 Provider History，避免重复已提交的归档；共享运行时中无关
  的会话保持存活。
- 归档与关闭后的选择留在自己的 Project 内：移除当前选中的 Agent 时，按该 Project
  侧栏顺序选择下一个可打开的 Agent，其次是最接近的前一个；不会启动或恢复任何运行
  时；没有后继时保留该 Project 工作区并交回焦点。
- 工作区加载后才出现的 Agent（包括程序化创建）会被正常选中；显式的空选择仍然在刷新
  后保持。
- macOS 硬停止时协调已经退出的进程组。

## 运行时

- 正确识别使用自定义或带命名空间模型名的 Codex Terminal 空闲状态，避免已就绪的
  会话仍停留在等待启动状态。
- 托管 Codex 更新至 0.155.0，Claude ACP 更新至 0.79.0（Claude Agent SDK 0.3.274）；
  Codex ACP 保持 1.12.0，并刷新 vendor 补丁以暴露会话归档操作。

## 升级

```bash
npm install -g farming-code@2.2.69
```
