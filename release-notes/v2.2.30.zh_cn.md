# Farming v2.2.30

[English](./v2.2.30.md)

这是一个以安装体验和日常可靠性修复为主的维护版本。

## 浏览器安装

- 当机器上没有合适的本地浏览器时，可以在**插件 → 浏览器**中显式安装与当前版本匹配的受管 Chromium。Chromium 仍是按需能力，Farming 的正常安装、更新和启动都不会自动下载它。
- 受管 Chromium 安装使用隔离暂存、跨进程协调、可执行文件校验和原子激活。失败或中断的安装不会成为可选 Browser 来源；存在旧版有效安装时，界面会明确提示可更新，而不是静默复用。

## History 与协作 Agent

- History 现在以各 Provider 的根 Session Identity 为准。子 Agent Transcript 会保留在所属根 Session 下，不再作为重复的顶层 History Row；界面也会区分当前已加载数量与 Provider 实际 Session 总数。
- Provider History Search 可以查到尚未加载的旧 Session，无需先读取完整归档。Resume ID 保持可见且可搜索，Row 操作会恢复精确 Session，空 Workspace 也会明确引导用户从 History 继续。
- ACP History 会保留支持的图片和其他 Media。Codex 协作事件保持审核过的层级与状态，归属于创建它的具体对话轮次，打开后聚焦匹配的 Process 证据，不会把子 Agent 活动展示成独立可写 Agent。收起的子 Agent 现在使用紧凑的行内按钮，仅在选中后原位展开。
- History Row 恢复使用各 Agent 对应的主题图标资源。

## 可靠性修复

- 深层 Project Files 目录在滚动时会保持真实层级。顶部粘性目录栈现在会计算自身高度、限制最大层数并保留正常文件行，不再遮住中间目录导致文件看似挂错层级。
- Dark Mode 会在应用 Bundle 启动前应用，避免页面重载时短暂出现浅色首帧，并恢复侧边栏与主工作区之间清晰的层次区分。项目列表滚动条在静止时保持隐藏，鼠标移入列表后自动显示。
- HTTP 与 HTTPS 链接现在会在普通点击时使用外部浏览器打开。只有 Browser 能力可用时，右键菜单才显示**在 Farming 浏览器中打开**；不可用时不显示这一行。
- 应用内自更新现在仅支持 npm 安装。源码、Standalone 和 App Bundle 继续使用各自显式的手动部署方式，不再把 GitHub Releases 当作应用内更新源。
- 已移除过时的 History Fallback Reader 和旧版 `farming memory report` 命令；受支持的 History 与恢复路径统一使用权威 Provider Adapter。
- 公共文档入口调整为更短的任务导向路径，并提供独立文档中心和更精简的产品 Landing Page。

## 升级

```bash
npm install --global farming-code@2.2.30 && farming daemon
```
