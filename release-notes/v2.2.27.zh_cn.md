# Farming v2.2.27

[English](./v2.2.27.md)

本版本汇总 `v2.2.21` 之后所有已交付的产品变更，收口 Agent、ACP、Terminal、Project Files、设置与更新流程中剩余的竞态窗口，同时保证旧 ACP 与 Terminal Session 在重启和升级后自动恢复。

## 修复

- 按 Agent 串行 ACP Prompt、Steer、Cancel 与排队消息准入。不明确的失败绝不重放，明确的 Turn 结束类失败会保留消息顺序；Cancel 期间提交的消息只会在旧 Turn 到达终态后启动一次。
- 为每个已观察到的 ACP 子 Session 建立独立 Control Owner。重复停止合并为一个 Provider 请求；父级 Cancel 包含仍能证明活跃的子 Session；旧 Binding 不能修改 Replacement，迟到更新也不能重新打开已完成的子 Session。
- 自动恢复尚未持久化 Process Group Identity 的旧 ACP Chat。升级时直接 Resume 精确的已保存 Provider Session，不要求用户逐个确认；新启动的 ACP 进程会立即持久化后续清理使用的精确身份。
- Agent Create、Update、Delete 与 Archive 在外部副作用前写入 Lifecycle Journal，并在重启后恢复未完成操作而不重复启动 Runtime。高频 ACP 与 Attention 状态和生命周期、进程所有权元数据分开存储。
- Codex 与进程内持有 Fork 的 Claude 均保留精确 ACP Fork 状态和 Provider Identity，包括有界子 Session Transcript、Patch Decision、启动回滚与清理失败报告。
- 在浏览器和后端 Owner 上 Fence Project Files 的保存、创建、重命名、移动与删除。迟到响应不能夺取新 UI 状态；结果不确定的 Mutation 只通过权威文件系统读取收敛且不自动重放；较新的草稿不会被较早完成的保存清除。
- 收口 Farming Code、CRT、Agent Home 设置、首页 Session Membership 与 Daemon Control 中剩余的 Request Ownership 竞态。Packaged Daemon 直接运行在记录的 Server PID 下，使 Stop 与 Release Smoke 校验真正的监听进程，而不是 Shell Wrapper。
- Farming Server Generation 重叠时仍保持 Live Native Terminal Session 可访问。每个 Native PTY Host 持有 Private Listener，并把 Config 绑定的稳定 Socket 发布为 Hard Link；过时 Host 退出时不能删除 Replacement Host 的链接。
- 公开 Native Host 链接丢失时，只有在恰好找到一个匹配的 Live Private Listener 时才恢复；多个匹配项会显式失败。Controlled Rotation 会等待精确 Private Listener 退出后再启动 Replacement。
- 从旧版 `ping` 未返回 Private Path 的 `v2.2.23` Host 升级时，通过公开与私有 Socket 的共享 Inode 自动识别 Listener；公开链接消失绝不会被当作旧 Host 已停止的证明。

## 调整

- npm 与 Bundle 更新会先在当前服务继续可用时准备到 Staging。应用已准备版本是独立的 Restart 操作；npm Package 目录切换失败时，会在重启前恢复旧包。
- Codex 协作活动在 Chat 中显示为紧凑的具名 `updated` / `finished` 时间线。选择事件会展开并聚焦对应的精确 Process 证据，但不会把内部协作事件暴露成可写 Agent。
- Terminal 渲染出的可读绝对文件路径可以直接在只读 Project Files 中打开，并支持行列定位。后端只接受该精确可读文件；目录、缺失文件与不可读路径仍会拒绝，写操作继续限制在 Workspace 范围内。
