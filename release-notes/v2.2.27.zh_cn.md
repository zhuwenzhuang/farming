# Farming v2.2.27

[English](https://github.com/zhuwenzhuang/farming/blob/main/release-notes/v2.2.27.md)

里程碑代号：**ACID**

本版本最重要的变化是系统性加强事务一致性，集中收口 Agent 生命周期、ACP Chat、Project Files、Settings、更新流程和 Terminal Runtime 中的并发与恢复竞态。

Farming 在每个权威 Owner 内采用了 ACID 式规则：先持久化 Intent 再执行外部副作用，串行冲突操作，用 Generation Fence 拒绝过期结果，通过原子替换提交文件，不重放结果不明确的网络请求，并在进程重启后恢复被中断的状态转换。

## 核心改进

- Agent Create、Update、Delete 与 Archive 使用 Lifecycle Journal 作为 Write-ahead Metadata History。冲突操作会串行或合并，已完成请求按 Operation Identity 去重，外部 Mutation 必须等待启动恢复完成；重启后消费未完成 Intent，不会重复启动 Runtime。
- ACP Prompt、Steer、Cancel、排队 Follow-up、配置修改和子 Session 控制都有明确的 Agent、Binding、Turn 与 Operation Owner。按 Agent 准入保证消息顺序；重复 Cancel 合并为一个请求；旧 Binding 和迟到更新不能修改 Replacement；结果不明确的失败不会自动重放。
- ACP Fork 保留精确 Source Revision、子 Transcript、Patch Decision、Provider Identity 与清理责任。进程丢失或无法证明清理完成时会显式失败，不会静默创建第二个 Child，也不会丢失仍需清理的精确身份。
- 浏览器命令在第一个异步边界前捕获 Request Ownership。迟到响应不能清除较新的 Loading、抢走焦点、覆盖 Replacement Agent 或文件，也不能重复提交 Create、Rename、Delete、Settings 或首页 Membership 操作。请求超时或断网后从权威状态对账，不猜测写入是否已经提交。
- Project Files Mutation 按 Canonical Workspace 串行，在队列内部重新检查内容或目录 Version，使用唯一临时文件写入，支持时在关闭前 Flush，再通过原子 Rename 提交。浏览器 Working Copy 使用 Revision 保留较新的草稿；结果不确定的 Mutation 只做有界权威重读，绝不自动重放。
- Agent 持久化结构把低频生命周期与进程所有权元数据放在 `agent_*.json`，把高频 ACP、Attention 与 Read State 放在 `agent_*.state.json`。每个记录文件都通过临时文件原子替换；旧记录在第一次修改时迁移到稳定 `agent_*` Identity；高频状态写入不会覆盖安全关键的 Process Identity 或 Lifecycle History。
- 重启和升级恢复使用精确 Runtime Ownership。默认配置会恢复旧 ACP 记录保存的准确 Provider Session；新接管进程保留清理身份；Packaged Daemon 记录真正监听的 Server PID；Native PTY Host 使用 Private Listener 与 Inode Ownership 的公开 Hard Link，重叠 Server Generation 不会让 Live Terminal Runtime 失联或被旧 Host 删除。
- npm 与 Bundle 更新先在当前 Server 继续可用时准备到 Staging。应用准备好的版本是独立 Restart Transition；npm 目录切换失败时，会在重启前恢复旧 Package。

## 调整

- Codex 协作活动在 Chat 中显示为紧凑的具名 `updated` / `finished` 时间线，并链接到准确的 Process 证据。
- 点击 Terminal 输出中的可读绝对文件路径时，可以在只读 Project Files 中打开，并支持行列定位。请求只授权读取该精确文件，不授权浏览父目录；写操作仍限制在 Workspace 内。

## 一致性边界

这些是 Farming 声明的 Owner 范围内的 ACID 式保证：单个 Server Process、它持久化的 Agent Records，以及按资源串行的操作。Farming 不宣称与另一台 Farming Server、任意外部文件写入者或远程 Provider 之间存在分布式事务。外部结果无法证明时，操作会显式停止，并通过权威重读收敛，而不是进行不安全重放。

## 已知限制

- 较早的 Codex Session 如果来自其他 Codex 界面，Provider History 可能缺少协作关系、Agent 名称与状态或 Fork 来源。Farming 会恢复实际收到的对话和 Process 证据，但不会根据普通 Tool 调用猜测缺失的协作元数据。
