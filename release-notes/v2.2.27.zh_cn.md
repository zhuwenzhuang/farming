# Farming v2.2.27

[English](./v2.2.27.md)

本说明把 `v2.2.21` 之后实际交付的产品变化汇总到最后一个有效版本中。

## 修复

- 默认配置下自动恢复尚未记录 Process Group Identity 的旧 ACP Chat。升级后通过正常 ACP Load 路径恢复精确保存的 Provider Session，不再要求用户逐个确认；严格清理诊断仍可显式关闭该兼容行为。
- 首页 Session Membership 与 Agent Home 设置请求增加 15 秒上限。首页 Mutation 结果不确定时从权威 Settings 对账；Agent Home 保存结果不确定时重新加载权威值，不猜测写入是否已经提交。
- CRT Settings 写入改为串行，并使用相同的 15 秒请求上限。保存失败或超时后重新加载权威 Settings，避免迟到响应静默覆盖较新的 UI 状态。
- Daemon Process Identity 改为从 Locale 无关的 UTC `ps` 输出记录，避免环境差异造成误判。Packaged Daemon 直接通过 `/usr/bin/env` 启动，因此持久化 PID 属于真正监听的 Server，而不是 Shell Wrapper。
- Farming Server Generation 重叠时仍保持 Live Native Terminal Session 可访问。每个 Native PTY Host 监听 Private Socket，再把 Config 绑定的稳定 Socket 发布为 Hard Link；退出时只有在公开链接的 Inode 仍属于自己时才删除。
- 公开 Native Host 链接丢失时，仅在恰好存在一个匹配的 Live Private Listener 时恢复；多个候选会显式失败。Runtime Rotation 会等待精确 Private Listener 消失，不再把公开链接删除误当成旧 Host 已停止。
- 从 `ping` 尚未返回 Private Socket Path 的 `v2.2.23` Host 升级时，通过公开与私有 Socket 的 `dev + ino` 身份匹配出精确 Listener，再执行 Rotation。

## 调整

- 点击 Terminal 输出中的可读绝对文件路径时，可以在只读 Project Files 中打开，并支持行列定位。请求只授权读取该精确文件，不授权浏览父目录；所有写操作仍限制在 Workspace 内。

## 已知限制

- 较早的 Codex Session 如果来自其他 Codex 界面，Provider History 可能缺少协作关系、Agent 名称与状态或 Fork 来源。Farming 会恢复实际收到的对话和 Process 证据，但不会根据普通 Tool 调用猜测缺失的协作元数据。

## 验证

- 默认配置的旧 ACP 恢复测试，以及显式严格诊断路径覆盖
- 首页 Session、Agent Home、CRT Settings、Daemon Identity 与 Packaged Server PID Ownership 测试
- Native Private Socket 发现、Ambiguous Host 拒绝、Replacement Ownership、旧 Host Rotation、Controller Fencing 与同 Home Codex 并发恢复测试
- Project Files Terminal Link、精确 External File Router、状态模型与浏览器回归覆盖
- Packed npm 临时安装、Codex ACP 握手、Server/Native Host/Main Shell 精确清理，以及 Standalone CLI 与 Linux/macOS Artifact Smoke

## 升级

```bash
npm install --global farming-code@2.2.27 && farming daemon
```
