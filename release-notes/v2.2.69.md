# Farming v2.2.69

[简体中文](./v2.2.69.zh_cn.md)

Milestone codename: **TETHER**

Tether keeps each supervised thing attached to its owner: a copied share becomes
a short persistent link, an active Codex session archives through its own
runtime, and an accepted ACP callback stays bound to the connection that
accepted it.

## Side Chat and related sessions

- Open one reusable Side Chat beside its parent with independent drafts,
  attachments, permissions, and turn controls. Resize the two panes on wide
  screens or switch between them on compact screens.
- Keep Side Chat and provider-native subagents beneath their parent in the
  sidebar; open native child transcripts in the same right-hand pane.
- Retain Side Chat history while releasing idle or unsupervised runtimes, and
  resume the exact session only for an explicit new message. Parent cleanup
  releases owned child resources and rejects further orphan messages.

## Sharing

- Copy a short persistent read-only link instead of a long signed query URL. The
  copied link carries only an opaque code; opening it resolves the stored
  read-only capability into an HTTP-only cookie and redirects to the exact
  contextual location.
- Preserve the shared capability's original expiry, target and read-only mode.
  Opening, previewing or re-sharing never consumes or extends a link, a delegated
  link never outlives its parent credential, and a server restart reloads
  persisted links without renewing them.
- Answer unknown, expired and invalidated links with an explicit `410`, keep
  `HEAD` free of side effects, and serve share responses with no-store and
  no-referrer.
- Keep supporting legacy read-only query URLs, removing their credential from the
  visible address bar before the application loads.
- Chat answer actions and the File Viewer copy the same short link and still
  revoke the QR ticket they do not display.

## Chat and ACP reliability

- Keep host-to-controller callbacks pending after the transport accepts them,
  including while the socket reports backpressure. Only the matching controller
  result completes a callback; disconnect or the bounded callback timeout ends it
  as an explicit uncertain outcome instead of a silent drop or replay.
- Fence controller outcomes and replaced transports. A controller identity or
  generation change invalidates its previous callbacks and fork reservations,
  connection replacement rejects the old connection's pending requests and resets
  framing, and data or terminal events from a detached socket cannot affect its
  replacement.
- Report a serialization failure without leaving a pending request or deadline
  and without invalidating an otherwise healthy connection.

## History archive

- Archive an active Codex ACP session through the official app-server operation
  before detaching its writer. The first submitted prompt makes a session
  archivable, an empty never-submitted session needs no History mutation, and a
  failed or timed-out archive stays blocked instead of being replayed through
  another process.
- Read Provider History first on explicit retry and restart recovery so an
  already committed archive is not repeated, and keep unrelated sessions in a
  shared runtime live.
- Keep archive and close selection inside its own Project. Removing the selected
  Agent chooses the next openable Agent in that Project's sidebar order and then
  the nearest previous one, never starts or resumes a runtime, and leaves the
  Project workspace with focus when no successor exists.
- Select an Agent that appears after the workspace loads, including programmatic
  creation, while an explicit empty selection still survives reload.
- Reconcile already-exited process groups during a macOS hard stop.

## Runtime

- Recognize idle Codex Terminals using custom and namespaced model names, so a
  ready session does not remain stuck waiting for startup.
- Update managed Codex to 0.155.1 and Claude ACP to 0.79.0 with Claude Agent SDK
  0.3.274. Codex ACP stays at 1.12.0 with a refreshed vendor patch that exposes
  the session archive operation.

## Upgrade

```bash
npm install -g farming-code@2.2.69
```
