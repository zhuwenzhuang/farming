# Farming v2.2.60

[English](./v2.2.60.md)

本次发布让长时间运行的 Chat 会话和移动端监督达到稳定可用，并进一步收紧只读分享的权限边界。

## 可靠的 Chat 历史

- 大型 ACP Transcript 会先在 Host 边界内投影和分页，再通过有大小上限的 IPC 通道；因此原始 Provider 历史超过传输限制时，不再导致整个会话历史加载失败。
- Transcript 分页、工具审查详情、媒体、缓存检查点、重连以及 Server 或 Host 被强制终止后的恢复，都保持同一个权威会话且不会重放 Prompt。
- Farming CRT 改为读取轻量 Session Metadata，不再请求无界的原始 Transcript。

## 生产可用的移动端监督

- Chat 编辑、发送、取消、模型选择、权限操作、图片预览与长 Transcript 导航，在 iPhone 和 Android 尺寸下均保持可用。
- Project Files 使用适合触控的行高和响应式双行编辑操作；大文件树、长文件名、横向滚动、预览、未保存草稿及冲突恢复在窄屏下保持有界。
- Share 控件、抽屉、菜单、Tab 与状态 Surface 在 Light、Dark、Paper 三种外观中保持稳定几何。

## 只读分享与恢复

- 只读链接对 Chat、Terminal、文件修改和 Language Server 操作 Fail Closed，同时保留有界的 Transcript、文件和 HTML Preview 读取能力。
- Preview Session 按访问权限和凭证 Scope 隔离并采用独立配额，一个 Viewer 不能驱逐或打开其他 Viewer 或 Owner 的 Preview。
- 只读 Browser 与更新检查保持纯观察：不会持久化默认 Browser、强制刷新 Registry、创建安装目录或推进恢复状态。
- Browser Capability Refresh 在并发探测中保留 Owner 较新的选择，并会重试瞬态 Source Verification 失败，不再无限缓存失败结果。

## API 兼容性

- `GET /api/agents/:id/acp-session` 现在默认只返回 Session Metadata，不包含 Transcript Entries。确实需要旧版原始 Entry 数组的客户端必须显式请求 `?includeEntries=1`；交互式客户端应使用有界 Transcript 分页。

## 升级

```bash
npm install --global farming-code@2.2.60 && farming daemon
```
