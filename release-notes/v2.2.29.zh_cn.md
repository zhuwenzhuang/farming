# Farming v2.2.29

[English](./v2.2.29.md)

里程碑代号：**BROWSER**

本版本把 Browser Resource 收敛为一项可长期维护的共享浏览器能力。Farming 现在把浏览器操作交给版本精确受管的 `agent-browser` Runtime，让人和 Agent 查看、操作同一个可见页面，同时不捆绑 Chromium，也不管理外部 Owner 的浏览器与容器。

## 核心改进

- 本地浏览器与外部 CDP 来源统一使用一套版本锁定的 `agent-browser` 实现。Farming 会在安装或更新阶段自动准备并校验 Runtime，但不携带 Chromium、Playwright、Puppeteer、WebDriver，也不保留第二套 Raw CDP 自动化路径。
- **插件 → 浏览器**成为启用能力和选择来源的唯一入口。用户可以选择发现到的 Chromium 系浏览器，或显式配置回环 CDP Endpoint；切换来源时会先验证新选择并停止 Farming 拥有的 Browser Resource，再提交设置。
- 使用本地来源时，同一 Project 的 Browser Resource 共享一个 Farming 拥有的浏览器进程、隔离 Profile、登录态和 `agent-browser` Session。使用外部 CDP 时，Project 共享的是连接到外部浏览器、Profile 与登录态的 `agent-browser` Connection。两种来源下，每个 Resource 都是 Farming 拥有的独立可见标签页，可以直接打开、切换、导航和关闭，不再出现删除独立资料目录的确认弹窗。
- 共享 Viewer 转发 Runtime 的 JPEG Stream，并把指针、键盘、滚轮、导航和 Viewport 输入映射回 Agent 使用的同一个 Session。Browser Row、Viewer Generation、Action、Tab 以及 Stop/Drain 现在都有明确生命周期 Owner 和有界失败状态。
- Agent 先通过 `farming capabilities` 发现 Browser，再使用渐进式披露的 `farming browser` 工作流。支持范围包括导航与等待、DOM 交互、检查与 JavaScript、Console/Error/Network 证据、Cookie/Storage、Frame/Dialog，以及 Project Scoped Upload/Download。Browser MCP 仍是显式选择，不会自动挂载。
- Farming 可以通过用户管理的回环 CDP Endpoint 连接 Docker 内的浏览器，但不会访问 Docker Socket、选择或拉取镜像、管理容器，也不拥有外部浏览器生命周期。

## 插件与 Agent 能力展示

- 左上角拼图按钮和欢迎页都可以进入独立的插件页面。
- Farming 内置能力排在第一组；扫描到的 Skill、插件、命令和其他扩展类型按 Agent、按类型分组，每个 Section 都可以独立收起，并保持固定卡片大小，避免大量能力破坏整体排版。
- 没有 Browser 时不显示空行；插件卡片默认保持紧凑，点开后再查看完整内容。

## Runtime 与可靠性

- Codex CLI、Claude Code CLI 和 `agent-browser` 改为启动依赖，不再作为 Package 打包依赖。安装和更新准备会在重启窗口前下载、校验、暂存并原子激活精确 Artifact；新 Server 打开端口前再次校验，健康启动后才清理不再使用的 Cache。
- 大型 ACP Transcript 使用有界、Revision Aware 的加载；协作 Agent 与 Process 证据默认收起且不挂载详情 DOM，只有打开时才加载。只读 Transcript 恢复可以有界重试传输失败，但绝不会重放 Prompt 或 Terminal Input。
- Farming Server 的重启与更新路径采用 Crash-only、Identity-fenced 语义；Browser Session、Native PTY Host、更新回滚、Terminal Attachment 和重连 UI 都补充了 Ownership 与恢复检查。

## 升级

```bash
npm install --global farming-code@2.2.29 && farming daemon
```
