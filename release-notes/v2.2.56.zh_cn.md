# Farming v2.2.56

[English](./v2.2.56.md)

里程碑代号：**BOUNDARY**

本次补丁发布明确了 Agent、Session、Browser 与 Project Files 的状态归属，并消除了文件树自反馈循环和大目录失败边界。

## 可靠的 Agent 与 Session 操作

- Agent Session 现在可以设置持久 Follow-up 标记。该标记会跨重启、归档与恢复、Runtime 切换保留，计入 Project 汇总，并且不会被 Fork 继承。
- Detached Provider Session Row 现在可原位恢复；Archive 只在 Provider Mutation 成功后移除 Row。并发 Resume 与 Archive 通过同一精确 Session Identity 串行化，不能再相互撤销结果。
- Chat Refresh 不再短暂重置 Model Picker；协议升级后，过期 Code 或 CRT Client 最多执行一次 No-cache Reload，再连接到当前 Backend 状态。

## 更快、更稳定的 Project Files

- 大型展开树现在使用有界 Virtual Row Projection 与一个原生 Project Scrollbar。Sticky Context 只从结构 Row 与 Viewport Input 推导，避免渲染 Overlay 反向写入自己的 Source State。
- Directory Structure 与 Git、Ignored Decoration 独立加载。超大 Decoration Read 同时按 Protocol Message 与 Subprocess Argument 边界分批，不会再因超过 4,096 项而失败或永久 Pending。
- Project Files Search 现在只通过 Farming 自带、版本固定的原生 ripgrep 15.2.0 执行一条有界、可取消路径；失败会明确结束，不会切换到系统或 WebAssembly Fallback。
- 不属于任何 Project 的精确只读文件会直接打开，不再展开 Files 或尝试不可能成功的 Tree Reveal；Reconnect 与普通文件定位仍保留权威目标。
- 创建 File 或 Folder 后，其 Parent 会在权威 Refresh 期间保持展开。重命名已展开的 Directory 时，其展开的后代路径会一同迁移；键盘激活文件后焦点仍留在 Tree 中，后续 Rename、Menu 与 Delete 命令可以继续使用。

## Resource Ownership 与打包

- 每个 Browser Resource 现在只归属于一个 Active Agent，并且只显示在该 Agent 的 Resource Section 中。升级迁移会先清理退役 Project-owned Browser Row 的 Runtime 与 Profile，再移除其持久化身份。
- Project Archive 会保留手动和动态 Pin 的 Session；只有显式 Project Removal 才负责清理该 Project 拥有的工作。
- Agent Row 的紧凑间距更加一致，并新增了一套与主体无关的 Editorial Systems-sketch Style Capsule，用于架构与流程插图。
- 托管 Codex ACP Adapter 从 1.6.0 更新到 1.6.2，并继续保留经过审查的 Farming Patch 与不可变 Runtime Digest。Release Preparation 与 Publication 现在复用同一组已测试的 Exact-SHA Artifact。
- Standalone Linux arm64 CLI 现在内含与架构无关的 Bundled JavaScript，并在发布前通过 arm64 模拟环境执行 Native PTY Smoke。

## 升级

```bash
npm install --global farming-code@2.2.56 && farming daemon
```
