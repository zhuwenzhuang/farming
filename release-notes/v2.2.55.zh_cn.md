# Farming v2.2.55

[English](./v2.2.55.md)

里程碑代号：**STAY**

本次补丁发布让 Agent 切换、Chat 恢复、共享链接打开与 Browser 复用过程中的当前 Workspace 保持稳定。

## Chat 与 Agent 连续性

- 用户在多个实时 Agent 间切换时，结构化 ACP Transcript 与 Session 配置现在始终归属于各自的精确 Agent，包括后台到达的渐进更新。
- 新建 Chat 在权威 Provider Session 身份产生前会保持明确的 Pending 状态；加载更早历史时也会保留读者当前阅读位置。
- 当权威 Transcript 不可用时，有界 Chat 历史恢复现在会明确结束为 Transport 或 Response 错误，并能在保留已有历史的前提下重新连接。
- Codex Session Discovery 通过有界 Cache 复用，但 Cache 不成为权威状态；过期或身份不匹配的 Session 状态会失败关闭，并从 Provider 边界重新读取。
- 选择 Agent 不再改写其活动时间；Project 顺序更新到达时，当前可见 Agent 仍保持锚定。
- 恢复后的 Codex 历史可通过同一套沙箱化 Chat Renderer 还原交互式内联可视化，同时 Host Path 仍严格限制在对应 Provider Session 的精确目录内。
- Chat/Terminal 切换在替换 Runtime Agent Identity 时会保留同一 Browser 与 Computer Resource，包括回退到原 Runtime 的场景。
- Linux Hard Stop Recovery 会把仅含 Exited 或 Zombie 成员的 Process Group 视为已结束，但只要仍有 Live Descendant 就继续阻止 Cleanup。

## 可复用的 Browser Session

- 每个 Agent 与 Project 现在都有一个可复用的 `default` Browser Session。`farming browser open` 仅在不存在时创建、在已停止时启动，否则复用同一 Resource 与 Profile。
- 需要独立 Browser 工作时可使用稳定的命名 Session；显式 Resource ID 仍保留用于兼容与管理。
- Browser Cleanup 失败时现在会进入有界、可重试的 Failed 状态，不再无限停留在 `stopping`；删除 Agent 时可精确回收孤立的 Isolated Browser Runtime，同时不会 Kill Shared Session 或借用的 Chrome Tab。
- Project 启动快捷操作保持显式语义：Provider 主 Row 始终启动 Terminal，相邻快捷按钮始终启动 Chat，不受新 Agent Runtime 默认值影响。
- 移除 Project 前现在会列出即将清理的 Agent、Session 与已打开文件，并按 Owner 顺序完成归档和关闭后再移除 Project。

## 更可预测的 Workspace 行为

- Farming Code 与 CRT 现在只使用受支持的 xterm.js WebGL Terminal 路径，移除了退役的 Ghostty Renderer 及其打包 Runtime。
- Owner App URL 会在重新加载、复制与 Installed App 交接时保留认证 Token；Chat 与 File 上下文位置只在首次页面加载时消费一次。
- 横向 Workspace 调整会在 Pointer 松开后可靠停止；Native、Monaco 与 Terminal Scrollbar 现在共享随 Appearance 变化的几何与交互颜色。
- 托管 Codex ACP Adapter 已从 1.4.0 更新至 1.6.0，同时保留 Farming 已审查的集成能力，包括 Session 级环境变量、Steering、精确删除、Fork、Subagent、历史图片、实时标题与有界 Discovery 刷新。

## 升级

```bash
npm install --global farming-code@2.2.55 && farming daemon
```
