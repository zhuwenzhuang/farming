# Farming v2.2.17

[English](https://github.com/zhuwenzhuang/farming/blob/main/release-notes/v2.2.17.md)

里程碑代号：**TOKEN USAGE**

这个版本修复 Agent 升级与重连后的恢复问题，保留最多 20 个最近使用的 Agent View，并为两套公开皮肤加入可追溯到原始会话的 Token 历史统计。

## 主要变更

- **Provider 会话身份与产品元信息分离**：Farming 使用 `fsess_*` 记录保存产品元信息，同时独立解析 Codex 和 OpenCode 的 Provider 身份。即使 Provider ID 暂时尚未生成，标题、置顶、Project 归属、运行模式和 Resume 行为也可以跨服务重启与 Archive/Restore 保留。
- **Codex 与 OpenCode 启动绑定 Provider 身份**：Codex Terminal 仍然立即可交互，只有在确认唯一 Rollout 后才把临时关联 ID 升级为正式 ID；OpenCode 则在启动前创建并绑定 Provider ID。两条路径都不依赖 `--last`，也不按时间选择“最近会话”。
- **后台返回时从 Checkpoint 恢复**：浏览器切到后台再返回时，通过 Agent 状态和 Terminal Checkpoint 恢复，不再长期停在过期的心跳警告上，也不会回放历史 Terminal 输出。
- **Code 与 CRT 的 Token 活动视图**：Usage Panel 与 CRT Billing 共享按天、按小时的 Provider Token 历史、缓存占比、活跃天数、峰值日期和准确的选中日期详情。

## Token 历史

- 用只依赖随包运行时的 Node/TypeScript Worker 替代 Python Usage Helper。Codex 累积计数器与 Fork 统计改编自 MIT 协议的 CodexBar Parser；Claude 归一化遵循 MIT 协议的 `cc-statistics` 语义，来源记录在 `THIRD_PARTY_NOTICES.md`。
- 引入不兼容但可丢弃的新 SQLite Cache 版本，旧 Usage Cache 会自动清除重建；Codex、Claude 与 OpenCode 的原始历史始终保持只读和权威。
- 使用持久化目录清单与有界 Source Audit，Warm Refresh 不再枚举或排序全部历史会话。发生变化的文件从经过校验的字节 Checkpoint 继续；Rewrite-and-grow、截断、Archive Move 以及 Codex Parent/Fork 边界都有明确恢复语义。
- OpenCode 导出达到 5,000 个 Session 上限时会明确标记为 Partial，不再把截断结果展示成完整统计。
- 增加发布产物级 Smoke，验证打包后的 Worker、SQLite Cache 与真实格式的合成 Codex Token Event。

## Agent 生命周期与工作区

- 最多保留最近使用的 20 个 Agent View，使活跃任务切换能够保留滚动位置、编辑器状态和 Terminal 展示，同时限制浏览器内存增长。
- 服务升级时根据 Farming Session Metadata 恢复仍在临时 ID 阶段的 Codex Terminal，包括置顶和首页可见状态，同时避免把临时 ID 写入 Provider Membership。
- Chat/Terminal 与权限模式转换增加保护：Terminal 一旦接受过输入，在可恢复 Provider Session 得到证明前不能静默切换。
- Archive、Restore、Fork、运行时替换与 Native PTY Host 恢复保留精确的 Provider Session Mapping。

## 验证

- 真实 Codex 跨皮肤发布门禁与 Terminal 直接输入门禁
- 单文件 CLI 打包及其中 Usage Worker/SQLite Smoke
- 在保留活跃 Agent 的前提下，对长期运行的 Linux 环境进行只读 Code/CRT 验证
