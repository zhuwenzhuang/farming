# Farming v2.2.35

[English](./v2.2.35.md)

这个版本强化了 Farming 的自托管生命周期，让用户更容易注意到已经完成的 Agent 工作，并收敛了多处高频 Code 交互。

## 安装、更新与实例隔离

- 每个 Farming Server 现在独占一个规范化配置目录，并拒绝冲突 Owner。不同安装可以安全隔离认证、Session、Runtime 状态和更新元数据，同时继续使用外部共享的 Workspace 与 Provider Home。
- npm 安装使用隔离的 Package Version 生命周期完成更新。候选包先暂存和校验，修改安装目录前会证明精确 Server 进程已经退出且端口已释放；陈旧 Updater Metadata 也会被安全协调，源码与 Standalone 安装不会被误当作 npm 部署。
- npm 包携带经过审核的生产依赖集合，全新安装和更新使用包内确定的依赖图，不依赖无关的全局环境状态。

## Agent 完成通知

- 页面处于后台时，Farming 可以在 Agent 完成后通知用户。ACP Chat 使用权威 Prompt `stopReason`；Terminal Session 消费标准 BEL 与 OSC 通知协议，OpenCode 使用其支持的 OSC 99 集成。
- 通知正文使用 Agent 最新可见回答或 Terminal 提供的消息，不再展示笼统的“已完成”。点击通知会回到精确 Agent，并关闭冲突的 Overlay。
- 通知权限是显式的 Agent 设置。多个后台 Tab 会协调发送，同一个完成 Turn 只产生一次通知。

## Chat、Plan 与侧栏交互

- ACP 浮动 Plan 现在只属于 Live Turn：仅当最新 Turn 仍在运行且 Plan 未完成时显示；Prompt 完成、失败、取消、进程丢失或后续 Prompt 开始时都会清理陈旧 Plan。
- History 现在展示完整 Resume ID，标记已经在主页面存在的精确 Session，并在恢复后打开对应 Agent，而不是继续停留在 History；焦点位于 History 搜索框时，Escape 会返回工作区。
- ACP Composer 菜单支持 Escape 关闭并恢复输入焦点；展开的 Usage 面板也遵循同一键盘约定，可用 Escape 收起。
- 新建 Codex Chat Agent 会在首个 Turn 仍运行时就使用首条任务生成标题，不再一直显示通用的 `Codex` 并等到任务完成。
- 空 Workspace 的无效启动保持立即可编辑；Project 分页按钮上的方向键不再误切换当前 Agent。Agent 与 Session 的“显示更多”也会向辅助技术暴露不同名称和隐藏数量。
- 关闭 Settings 或 Extension 详情后，键盘焦点会回到打开它的控件。
- Project 选项菜单打开期间暂停 Project 与 Agent 的 Hover Detail。鼠标打开菜单时不再预选第一项，键盘仍可从第一项开始导航。
- 鼠标经过 Git Branch Row 时不再同时高亮父 Project 标题；Agent Provider 图标也调整为更轻、与文字基线更协调的尺寸。
- Provider 专属控件继续由实际协商能力决定，不会仅凭 Provider 名称展示不受支持的 Session Mode 或操作。

## Browser 与休息体验

- Browser Viewer 的输入队列和 JPEG Frame Backlog 现在有明确上限，快速指针、Viewport 与 Stream 活动不会无限积累陈旧工作。
- Farming Pet 黑洞休息场景拥有更连续的吸引、引力透镜、吸积盘、辐射和蒸发过程，最后一分钟的归位也更顺滑。

## 升级

```bash
npm install --global farming-code@2.2.35 && farming daemon
```
