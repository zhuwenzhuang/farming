# Farming v2.2.21

[简体中文](./v2.2.21.zh_cn.md)

This release closes race windows around Agent lifecycle, structured Chat, Project Files, and updates.

## Fixed

- Serializes ACP prompt, steer, cancellation, and queued-message admission per Agent. Definite turn-end steer failures preserve message order, ambiguous failures are never replayed, and messages submitted during cancellation start at most once after the old Turn reaches a terminal state.
- Gives every observed ACP child Session an isolated control owner. Duplicate stops join one provider request, parent cancellation includes children proven active, stale bindings cannot modify replacements, and late updates cannot reopen terminal child state.
- Surfaces blocked ACP recovery as an actionable unavailable state instead of leaving a visible Agent backed by no registered runtime. Legacy records without a provable process identity remain fail-closed.
- Journals Agent Create, Update, Delete, and Archive intent before external side effects, then recovers unfinished operations without launching duplicate runtimes. Frequently updated Agent state is stored separately from lifecycle and process ownership metadata so hot writes cannot overwrite safety-critical identity.
- Fences Project Files saves, Create, Rename, Move, and Delete across browser and backend owners. Late UI responses cannot steal newer state, uncertain mutations reconcile from authoritative filesystem reads without automatic replay, and newer drafts survive older save completions.
- Preserves exact ACP Fork state and provider identity across Codex and process-owned Claude forks, including bounded child transcripts, patch decisions, startup rollback, and failed-cleanup reporting.

## Changed

- npm and Bundle updates now prepare into staging while the current server remains available. Applying a prepared update requires a separate restart action, and a failed npm directory switch restores the previous package before restart.
