# Farming v2.2.17

[简体中文](https://github.com/zhuwenzhuang/farming/blob/main/release-notes/v2.2.17.zh_cn.md)

Milestone codename: **TOKEN USAGE**

This release fixes Agent recovery across upgrades and reconnects, retains up to 20 recently used Agent views, and adds source-backed token history to both public skins.

## Highlights

- **Separate provider identity and product metadata**: Farming keeps product metadata under its `fsess_*` record while resolving Codex and OpenCode provider identities independently. Titles, pins, Project membership, runtime mode, and resume behavior survive temporary provider IDs, server restarts, and archive/restore transitions.
- **Provider-bound Codex and OpenCode startup**: Codex Terminal remains immediately interactive and promotes its temporary correlation ID only after confirming a unique rollout. OpenCode sessions are created with their provider ID before launch. Neither path relies on `--last` or a timing-only nearest-session guess.
- **Checkpoint recovery after backgrounding**: backgrounded browsers recover through Agent and terminal checkpoint state instead of remaining stuck behind a stale heartbeat warning or replaying historical terminal output.
- **Token activity in Code and CRT**: the Usage panel and CRT Billing view now share daily and hourly provider-backed token history, cache composition, active days, peak days, and exact selected-day details.

## Agent lifecycle and workspace

- Kept up to 20 recently used Agent views mounted so switching among active tasks preserves scroll position, editor state, and Terminal presentation without unbounded browser growth.
- Restored temporary Codex Terminal records from their Farming session metadata during server upgrades, including pinned and main-page visibility, without adding temporary IDs to provider membership.
- Added transition guards so a Terminal that has accepted input cannot silently switch Chat/Terminal or permission mode before a resumable provider session is proven.
- Preserves exact provider-session mapping across archive, restore, fork, runtime replacement, and native PTY host recovery.

## Upgrade

```bash
npm install --global farming-code@2.2.17 && farming daemon
```
