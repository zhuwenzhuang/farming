# Farming v2.2.32

[简体中文](./v2.2.32.zh_cn.md)

Milestone codename: **TYPESCRIPT**

This release completes Farming's full TypeScript migration, adds Qwen Code as a first-class coding agent, and turns the migration into a broad product and reliability pass across Agent workflows, Extensions, Browser, Computer, Chat, Terminal, Review, Files, and mobile use.

## Qwen Code and Agent workflows

- **Qwen Code is now a supported coding agent.** Farming discovers the system `qwen` executable, supports its `QWEN_HOME`, launches both Terminal and ACP Chat sessions, injects the Farming bootstrap, reads resumable session history, resumes existing work, switches between Chat and Terminal, and gives Qwen its own launch, sidebar, History, and provider-settings identity. Fork remains capability-driven and appears only when the live ACP agent negotiates standard `session/fork`.
- Project menus now offer direct Chat launch shortcuts for supported coding agents, avoiding an unnecessary Terminal-first start when the intended workflow is structured Chat.
- Registered Agent Homes remain visible even when their CLI is temporarily unavailable. Home selection, provider configuration, dangerous permission-skip flags, runtime dependencies, history, and launch identity now stay attached to the exact selected Home.
- The experimental JSON Chat and Codex App Server paths have been removed. New and recovered structured Chat sessions use the supported ACP path; Terminal remains the direct PTY path.

## Extensions, Browser, and Computer

- **Plugins → Extensions** is now a read-only catalog grouped by Agent Home and extension type. It recognizes Agent Plugins v1 and native Codex, Claude, Qoder, Skill, MCP, Hook, Plugin, and Command layouts, shows provider-owned configured/enabled/disabled state, and opens the exact source file without inventing a second Farming-owned enablement database.
- Browser Resources are now owned by an Agent. Multiple labeled Browser tabs share that Agent's Browser session and remain available through the UI, ACP projection, and the on-demand `farming browser` bridge.
- Computer Use is a separate Agent capability with a visible, Agent-owned Computer and human-viewable desktop. It is not hidden inside Browser automation, so desktop lifetime and Browser-tab lifetime remain independently understandable.
- **Isolated Browser** combines the same pinned `agent-browser` runtime with the Agent's visible Computer container. It is explicitly prepared, uses verified managed Chromium inside that container, and keeps Browser automation and the observable desktop on one exact runtime identity.
- Browser and Computer resource metadata now travels through each page's single versioned control WebSocket, with authoritative reconnect snapshots and revisioned updates. JPEG and noVNC streams remain separate and on demand; no Browser- or Computer-specific EventSource is added.
- Extension and capability pages perform a fresh authoritative read when opened instead of presenting a previous visit's snapshot as the current answer.

## Chat and collaboration

- Active ACP work keeps accepted steers and queued follow-ups in one ordered transcript. Queued follow-ups can be edited, sent, or discarded before delivery.
- Settings now choose whether messages sent during active work default to **Queue** or **Steer**; Command/Ctrl+Enter temporarily uses the opposite behavior. Session setting changes that cannot safely apply mid-turn are deferred until the Agent becomes idle, while newer choices supersede older deferred ones.
- The collapsed process area shows only the command currently running. Completed intermediate activity no longer leaves a stacked residue, while tool evidence, permissions, forms, plans, collaboration activity, file changes, and terminal details remain available on demand.
- ACP history preserves images and other media across replay, and transcript images can be opened for a larger inspection view.
- Composer drafts and attachments survive navigation and replacement more reliably, including queued follow-up editing and background Chat continuity.

## Review, Files, and Terminal

- Chat file-change cards continue to offer the exact ACP change review. Their Git comparison now opens the working-copy diff when changes exist and automatically becomes **Git Diff · Last Commit** when the working tree is clean.
- Project Files uses one explicit reveal owner when Chat or another surface opens a file, preventing the directory tree and Project list from fighting over focus or scroll position. Deep trees remain stable through expand, scroll, collapse, refresh, and reload.
- Terminal reattachment hides a parked xterm buffer until a current authoritative checkpoint commits. Fast recovery avoids a transient loading flash; slower recovery still exposes bounded progress and retry state.
- Foreground Terminal opening now takes priority over background usage and session prefetches, and Browser/Computer resource traffic no longer competes through additional long-lived control connections.

## TypeScript milestone and release reliability

- Farming's maintained backend runtime, shared browser protocol, classic browser, frontend bridges, scripts, usage scanners, and tests now pass repository-wide TypeScript gates. Release packages still ship generated or bundled JavaScript and do not require users to run TypeScript.
- Runtime bindings, provider capabilities, lifecycle journals, workspace roots, ACP checkpoints, Terminal state, update management, resource inventories, and release tooling now have explicit typed boundaries instead of loosely shared runtime shapes.
- Backend tests are TypeScript-checked as a first-class release surface. Production-shaped desktop Chromium and iPhone WebKit coverage exercises long Chat, Terminal, Files, permissions, authentication, Fork, background continuity, runtime switching, Browser, and Computer flows.
- App bundles and the single-file CLI explicitly include the generated Backend, Browser, Computer, and ACP runtime modules after the tracked-source archive is created, so clean release runners ship the same generated code verified during packaging and dogfood deployment.

## Product polish

- Project and Agent rows, hover previews, menus, settings, status presentation, file diffs, content sizing, dark mode, narrow layouts, and mobile controls received a coordinated interaction and visual pass.
- Farming Pet rest reminders now use an explicit delayed interaction model with regression coverage.

## Upgrade

```bash
npm install --global farming-code@2.2.32 && farming daemon
```
