# Farming v2.2.12

[简体中文](https://github.com/zhuwenzhuang/farming/blob/main/release-notes/v2.2.12.zh_cn.md)

Milestone codename: **PROJECTS**

This release changes Farming Code project navigation, workspace selection, the Chat composer, Project Files, and local token activity. It also adds Project and Codex lifecycle actions, an installable app-mode guide, and an updated public product tour.

## Highlights

- **Project pin order and action menu**: pin or unpin Projects from the `...` menu, keep multiple pins in the order they were added, reveal a Project in the host file manager, create a permanent Git worktree, rename it, mark its Agents read, archive its chats, remove it from Farming, or delete an eligible worktree through the explicit destructive flow.
- **Independent Agent visibility per Project**: a compact eye control on each Project row hides or restores only that Project's Agent list. Files remain available, and the Project title and actions keep a stable aligned baseline.
- **In-place workspace directory tree**: New Agent's host-backed directory picker now expands nested directories lazily in place instead of replacing the current level. Parent and sibling context remain visible while selecting a deep workspace, including from a remote browser.
- **Local token activity details**: Usage opens into 24-hour and 52-week views with compact token totals, hourly labels, a selected-day readout, current-versus-previous seven-day analysis, peak-day emphasis, and an hourly histogram aggregated by Agent type. The peak day uses a crown silhouette and days above one billion tokens use a flame silhouette without losing heat intensity.
- **Consistent Chat and Terminal composer controls**: both runtimes expose the same edge-hover collapse and restore action. Collapsing hides only the input surface, preserves unsent drafts, and keeps the active transcript or Terminal visible. Chat spacing and copy controls are tightened so the latest result stays closer to the Composer.
- **Project Files layout and syntax diagnostics**: Files, Changes, Untracked, History, and tree rows share one typography, row-height, and hierarchy-spacing system. Markdown links retain the source Agent return path, and JavaScript/TypeScript editing provides syntax diagnostics without running a project typecheck.
- **History pagination and Codex archive order**: History loads older provider sessions only at a page boundary. Archiving a live Codex Agent completes Farming's local lifecycle first and then invokes the provider archive operation for the stable session, reporting provider failure without reviving the Agent.
- **Installable desktop app guidance**: Farming Code exposes an app/fullscreen entry with Chrome installation guidance for a standalone window. Installed launches use a base-path URL without the startup token and reuse the existing authentication cookie.
- **Product tour and responsive-layout update**: the public Code and CRT screenshots now show the current interface, interface-switching instructions are included, and transcript typography and wide or narrow layouts reduce empty gutters and layout shifts.
- **Browser tests use semantic and test-id contracts**: browser tests target semantic or test-id contracts for project actions, terminal links, context menus, files, Chat continuity, workspace selection, Usage, and platform-specific rendering.

## Compatibility Note

- The macOS CLI artifact is ad-hoc signed, not Developer ID signed or notarized. Depending on local security settings, the first launch may require an explicit manual allow action before rerunning the CLI.
