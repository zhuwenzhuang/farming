# 关联会话与旁聊设计

> English version: [related-sessions-design.md](./related-sessions-design.md)

状态：设计提案。本文定义目标产品行为与验收合同，不代表相关控件或 Provider 能力已经交付。
现有 [ACP Runtime](acp-runtime.zh_cn.md)、[Session 身份](provider-session-identity.zh_cn.md)、
[Agent 列表](agent-list-state-protocol.zh_cn.md)、[UI 设计](../../development/ui-design-protocol.zh_cn.md)
和 [交互协议](../../development/ui-interaction-protocol.zh_cn.md)仍是对应领域的权威合同。

## 产品决策

用户可以在父 Agent 继续工作时提问。旁聊使用具有明确上下文快照的独立会话，消息不会自动进入父会话。

用户创建的旁聊与 Provider 创建的原生子 Agent 共用关联会话列表、消息展示、注意力提示与按能力显示的操作。
两者保留明确的用途和控制方。Provider 上报一个子 Agent，不代表 Farming 就能直接向其发送消息、恢复、关闭或删除。

初版每个父 Provider Session 保留一个旁聊。再次打开回到原会话；结束保留历史；删除后可以重新取快照并创建。
普通 Conversation Fork 继续创建独立任务，不把已有 Fork 重新归类。
嵌套的用户旁聊、转为独立任务、自动合并结果、新建 Worktree、Farming 自行编排子 Agent 不在首版范围内。

## 左侧列表与会话视图

```text
项目
  v 修复登录问题                  运行中
      旁聊 · 缓存行为             回复中
      子 Agent · 排查缓存失效     运行中
      子 Agent · 补充回归测试     已完成
  > 优化构建速度                  已完成
```

关联会话直接位于父行下面，使用同一导航行家族的缩进层级变体。用途通过共享的聊天／Agent 图标和无障碍标签表达，
标题显示简短话题或委派任务。不增加常驻的“子 Agent”中间分组。旁聊排在前面，委派任务按创建顺序保持稳定，
不随每次消息更新重排。大量子项使用有界分页与共享“显示更多”交互，后端汇总包括当前页外的子项。

Provider 创建子项只更新列表，不抢选中状态、不自动展开祖先，也不把用户正在阅读的位置滚走。

- 父任务已有操作菜单提供“旁聊”。打开时展开父行，创建确定成功后选中子项。重复点击和多浏览器请求合并到同一个后端操作。
- 点击父行显示原有 Chat 或 Terminal；点击子项在现有工作区面板打开其会话。紧凑面包屑显示父任务与用途，并可返回父任务，不增加新的标题工具栏。
  初版不要求双栏分屏；查看子项期间父任务继续运行。
- 只高亮被选中的行，选中子项不同时高亮父行。Hover 与 Selected 使用同一表面，不增加左侧边线。
  Light、Dark、Paper 共用几何和文字规范；紧凑布局沿用导航抽屉和全宽工作区。
- 折叠父行不停止子会话。独立的关联会话指示汇总运行、待处理、失败与未读状态，不改写父任务自己的运行状态。
  等待用户或失败的子项即使被分页、祖先折叠隐藏，也必须能够被发现。
- 阅读父任务不把子会话标为已读。Read Cursor 归属于精确子会话，沿用可见且阅读最新内容的规则。
  父行可汇总子项注意力，但统计不能因此把同一工作重复计数；没有独立 Farming Runtime 的原生子项不增加 Farming 存活 Agent 数。
- 固定或移动父任务时，子项随父任务展示。子项不独立进入 Pinned，也不在顶层历史中重复出现。
  搜索保留父任务路径并打开同一身份；父列表分页不把嵌套子项计作额外父任务。

消息面板复用 Chat 渲染、草稿归属、历史滚动、工具详情和权限卡片。
父任务工具调用中的子 Agent 预览链接到同一子会话视图，不建立第二套消息状态。
没有 Prompt 能力的原生子项提供可查看的消息历史和明确的控制方说明，不提供可用的输入框。

## 操作与记录保留

| 用户操作 | 运行效果 | 记录与导航 |
| --- | --- | --- |
| 返回、切换任务、折叠父行、收起菜单 | 无 | 保留会话与运行提示 |
| 停止回复 | 支持时取消该子会话当前 Turn | 保留 Session，之后仍可发消息 |
| 打开已结束旁聊 | 读取历史，不启动 Runtime | 用户再次发送消息时才恢复同一个 Session |
| 删除旁聊 | 完成所属 Runtime 清理，再删除精确 Provider 历史 | 确认完成后移除子行 |
| 复制到父任务草稿 | 无 | 把用户选定内容带入父任务普通草稿，不覆盖已有草稿，不自动发送 |

不提供“结束旁聊”按钮或专用关闭控件。Runtime 按下文回收政策自动释放，用户仍可阅读保留的历史。
Escape 和外部点击继续服从共享交互协议，只负责本地导航或浮层收起，不能隐式发送删除请求。
复制到父任务草稿保留来源引用，由用户正常提交；父任务忙碌时沿用已有 Prompt／Steer／排队策略。

首版不为持久旁聊单独增加历史自动过期政策。显式删除和现有已授权的父任务／Project 删除负责记录移除。
不支持精确删除历史的 Provider 仍需支持自动释放 Runtime，不能提供声称删除成功的假操作。
真正 ephemeral 的 Provider Session 无法满足旁聊历史保留合同，不能静默用于该路径。

## 身份、所有权与能力

后端在现有 Session 元数据和生命周期日志中扩展关联关系，拥有父子关系、用途、控制方、快照来源和操作结果。
浏览器只拥有选中、展开与草稿等展示状态；Provider 通知提供原生执行事实。

关联行和汇总扩展现有版本化列表 Snapshot／Delta 投影，共享其 Generation、顺序、作用域完整性和恢复规则。
Adapter 向后端投影提供事实；浏览器不从原始消息事件独立建立第二份子项库存。

| 关注点 | 合同 |
| --- | --- |
| 身份 | 真正的 Provider Session 使用标准 `(provider, providerHomeId, sessionId)`；Runtime Agent ID 只是绑定，不能作为持久父键。 |
| 原生子项身份 | 在 Adapter 证明持久 Provider Session 映射前，不透明通知 ID 只在精确父 Runtime Generation 中有效；不能猜测它可用于 History API。 |
| 用途 | 旁问或委派工作；用途本身不授予控制能力。 |
| 控制方 | Farming 管理自己明确创建的旁聊 Session；Provider 管理原生委派及结果回传。 |
| 能力 | 逐子项投影真实的读取、发送、取消、恢复、释放、删除能力；缺失或未知能力不授予写操作。 |
| 快照 | 保存精确父身份和 Provider 拥有的上下文边界；重开不能偷偷重新取快照。 |

同一 Session 只允许一个存活 Runtime Owner，即使它同时可从 Provider 历史中发现。
关联边不能成环。原生嵌套保留真实父子关系并复用同一行样式；每个父任务一个旁聊是产品规则，不限制原生子 Agent 数量。
旁聊启动的后代归入该旁聊 Runtime 的清理范围，不归入主任务的其他执行范围。

可用能力取 pinned Adapter 已验证合同、实时协商与精确子项所有权的交集。
连接级方法声明或 `subagent_spawned` 事件不能授予所有子项该方法的调用权。
原生子项控制留在 Provider Adapter；Farming 不冒充父 Agent，也不另建 Fork 来伪装不支持的控制成功。
旧元数据和新类型化通知在该边界归一化，不进入通用 UI 分支。

## 创建与继续旁聊

创建复用 Conversation Fork 的准入、Provider 启动配置和持久生命周期结算，结果进入关联成员列表，不进入顶层任务列表。
首版沿用现有 ACP 合同，取当前 Turn 之前的 Provider 稳定边界，不复制未完成工具调用。
不得为了 Fork 而取消、Steer、切换或重新加载父 Runtime。

子会话标题栏显示“上下文截至上一轮完成”，并提供可用的来源引用。
父任务当前的部分回答和后续变化不在快照内。没有安全边界时明确说明原因，不把 Fork 静默排在父任务整个运行 Turn 后面。
仅支持空闲 Fork 的 Provider 可以在空闲时提供功能，但不能被标为支持运行中旁聊。

纳入“当前已保存进展”属于后续 Adapter 合同：必须证明并发写入／压缩期间的复制一致性，
修复子会话续聊所需的未完成工具配对，并确保继承的待执行内容不会被显示为子会话仍在执行。
启用前必须更新 ACP Runtime 的拥有文档。单纯移除空闲判断不构成支持。

继承上下文只作为参考。Provider 侧 Bootstrap 要求子会话回答用户的旁问，不自主继续父任务或 Goal。
子会话模型、权限、环境和工具范围通过现有 Adapter 配置边界处理，不提升权限。
工具请求与结果归属于子会话。对话隔离不等于文件隔离：首版共用现有 Workspace，不承诺文件系统快照，不创建 Worktree。

重开已有旁聊不更新父上下文，标题栏继续展示原快照边界。
用户可以通过普通消息补充选定的新信息，或者明确删除后重新创建。

## 最小状态转移模型

复用现有 Runtime 状态；关联成员关系不是第二套 Agent 生命周期。
资源绑定、Turn 活动和历史保留是不同事实。下表描述操作，不新增一套 Runtime 枚举。

| 触发 | 准入／权威 Owner | 效果与有界出口 |
| --- | --- | --- |
| 打开旁聊 | 后端串行处理父任务唯一保留旁聊槽位 | 返回已有身份，或先持久化一次创建意图，再请求 Provider |
| Fork 完成 | 操作身份与源快照边界仍匹配 | 持久化子身份和关联成员后才发布成功；过期浏览器导航意图不能抢回页面 |
| Fork 被拒绝 | Provider 明确失败且没有未决子会话 | 发布失败并释放预留；显式重试可创建新操作 |
| Fork 结果不明 | 超时、响应丢失、身份发布前后崩溃 | 保留日志与预留，仅对账，不重放创建，也不声称没有子会话 |
| 向保留子会话发送 | 当前能力、Owner、操作 Generation 匹配 | 必要时恢复精确 Session，通过现有队列准入一次有身份的 Prompt |
| 停止回复 | 精确子 Turn 正在运行且支持取消 | 只取消该 Turn；在现有截止时间内观测完成或明确取消失败 |
| 结束／资源回收 | 后端阻止该子项继续准入 | 对账在途输入，释放所属资源，持久化保留状态；失败明确保留为清理失败／不确定 |
| 删除 | 精确子身份，支持删除，创建／恢复已结算 | 阻止恢复、完成所属清理、删除存储、再移除成员；删除不明保留可对账 Tombstone |
| 原生子项更新 | Adapter 证明父归属与 Generation | 更新执行状态；旧事件不能复活已删除／替换子项，不完整快照不能证明删除 |
| Server 重启 | 现有生命周期恢复与精确所有权 | 准入输入前对账未完成操作；保留记录不自动启动、不重新 Fork、不重放消息 |

创建、恢复、结束、删除与父任务销毁在同一 Owner 串行结算。
同一操作身份的重复请求合并，变更内容不合并。
创建期间收到结束请求时，记录目标终态；子身份确定后释放精确子会话。
身份仍未知时保留不确定状态，不得重新开放槽位并泄漏第二个 Fork。
清理和删除均不能通过乐观移除 UI 来假装成功。

## 资源回收与父任务生命周期

结束 Runtime 是内部生命周期操作，不增加面向用户的按钮。它复用现有 Agent／ACP 释放路径，覆盖子会话拥有的 Binding、订阅、待处理权限、Elicitation、Terminal 与外部 Resource。
不引入优雅停止替代路径。进程停止保留 Farming 唯一的直接硬停止合同；可选 ACP Session 释放只属于现有共享 Runtime 边界。
其他 Session 仍拥有共享 Provider 进程时，不能为了回收一个子项而杀掉整个进程。
无法证明独立释放的 Adapter 不能提供完整旁聊合同。

建议首版资源截止时间：Turn 完成后空闲五分钟（创建后没有输入也适用），或最后一个监督浏览器失去旁聊 Attachment 后六十秒。
空闲回收要求没有活跃 Turn、权限／Elicitation、子任务或所属异步工作。
这些期限只回收资源、保留历史，不是记录过期时间。
浏览器在六十秒内重新连接可保留 Runtime；超过期限则执行同一“结束”操作，即使旁聊仍在回答。

监督基于现有已认证 Workspace 连接中的显式关联会话 Interest，不依赖消息面板可见性。
返回父任务保留 Interest；从其他位置读取历史或仅列出 Project 不获取它。
创建旁聊或明确向保留旁聊发送消息时，在 Runtime 准入前获取 Interest。
多浏览器按精确连接与子身份计数，心跳／存活判断和有界后端过期队列复用共享基础设施。
不添加逐行浏览器轮询，不依赖 `beforeunload`。
后端保存最近监督截止时间并在重启后对账。截止时的新活动通过同一 Owner 竞争：
回收准入前可以阻止回收，一旦结束已经开始，不能直接重新打开 Runtime。

上述期限只适用于 Farming 拥有的旁聊。Provider 原生委派服从父 Runtime 生命周期，不因观察者关面板就被取消。
主动结束主 Agent 时，精确清理范围包括它拥有的活跃旁聊与 Provider 管理的后代。
父任务一个 Turn 自然完成，不结束用户正在进行的旁聊。

归档父任务时结束附属旁聊 Runtime，把相关历史保留在已归档父任务下，成功后隐藏整组。
删除父任务／Project 时先枚举并结算所属子项，再移除记录。
不支持或结果不明的子项删除必须明确保留，不能静默留下隐藏的所属资源。
原生 Provider 历史只按已证明的删除合同处理；不完整历史扫描中缺少父任务不触发级联清理。

## ACP 与 Terminal 边界

运行时选择一个明确的 Adapter 策略：原生 ACP Fork、经过验证的 Provider 旁会话扩展，或不可用。
扩展必须满足与原生 Fork 相同的快照、身份、续聊和清理验收。
协议的 Draft／扩展状态与 Provider 实际能力分别判断。

Provider Terminal 只有在 Adapter 能解析精确父 Session，并能独立创建结构化子会话，
且不占用、加载或中断存活父 Runtime 时，才提供 Farming 旁聊入口。
随后使用相同关联会话模型和 ACP 子视图。普通 Shell 没有相应上下文，不自动提供旁聊。

在 Terminal 中手动输入的原生 `/side`、`/btw` 继续由 CLI 管理。
Farming 不从终端文字推断关联会话所有权，不代输这些命令，也不通过切换父 Runtime 来模拟旁聊。
Code 是首个创建界面；CRT 消费相同后端身份、状态与清理事实。
尚未具备关联会话导航的界面必须显示存在关联工作，并提供进入 Code 视图的路径，不能把它隐藏。

## 交付与验收

1. 通过确定性假 Provider 增加后端关系与能力投影；把原生子项归一到该模型，不改变控制方。
2. 增加共享左侧子行与已有消息／输入面板组合，同时接通创建、保留后重开、删除和自动有界回收。
   不能先交付创建，再把清理留到后续版本。
3. 每个 Adapter 通过共同端到端验收后才启用。运行中旁聊必须覆盖父任务活跃场景，空闲支持保持明确边界。
   Terminal 入口单独通过精确身份与不中断验收后启用。

| 验收领域 | 必须提供的证据 |
| --- | --- |
| 父任务运行 | 保持父 Prompt 和工具输出未结束，创建并与子会话交谈；证明父任务未收到取消／切换，且能正常完成 |
| 快照 | 验证显示边界、部分输出被排除、源未变化、子消息隔离和子会话正常续聊 |
| 共享身份 | 多浏览器同一父任务只创建一个旁聊；不同 Home 的相同 ID 不混用；原生合成 ID 不被猜成历史身份 |
| 控制 | 只读原生子项、仅可取消子项、完整旁聊只展示各自已验证操作；过期能力和 Generation 拒绝写入 |
| 顺序与失败 | 重复打开／发送、Fork 中结束、发送与回收竞争、删除与恢复竞争、乱序事件和响应丢失均不重复执行 |
| 清理 | 精确释放子进程、Binding、工具资源和交互；共享兄弟存活；空闲／断连到期和清理失败路径都有明确终态 |
| 重启与保留 | 创建／删除各阶段硬进程丢失后能精确对账；读取历史不触发推理；缺失／不完整库存不导致猜测删除 |
| 父生命周期 | 自然完成、主动结束、归档、删除与原生后代遵守各自所有权和保留规则 |
| 组合 UI | 父运行＋子流式输出＋原生子项等待，长标题、分页、未读、折叠、固定、搜索、键盘和触屏，在 Light／Dark／Paper 与紧凑布局验证 |
| 成本与规模 | 折叠行不加载完整子消息或启动 Runtime；多父任务、多原生子项下保持分页、Delta 与 Fixture 清理有界 |

Provider 启用除确定性测试外还需要低量、隔离的真实 Provider Smoke。
源码阅读或 Fork 请求成功，不能单独证明续聊、运行资源回收或 Terminal 互操作已通过。
