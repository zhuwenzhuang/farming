# Browser 交互

> English version: [browser-interaction.md](browser-interaction.md)

## 远程 Viewer 输入

后端拥有当前 Runtime 目标和输入准入；Viewer 只拥有本地焦点与输入法组合状态。
物理按键按下／松开、已提交文本、鼠标按钮和剪贴板传输是不同操作。已提交文本不能
重新解释成快捷键；物理按键保留修饰键、重复、位置和对应松开。剪贴板只传纯文本，
不能读取执行主机的系统剪贴板。

| 触发 | 条件与效果 |
| --- | --- |
| 输入 | 必须来自已连接的 Viewer 和同一运行中的 Resource generation；非法输入明确失败。 |
| 输入法组合 | 中间文本留在本地，仅提交结果送到远端；取消不发送文本。 |
| 失焦、指针取消、Viewer 关闭 | 释放该 Viewer 按住的键和按钮，不导航、不重放文本。 |
| Runtime 目标或输入 Viewer 改变 | 新目标接收输入之前先释放旧状态。 |
| 断线 | 禁用输入并丢弃未发送事件；后端在传输可用时释放按住状态，操作不自动重放。 |
| 剪贴板 | 只复制选中的纯文本，拒绝密码选择；本地复制成功后，剪切只能删除未改变的选择。不支持的选择明确失败。 |

鼠标移动、滚轮只能合并相同按钮和修饰键状态的事件。按键、按钮和文本构成顺序屏障。
Desktop 原生输入继续由 Chromium 负责，不经过远程 Viewer。系统浏览器、隔离浏览器和
借用 Chrome 使用同一套用户流程验收。

人工输入通过带响应的 CDP 连接操作现有 Runtime；agent-browser 流负责画面。
输入连接验证选定标签页的精确身份，包括 URL 相同的页面，并使用私有目标 Session，
避免关闭输入连接时解除其他 Relay 客户端的调试连接。输入连接丢失或动作超时意味着
结果不确定：Runtime 明确失败，丢弃排队输入，要求显式重新启动 Browser，不重放操作。
这不增加浏览器启动器或第二个生命周期所有者。

## 共享控制

Web Viewer 允许人工直接操作，不要求先接管、再交还。它与 Agent 共享同一个 Browser，
不提供独占人工租约。输入顺序和精确目标身份用于防止状态丢失与跨页投递，不能保证
人工和 Agent 同时修改网页时在语义上不冲突。

登录等需要人工协助的场景，由 Agent 等待用户操作，继续前重新读取当前页面。
打开或聚焦 Viewer 不会隐式暂停 Agent。独占交接、多 Viewer 控制权仲裁后置，
待实际冲突证明必要性后再设计。Desktop 原生 Browser 保留已有控制契约。

## 验收

在真实 Chromium 的输入框、contenteditable 和网页代码编辑器中验证标点、中文组合、
选中替换、撤销重做、纯文本剪贴板、特殊键、双击、拖动和失焦。检查网页值及事件，
不能只检查发送消息。按住按键／按钮时验证断线和切页。可见变化覆盖 Light、Dark、Paper，
平台与移动端覆盖必须明确报告。
