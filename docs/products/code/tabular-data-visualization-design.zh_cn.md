# 表格数据与可视化方案

> English version: [tabular-data-visualization-design.md](./tabular-data-visualization-design.md)

状态：阶段 1 已完成，更新日期为 2026-09-19。只读查看器及三 Sheet、1.2 万行代表性工作簿验收已经完成；数值性能预算和阶段 2–4 尚未完成。

## 产品目标

用户可以打开 Agent 生成的工作簿，检查数据，选择范围，生成图表，并携带准确的数据位置继续询问 Agent。文件、Chat 与分析视图组合在现有工作区中。

第一阶段提供只读 XLSX、CSV/TSV 浏览；后续增加有类型的数据集、少量常用图表和可保存的分析视图。电子表格编辑、公式重算和任意数据库连接分别决定范围。

## 当前实现

XLSX、CSV 和 TSV 文件会在现有带版本的文件标签页中打开。解析使用固定版本的 SheetJS CE 0.20.3，在可取消的浏览器 Worker 中运行；VTable 1.26.8 只在打开表格时加载。表格渲染器就绪后才启用地址跳转、查找、复制和引用；复制与引用使用同一份当前显示的选区快照。查看器提供工作表切换、查找、地址跳转、选区与复制、带来源引用到 Chat、合并单元格、原始坐标、格式化缓存值、公式查看，以及公式缺少缓存和隐藏内容的明确提示。

后端先经过现有 8 MiB 预览限制，再在传输 XLSX 前限制 ZIP 条目数、单条目解压大小和总解压字节数。Worker 另外限制行列数、保留单元格范围、文本长度和解析时间。选区转数据集、图表、保存分析视图及 Agent 上下文附件尚未实现。

## 现有基础与参考项目

- Farming 已有工作区授权、精确文件监听、带版本的文件模型、编辑器标签页和二进制传输。阶段 1 查看器复用这些路径，增加有界表格解析和渲染，没有新建文件访问体系。
- Farming 已把 Codex 可视化引用适配成 HTML 资源，并在 Chat 的沙箱 iframe 内显示。目前准入仍有提供方专属逻辑。普通 HTML 文件预览禁止脚本；专用可视化策略允许部分外部脚本 CDN，因此不能据此认定支持离线。
- Open WebUI 用 SheetJS 读工作簿、切换工作表，再生成经过清理的 HTML 表格。所检查实现会展开全部行列，不适合作为 Farming 大表架构；它也识别 Vega/Vega-Lite 代码块。
- Craft Agents 把文件中的结构化数据与聊天内的紧凑表格分开，支持展开和导出。所检查的 spreadsheet 块是 JSON 转 HTML 表格，并不是 XLSX 导入器或虚拟化工作簿引擎。值得借鉴交互，不应照搬其币种、精度和数据规模假设。
- OpenAI 当前桌面文档描述了与聊天并列的表格/文档预览、批注和交互式 HTML 预览。可视化文档强调可交互解释及快照结果。可以借鉴这些产品模式，但不能据此推断桌面端使用了什么库，或所有账户均具备相同能力。
- MCP Apps 展示了嵌入工具的宿主/视图边界和显式消息通信。未来外部交互资源可参考它；基础本地文件浏览不要求接入 MCP Apps。

## 技术选型

完全开源实现是选型硬约束。采用的组件及必需能力必须使用与 Farming 兼容的开源许可证，支持自托管/离线运行，不依赖商业授权、闭源转换服务、许可证密钥或付费功能解锁。约束覆盖规划中的选区/复制、导入/导出、图表和探索分析，而不只覆盖初期查看器。仅源码可见或免费使用的闭源软件不符合要求。项目存在可选商业产品不影响其可独立使用的开源版本入选，但任何规划能力都不能依赖商业部分。

AG Grid 从候选与对照清单中移除，因为所需的范围选择和内置剪贴板能力属于商业功能。任何依赖 Pro 导入/导出的电子表格路线同样排除。

| 职责 | 优先方向 | 决策边界 |
| --- | --- | --- |
| 工作簿解析 | 仅使用 SheetJS CE，从官方支持的渠道固定版本 | 保留原值、显示文本、坐标、合并区域及公式信息；核对具体 CE 包及依赖，不依赖 Pro。必需能力若在 CE 中不可用，选择其他开源实现。 |
| 工作簿/数据网格 | VTable 核心，配合 Farming 自有只读工作表控件 | 优先考虑范围选择、复制、合并、大表渲染与 MIT 许可；Canvas 的键盘/无障碍及 React 19 集成必须验收。 |
| 常规图表 | Vega-Lite，加受约束、带版本的声明式定义 | 便于 Agent 生成与人工检查，统一主题和数据绑定；运行时本地打包、按需加载。 |
| 可选探索分析 | 常规图表完成后评估 Graphic Walker | 可嵌入 React 的字段/视觉编码配置与查询接口，与 Vega-Lite 方向一致；只在进入 Explore 时加载。 |
| 探索分析替代方案 | Perspective | 当透视、流式更新和响应式表图切换成为主要需求时优先评估；默认不同时引入两套探索引擎。 |

VTable-Sheet 自带公式引擎和编辑生命周期。先验证核心网格及显式缓存值展示，避免把导入公式交给 VTable-Sheet 意外重算。组件功能列表不能证明 Excel 保真度。

依据解析契约和代表性样本做一次有时间上限的 VTable 原型验证，产品只选一个渲染器。如果 VTable 无法满足必要的无障碍或正确性门槛，按相同要求评估其他完全开源的网格，不能因此引入商业依赖或悄悄删掉必需交互。

## 用户体验

Chat 中的 XLSX 链接和 Explorer 文件打开同一个文件标签页。紧凑工具栏提供工作表切换、查找、单元格地址、复制和引用提问；行号、列标、列宽调整、冻结表头、只读公式/值查看帮助用户检查。工作簿模式保留原坐标和顺序。

“作为数据使用”把选中的矩形区域转成明确的数据集。展示建议表头行与字段类型，允许调整；保留空单元格，区分缺失与零，前导零标识符保持文本，并保留原单元格位置。合并标题、小计、多块数据区域不能静默转成普通记录。

数据模式增加排序、筛选、字段统计和创建图表。先提供柱状图、折线图、散点图、直方图、热力图；明确维度、指标、聚合、单位和筛选范围。图表与数据表引用同一结果版本，切换视图不能改变统计对象。

聊天中显示紧凑的表格/图表卡片，注明来源、行数并提供明确的打开入口；文件标签页承载完整检查。“询问 Agent”把来源版本、Sheet/范围或稳定记录身份、筛选条件、所选字段及有限样本作为上下文附件放入输入框，由用户检查后发送。排序后的行号本身不能作为稳定来源引用。

工具栏、标签页、菜单、反馈和内容区域遵循现有 [UI 设计协议](../../development/ui-design-protocol.zh_cn.md)。Light、Dark、Paper 共享几何和控件；使用统一悬浮/选中表面，不用左侧边线标记激活。图表提供标签与可访问的数据表，不能只用颜色表达含义。

## 数据与职责边界

```mermaid
flowchart LR
  F[授权且带版本的文件] --> W[工作簿快照]
  W --> G[只读网格]
  W --> R[明确范围和字段解释]
  R --> D[数据集快照]
  D --> Q[有界筛选与聚合]
  Q --> T[结果表格]
  Q --> C[图表定义]
  C --> V[图表视图]
  T --> A[交给 Agent 的选中上下文]
  V --> A
```

区分工作簿和数据集模型。工作簿是稀疏单元格文档，包含原值、显示文本、格式、公式/缓存可用性、合并区域和工作表身份；数据集是明确表头/范围解释并带来源的有类型记录。计算使用类型值而非格式化字符串，精度敏感的整数/小数不能静默转换为 JavaScript number。

后端继续权威管理路径准入、文件字节、版本及访问归属。小文件解析和有界本地变换可以在浏览器 Worker 中作为派生计算执行。复用工作区二进制传输，在所属边界扩展预览能力与版本校验，避免 Base64 拷贝和文件模型可合并的重复读取。

解析快照身份包含访问归属、规范化资源、文件版本和解析器版本；数据集身份再包含 Sheet/范围及字段解释。保存的视图包含数据集身份、变换、图表定义和渲染器/协议版本。保存操作必须经过现有带版本检查的工作区写入。

初期图表只处理完整准入的数据集。只对某一页或样本排序/筛选，不能标成全量结果。未来需要查询服务时，由它负责全范围筛选、聚合、分页，返回结果版本、总量/范围和截断信息；届时再评估 DuckDB/Arrow，支持 XLSX 本身不构成部署数据库引擎的理由。

所有支持的 Agent 提供方使用相同表格/图表资源契约和上下文附件。提供方专属指令由适配器归一化，不把 Codex 专属元数据扩散到通用分析接口。

## 最小状态模型

| 归属/状态 | 触发与条件 | 效果和终止路径 |
| --- | --- | --- |
| 文件模型：不存在 → 读取中 | 授权打开，可加入既有读取 | 有界读取字节与版本，进入就绪、明确错误、超时或取消。 |
| 派生工作簿：解析中 | 当前文件版本，体积与格式通过准入 | Worker 在预算内解析，进入就绪、不支持、错误、超时或取消；只有当前代次可提交。 |
| 就绪工作簿/数据集 → 过期 | 精确监听失效或重连校验 | 旧内容明确标成过期，进行权威重读；字段/范围变化使相关分析失效。 |
| 查询/图表：计算中 | 数据集版本有效，变换/定义有界 | 生成结果或诊断；旧任务取消且不能覆盖较新结果。 |
| 任意暂态 → 释放 | 关闭、访问归属变化、版本替换、缓存淘汰 | 取消所属请求，释放 Worker 任务、渲染器、缓冲区和对象 URL；仍有其他持有者时共享工作继续。 |
| 失败 → 重新请求 | 显式重试或权威失效通知 | 重新校验后恢复；访问/格式错误不进入自动重试循环。 |

文件生命周期和导航继续遵守 [工作区文件状态模型](./workspace-file-state-model.zh_cn.md)。切换 Sheet 不重复读取文件；返回保留模型恢复视图状态。缓存预算覆盖全部工作簿，不能只限制单标签页。

## 正确性与资源约束

- 公式显示带来源说明的缓存结果，缺失缓存必须明确，不能伪造零或声称已重算。不执行宏，不刷新外部链接。
- 验证日期体系、时间解释、百分比/金额精度、隐藏行/Sheet、稀疏范围、合并单元格及 CSV 编码/分隔符。隐藏内容可以区分，分析说明是否包含它们。
- 限制压缩体积、ZIP 条目数、解压字节数、实际单元格数、文本长度、解析时间、并发任务与保留数据；解压过程中执行限制，不能只相信 ZIP 元数据。Worker 防止解析阻塞主线程，但不是具有硬内存上限的进程沙箱。
- 当前二进制预览默认 8 MiB 是需要测量的现有限制，并不代表每个 8 MiB XLSX 都安全。如果解析器无法执行必需资源限制，应收紧准入或使用有独立资源上限的解析进程，再支持该类文件。
- 无效、加密、不支持、超预算文件提供可操作诊断；截断数据和采样图表明确标注范围。
- 校验图表定义、字段引用、变换、URL 和规模；声明式格式本身不等于安全边界。标准图表使用授权本地数据和本地资源；任意 HTML 继续使用现有隔离资源路径与明确能力。
- 复制/导出区分原值与显示值，处理 CSV 公式注入，不能静默改写原工作簿。默认不把源数据发送到公开 Office 预览服务。

## 交付计划

| 阶段 | 交付内容 | 退出标准 |
| --- | --- | --- |
| 0：有界验证 | VTable 原型验证，确定解析/格式契约和唯一渲染器 | 建议限时 1–2 个工程日；核对键盘、选区/复制、合并、依赖完全开源、内存、加载成本和主题。缺少关键能力必须阻止选型，不能掩盖。 |
| 1：实用文件浏览 | XLSX、CSV/TSV，Sheet、格式、坐标、冻结表头、复制/查找、精确刷新 | 三 Sheet、约 1.2 万行的代表性工作簿数值正确，无导航竞态；明确提示不支持的 Excel 特性。旧 XLS 可单独通过样本门槛后加入。 |
| 2：实用分析 | 选区转数据集、排序/筛选、字段统计、五类图表、选中上下文交给 Agent | 图表和表格总量一致，排序/筛选不丢来源；各提供方都能打开产物并获得相同上下文语义。 |
| 3：可复用结果 | 统一聊天卡片与文件视图，保存图表/视图，图片/数据导出、重新打开与过期反馈 | 重启/重开可以复现来源绑定和配置，或明确说明来源已变更/丢失。 |
| 4：可选探索 | Graphic Walker；确有需求时才增加有明确归属的查询后端 | 真实重复工作流证明手动字段探索或数据规模超出阶段 1–3；透视/流式需求优先时改评 Perspective。 |

阶段 1–3 构成首个完整产品闭环。阶段 2 可先增加最小结构化结果卡片，阶段 3 完善复用与持久化。原型验证之外的工期应在测得集成结果后估算。

## 验收

使用匿名样本：三 Sheet、约 1.2 万行中文工作簿，10 万行有类型数据集，宽稀疏表、合并表头、精度敏感 ID、两种 Excel 日期体系、百分比、带/缺缓存公式、隐藏内容，以及损坏/加密/超预算文件。包含远端工作区延迟与受限/离线网络。

覆盖快速切文件/Sheet、解析中关闭、重命名/删除、并发持有者、监听事件突发、断线重连、访问归属切换、进程丢失后重开。证明旧任务不能覆盖新内容，失败释放资源，计算期间界面仍可操作。

分别测量冷/热加载、首次有效显示、交互延迟、峰值/保留内存和懒加载包大小。根据阶段 0 基线确定数值预算并持续执行，不能用组件宣传替代性能证据。验证键盘与辅助访问、窄屏，以及真实形态数据下 Light、Dark、Paper 自动截图。

阶段 1 已通过解析/模型和后端准入定向测试、仓库 typecheck、lint、生产构建，以及三 Sheet、1.2 万数据行工作簿的 Playwright 交互覆盖；Light、Dark、Paper 截图也已人工检查。上面的后续阶段完整矩阵要等对应能力实现后再执行。
