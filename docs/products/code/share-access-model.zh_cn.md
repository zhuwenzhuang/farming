# 分享访问模型

> English version: [share-access-model.md](./share-access-model.md)

本文定义 Farming Code 分享功能的鉴权与交互契约。

## 产品契约

分享面板有意提供不同权限的能力：

| 当前访问者 | 点击后复制的链接 | 二维码 | 俳句口令 |
| --- | --- | --- | --- |
| 拥有者 | 只读 | 完整控制 | 完整控制 |
| 只读访问者 | 只读 | 只读 | 不返回、不展示 |

二维码正下方必须使用浅色文字直接说明该二维码的权限和有效期。点击后的复制提示必须明确
说明“当前页面只读链接已复制，只能查看，不能修改，并随倒计时过期”。拥有者的俳句口令
区域是可点击的完整控制链接复制按钮，并保留按口令分段换行的展示；它需要单独标明会授予
完整控制权限，持续到实例口令变更，并不受二维码倒计时约束。

分享依赖 Token 鉴权。关闭鉴权时必须拒绝生成分享结果，因为接收者可以绕过受限链接，
直接打开未受保护的实例。

## 权威状态

后端为每个已鉴权的 HTTP 请求和 WebSocket 连接分配唯一访问模式：

- `owner`：实例拥有者凭证，允许读取和修改。
- `read-only`：签名能力，允许观察和继续创建只读分享，其他修改必须被拒绝。
- `none`：没有有效凭证，拒绝访问。

前端负责呈现权限差异，但永远不是权限边界。只读访问进入工作区后，即使关闭分享面板，
页面仍持续显示工作区级只读标识。

## 创建分享

拥有者创建分享时，后端生成：

- 一个用于自动复制长链接的签名只读能力；
- 一个携带拥有者凭证的一次性二维码票据；
- 用于显式完整控制访问的拥有者俳句口令。

只读访问者可以继续分享，但响应中只能包含：

- 一个用于自动复制长链接的签名只读能力；
- 一个携带同一只读能力的一次性二维码票据。

二次分享响应不得包含拥有者俳句或任何拥有者凭证。新分享的过期时间不得超过父级只读
能力，因此不能通过连续转分享延长访问期限。

分享票据和新签发只读能力的最长有效期为五分钟。票据只能兑换一次；已有能力仍按各自原定
时间过期。拥有者俳句是实例主凭证，会持续有效到口令被修改或轮换。

## 兑换分享

兑换二维码短链接时会消费票据，并把票据中原样保存的凭证写入 HTTP-only Cookie。
因此，拥有者生成的二维码授予完整控制；只读访问者生成的二维码仍然只读。

点击后复制的长链接始终携带只读查询能力。首次打开时，后端先把能力写入 HTTP-only
Cookie，再从 URL 中移除，然后才加载应用，从而减少地址栏、历史记录和 Referrer 泄露。

Chat 回复操作区和文件查看页提供同一只读长链接的直接复制入口。Chat 入口固化被选回合的
持久 Turn 标识，而不是周边 viewport 位置；文件入口固化当前文件标识、Editor 或 Diff 视图，
以及当前阅读行列。直接链接与共享后端响应一起创建二维码票据；由于直接入口不展示该票据，
客户端在复制长链接后会撤销它。

打开带上下文的链接时，先解析精确位置，再执行有界回退。Chat 在目标 Turn 可能存在时向前加载历史分页，
若仍不可用则回退到 Chat 最新位置。文件位置会被限制在当前文件边界内。如果在有界 Project 清单对齐后
文件仍不可用，Farming 会打开最近的可用父目录。如果 Agent 或 Project 本身无法解析，Farming 保留默认
工作区并报告定位失败。位置回退绝不改变链接的只读权限。

拥有者启动 URL 可以携带实例 Token，以便入口资源完成加载。应用加载完成且后续访问已由
HTTP-only Cookie 持有后，前端会从可见 URL 中移除该 Token，同时保留其他查询状态和片段。

只有仍然有效的能力才能建立新的 HTTP 请求和 WebSocket 连接；已经建立的 WebSocket
连接在断开前保持其准入结果。

## 只读强制执行

`read-only` HTTP 访问允许 `GET`、`HEAD` 和 `OPTIONS`。唯一的修改例外是创建或撤销分享票据，
并且只读调用者创建时只能生成只读能力。其他方法会在进入路由处理器前返回 `403`。

主 WebSocket 只允许协议协商、健康检查、状态刷新、查看焦点切换和文件监视订阅。
启动 Agent、终端或 Chat 输入、权限响应、中断、缩放、清屏、归档和重启消息都会在进入
生命周期或会话所有者之前被拒绝。

前端在 WebSocket 握手确认访问模式前暂存普通客户端消息。拥有者握手成功后继续发送；只读
握手只发送查看白名单内的消息。终端为了适配视口自动产生的 `resize-agent` 在只读页面中静默
跳过，避免首次打开时显示非用户操作造成的权限错误；后端仍保持拒绝该消息的安全边界。

Browser Viewer 可以接收画面，但其输入和缩放消息会被忽略。Computer Viewer 使用双向
RFB 传输，当前无法提供可由服务端验证的只读边界，因此只读分享会拒绝该连接。

## 失败与恢复

- 无效、被篡改或已过期的能力按普通鉴权失败处理，也不能建立新的 WebSocket 连接。
- 只读修改请求明确返回 `403` 或 WebSocket 错误，后端不会重放。
- 关闭鉴权时明确拒绝创建分享。
- 二次分享失败时，不得回退成拥有者权限，也不得延长有效期。

## 验收标准

- 点击后自动复制的 URL 始终只读。
- Chat 和文件的上下文复制入口分别携带选定 Turn 或当前文件阅读位置，并明确提示只读链接已复制。
- 乱序返回的旧直接分享请求不得覆盖较新分享操作的剪贴板结果。
- 拥有者二维码和俳句口令保持完整控制，并明确标注。
- 只读访问者可以继续分享，但只能拿到只读 URL 和只读二维码，拿不到拥有者俳句或主 Token。
- 二次分享永远不超过父级能力的有效期。
- 使用只读能力直接调用 HTTP 或 WebSocket 修改入口时，不会对工作区、Agent、终端、配置、
  Browser 或 Computer 产生副作用。
- 拥有者的 HTTP 和 WebSocket 行为保持不变。
- 只读接收者仍能获得最新状态、文件监视更新、终端输出、对话记录和 Browser 画面。
