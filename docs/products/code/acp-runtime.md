# ACP Backend Runtime

> Chinese version: [acp-runtime.zh_cn.md](./acp-runtime.zh_cn.md)

Farming has an Agent Client Protocol runtime for Codex, Claude Code, OpenCode, and Qoder. Backend lifecycle and frontend presentation remain intentionally separate: the backend owns the Agent process, ACP session lifecycle, normalized state, and control APIs, while `src/components/code/acp/` owns ACP-only Chat behavior.

## Provider Connections

- Codex uses the pinned `@agentclientprotocol/codex-acp` adapter. A version-locked `patch-package` delta adds the negotiated `_codex/session/steer` extension with `turn/steer` forwarding, plus standard ACP `session/fork` backed by Codex `thread/fork`. Packaging fails if the pinned upstream package no longer matches the reviewed patch, then copies the exact patched adapter into the release under a locked SHA-256. Installed packages launch that immutable artifact and never rely on post-install mutation. Standalone CLI builds bundle it behind an internal process entry and must complete an ACP `initialize` handshake as part of native artifact smoke.
- Claude Code uses the pinned `@agentclientprotocol/claude-agent-acp` adapter.
- OpenCode uses its native `opencode acp --cwd <workspace>` command.
- Qoder uses its native `qodercli --acp` command. Qoder can emit the tail of a loaded history after `session/load` returns, so Farming waits for the replay stream to settle before exposing the restored session.
- All four communicate through the official `@agentclientprotocol/sdk` over newline-delimited JSON-RPC on subprocess stdio.

Adapter package versions are exact production dependencies. Farming does not run `npx latest` during Agent startup.

## Session Semantics

A live Codex adapter may advertise the versioned `_codex/session/steer` extension in addition to standard ACP capabilities. Farming enables it only from the initialize response and never from the provider name alone.

The runtime supports ACP `initialize`, `authenticate`, `logout`, `session/new`, `session/load`, `session/resume`, `session/list`, `session/fork`, `session/delete`, `session/close`, `session/set_mode`, `session/set_config_option`, `session/prompt`, and `session/cancel` when the Agent advertises the corresponding capability. New, load, resume, fork, and list requests preserve standard additional-directory scope; new, load, resume, and fork also preserve client-provided command or HTTP MCP server definitions at the adapter boundary. The unified WebSocket and control-HTTP Agent start interfaces accept those two standard session inputs, and a Chat/Terminal or permission restart carries them into the replacement ACP binding. The inputs are kept out of browser-facing Agent state and stored only in the private `0600` Farming session record so crash recovery can reconnect the same scope. Farming does not invent support for an unadvertised optional method.

When a live idle ACP binding advertises `session/fork`, the Fork action below the latest completed Chat answer fences the exact transcript revision and creates a distinct provider session in a new ACP Chat Agent in the same workspace. Most adapters fork from the source binding and let the new Agent load the returned session. Claude's fork exists only in the adapter process that creates it until the child completes its first prompt, so Farming instead starts the isolated child adapter, loads the fenced source there, forks in that same process, closes its temporary source session, and keeps the returned child live on that process. The exact source binding checkpoint—including bounded child transcripts and committed patch decisions—crosses this transition only as private in-memory startup state and is installed under the returned child identity after the provider fork succeeds; returned child mode, configuration, and command state then override the source values. This keeps the child UI and tool details on the clicked revision even when provider history replay lags. A child Agent whose persisted parent and provider-fork identities are both present renders a presentation-only `Forked from agent` divider above its Chat transcript; the divider is not inserted into the ACP entry stream. A process loss before the first child prompt fails visibly instead of silently creating a different fork; after the first prompt, normal `session/load` recovery applies. Startup rollback stops the child process before asking the still-live source binding to delete the exact fork identity. If that provider deletion fails, the failure returns the exact retained identity for operator cleanup. This action does not launch a Terminal or infer support from browser-side provider lists. The Agent context-menu Fork actions remain the explicit provider-CLI paths for same-worktree Terminal or new-worktree workflows.

The initialized client advertises the ACP file-system, terminal, terminal-authentication, boolean configuration, plan, form-elicitation, URL-elicitation, and terminal-output capabilities that Farming actually implements. Corresponding Agent requests are served by bounded workspace file access, managed client terminals, explicit permission cards, authentication UI, and elicitation forms. Elicitations without a `sessionId` remain request-scoped, including authentication-time requests before a session exists; session- and child-session-scoped requests keep their own origin. Session updates—including text, reasoning, plans, tool calls, diffs, terminals, resource links, images, audio, usage, commands, configuration, and child-session metadata—reduce into the same ordered session model. Protocol features are enabled from the live initialize/session responses, not from provider-name guesses.

Chat preserves these typed ACP parts instead of inferring them from assistant prose. Markdown remains a typed text part; its explicit file links and qualified inline-code references reuse the terminal's bounded file-location grammar, then pass through workspace/global-file normalization before opening. Tool-call `locations` remain bounded structured path/range records and render as workspace file anchors; they are never flattened into a `Locations` prose section and parsed back. HTTP(S) resource links remain external links, while local `file://` and workspace resource links open through the same workspace boundary. Images, audio, resources, tool calls, patches, plans, terminals, and collaboration metadata continue through their structured renderers rather than a competing text recognizer.

An existing history session keeps a Farming-owned reducer checkpoint under the config directory. Its identity includes provider, Agent Home, provider session id, and workspace; writes are compressed, file-and-directory synced, and atomically replaced. The checkpoint carries the primary reducer, child reducers, patch-decision fences, and the previous browser revision. Before a prompt Farming durably marks it dirty. ACP currently exposes neither a provider-owned opaque revision nor a conditional `session/resume`, so a timestamp comparison cannot prove that local state is exact. Farming therefore fails closed to `session/load`; the checkpoint is used only to preserve the revision/reset fence, preventing a browser from retaining entries from a discarded reducer. Bare resume and uncertain prompt failures remain dirty and can never create an exact recovery checkpoint. Local resume without replay may be enabled only if a future provider exposes a workspace-bound freshness token and a conditional-resume proof.

This distinction matters because ACP load replays the complete conversation through `session/update` notifications before the load request returns, while resume restores context without returning old messages. Farming registers the session reducer before sending load so early replay notifications cannot be lost. Replay updates reduce into the ordered stream without broadcasting one browser invalidation per entry; clients receive one settled snapshot after restoration. A reader whose `sinceRevision` is ahead of the rebuilt reducer, or at/before its reset fence, receives a full replacement rather than an empty delta.

History-origin Chat keeps a stable syncing surface until its first non-empty settled page arrives. An empty connecting or early-idle snapshot must not replace an already visible transcript, and recoverable main-page rows are materialized before their large transcript bindings are prepared.

History discovery keeps the full supported metadata window in the backend cache and sends Farming Code bounded cursor pages. The page status distinguishes locally loaded History rows from the backend's total discovered provider sessions. Scrolling near the bottom of the project list loads the next page; project-level “Show more” still controls only local presentation within the pages already loaded. Agent Search queries that full backend window instead of filtering only the pages already loaded in the browser. Matching is case-insensitive and covers visible Agent or session titles, Project names and paths, and exact or partial Resume IDs; provider metadata and transcript content are not searched. Backend-returned session identities are authoritative search matches so the scope can expand without being discarded by a second frontend title filter. History resume resolves provider metadata across the full backend window so an older session keeps its original workspace when it moves between Terminal and Chat. Claude and Qoder discovery treat only project-level transcript files as sessions; nested child-agent transcripts inherit the parent identity and remain replay details rather than duplicate History rows. Each provider-session row shows a compact Resume ID, with the complete identifier available on hover, so equal titles remain distinguishable without changing the resume identity passed to the backend.

ACP updates are retained in bounded, size-limited diagnostic form and reduced into one provider-neutral ordered entry stream. History replay and live updates use the same reducer. Adjacent compatible message chunks merge by message id, while Codex phase metadata remains attached and prevents commentary from merging across a `final_answer` boundary. A Codex steer message remains inside its owning root user turn and never becomes a transcript-slice turn boundary. Tool updates mutate the original tool-call entry by id, and plan entries update in place. Session metadata such as usage, modes, commands, and config options stays outside the conversation stream. Runtime notifications carry only lightweight invalidation metadata: live transcript revisions use the coalesced per-Agent `acp-session-revision` browser message instead of broadcasting the full workspace state, while initial hydration and reconnect still receive the authoritative full state. Transcript reads use a monotonic revision and replace only the affected entry suffix. The transcript page carries a compact ordered tool envelope with bounded inline detail, patch statistics, media references, and terminal ids; exact raw input/output and patches remain in the backend checkpoint and load through the tool-detail endpoint. A new reader explicitly negotiates `external-v1` transcript media so rolling upgrades leave old readers on inline media; negotiated media URLs use immutable content hashes rather than mutable array indexes and fail closed if that exact content is no longer authoritative. Only transport failures of the read-only transcript GET receive bounded automatic retries; view replacement cancels them, and prompt, terminal input, and every other write path remain outside this retry behavior.

## Farming Code Presentation

When negotiated, Codex input submitted during an active turn is sent as steer and remains inside that turn at its ordered transcript position, including native media blocks. Providers without the extension keep the visible queued-follow-up presentation.

Short Chat transcripts start at the top of the reading surface instead of being pushed against the bottom Composer. Long histories still follow the latest content while the reader remains at the tail, preserve an explicit earlier reading position, and expose the jump-to-latest control when detached.

Farming Code separates the logical opened-Agent list from a bounded frontend working set. Chat DOM and pooled xterm instances share one twenty-Agent LRU: activating an Agent makes it most recent, the active Agent is protected, and a twenty-first retained view evicts only the least-recent inactive browser view. Eviction never stops the backend ACP or PTY process. Switching among retained Agent rows hides the previous Chat without unmounting its transcript, disclosure state, or exact scroll position; Search, History, and file-editor views also hide the Agent workspace without touching LRU recency. An inactive retained Chat performs no transcript request. When selected again, it paints the retained view first and requests only the changed ACP suffix. An evicted Chat performs a full authoritative transcript load; an evicted Terminal recreates its xterm from the authoritative session-view checkpoint.

When collaboration details are folded, the top-level child Agents use compact inline buttons and wrap only when the Turn runs out of horizontal space. Selecting one expands that Agent to the full bounded detail width in place; nested children remain inside that expanded parent.

ACP uses its own composer, draft namespace, permission cards, session controls, dynamic command menu, and transcript adapter under `src/components/code/acp/`. Terminal continues to use `CodeComposer` and the PTY input path without ACP branches. ACP client terminals use an embedded xterm view for real keystrokes, selection, output, resize, and stop behavior; this component is not shared with the Terminal page.

The composer renders the modes, model, reasoning level, boolean options, usage, and available commands negotiated from the live ACP session. The existing Chat UI design is preserved: an adapter projects the canonical ordered entries into its user/result/process view model without changing the composer or transcript component hierarchy. A Codex message marked with `final_answer` is the authoritative visible result even if history replay later emits a reasoning entry; providers without an equivalent marker retain the compatible tail heuristic. Earlier commentary, thoughts, tools, and plans stay inside the existing reversible process disclosure. During an active turn, that disclosure stays collapsed by default but presents a compact tool trail: at most four individual non-failed actions remain visible, earlier actions collapse into a count, intermediate failures stay off the default reading surface, each visible tool keeps its own reversible detail disclosure, and the latest non-empty commentary becomes a bounded plain-text progress preview. Rendering the preview as text, rather than clipping rich Markdown, ensures hidden links cannot remain in the keyboard focus order; the complete Markdown stays available in Process. Reasoning, older commentary, and failed-tool evidence remain available only through the complete Process disclosure instead of accumulating on the default reading surface. Codex collaboration and subagent-activity metadata stay in the bounded tool envelope and project into the Process area of the exact parent Turn that contains those ordered entries. Each child Agent remains directly discoverable as one collapsed card even while the rest of Process is folded; its primary label is the task and its secondary label is the authoritative Codex identity. Missing ancestors may be included to preserve the real thread hierarchy, but a latest snapshot alone never assigns an eventless descendant to an older Turn because it does not prove that descendant's birth Turn. Expanding a card reveals its ordered lifecycle milestones, coalescing only consecutive equivalent updates; selecting a milestone reveals the exact ordered parent-tool evidence inside that same Turn. This projection does not invent a writable peer chat when the adapter has not provided an independent ACP child Session. Formal ACP child Sessions continue to use their nested transcript, focused dialog, and independent Stop control. A running terminal tool auto-expands only after a 500 ms grace period and only after Farming observes real output; fast commands and newly reported failures stay collapsed, while a terminal already opened for live output remains open if it fails. Its expanded view owns one command header and no second protocol-status label. A live interactive terminal uses a dark, content-sized four-to-eight-row xterm; when its tool enters a terminal state, Farming immediately disables stale input and Stop controls, then refreshes the authoritative terminal detail before replacing that xterm with compact read-only output and exact exit metadata. If bounded refresh cannot observe the terminal outcome, the read-only evidence shows an explicit synchronization failure with a Retry action instead of remaining in a false running state. Raw output that contains only the same exit code or signal is omitted from the visual projection but remains available through exact copied tool detail. When the compact tool trail already makes current work visible, the generic waiting placeholder is suppressed and the bottom duration indicator remains the single live status. Later stream updates never overwrite an explicit per-tool or per-child disclosure choice, and opening the complete Process view keeps any already-open item reachable by opening its containing group. The top-level Process still folds when the Turn completes so the final result regains focus, while an explicitly opened child card remains open because it is a separate disclosure. Opening Process reveals the complete ACP-ordered evidence and only then auto-opens the latest streaming thought. Its summary and compact action rows stay on one ellipsized line, with the compact action row owning the localized provider-reported tool title and no duplicate protocol-status badge. Successful generated image or audio outputs are promoted from their tool entry to a default-visible result-media surface while their tool metadata remains reversible under the process disclosure. The version-locked Codex adapter converts `thread/read` image and local-image inputs into standard ACP image or resource-link blocks; Farming consumes those blocks directly and never reconstructs history images from rollout JSONL, while injected attachment paths and wrapper text stay out of the visible request. Mermaid code fences decode Markdown character references once before parsing, allowing protocol text such as `&lt;id&gt;` to render as the intended diagram source. A tool update containing ACP `diff` blocks is projected as a file-change result card without flattening away the protocol data: the collapsed card shows deduplicated paths and line totals, its first expansion lists the affected files, and each file can reveal the exact historical ACP patch on demand. The separate Review action captures only paths inside the Agent workspace instead of opening an unrelated whole-workspace change set; out-of-workspace patches remain inspectable inline. Tool details, raw input/output, compact contextual patches, terminals, and locations remain expandable. ACP child sessions remain nested under their parent tool entry; the preview can be opened in a focused dialog, a running child can be stopped independently, and child permissions or elicitation forms are answered through the parent Chat controls. Large details are omitted from the transcript page and fetched by tool-call id only when the user expands or copies that item. The ACP Chat view initially projects 20 turns and loads older turns in 20-turn pages as the user scrolls upward. ACP transcript refreshes follow session update signals from the shared state websocket and request only the changed suffix. Internal Codex context and heartbeat activity is hidden as a segment, while a visible automation notification remains an assistant message.

The current transcript presentation supersedes the compact-trail defaults described above. The authoritative Session plan is one view-attached translucent driver that updates in place and never appears as a chronological entry. Full commentary and admitted steer messages remain in ACP order and divide evidence into segments. Each segment renders one collapsed summary row for all of its reasoning and tool activity; opening that row still leaves every child reasoning/tool detail collapsed until the user opens it. ACP Process is visible by default, and neither reasoning nor terminal detail auto-expands. If terminal outcome synchronization fails, the expanded row shows only the bounded retry notice; raw tool input stays out of that error surface while remaining available through explicit copy/detail paths.

Codex collaboration activity and child lifecycle are separate protocol facts. `collabAgentToolCall` and `subAgentActivity` describe what the parent attempted; an activity named `interrupted` is a pause request, not proof that the child ended in that state. After `session/load` or `session/resume`, the pinned Codex adapter therefore returns the parent transcript immediately and reconciles spawned descendants asynchronously with app-server `thread/list(ancestorThreadId)` plus bounded `thread/read(includeTurns)`. It emits a versioned full snapshot and ordered live deltas through Codex-specific `session_info_update` metadata. The Farming reducer checkpoints that state and advances the ordinary transcript revision, so retained and restored views converge without polling. UI lifecycle labels come only from the child thread's current status or authoritative final `turn/completed`; a completed turn is shown as completed, an interrupted turn as resumable paused, and activity records remain reversible evidence inside that child's own disclosure. Spawn-edge parent ids preserve nested child ownership. Review and Guardian threads that Codex intentionally excludes from the spawned-descendant lifecycle are not assigned an invented terminal state.

The ACP composer preserves the ordinary message-box behavior that does not depend on PTY input: drafts and history navigation, Enter/Shift+Enter and IME handling, file selection, pasted media previews, attachment removal, voice dictation, provider commands and skills, Goal/Plan request modes, queued follow-ups, interrupt, context-window usage when exact Codex data is available, and provider permission/configuration controls. The `+` menu contains attachment, Goal, and Plan actions, plus Sign out only when the Agent advertises ACP logout; provider commands remain searchable through `/`, while `$` opens the provider-advertised skill subset. Uploaded images or audio travel as native ACP content blocks only when the live Agent advertises that prompt capability. Otherwise Farming converts the upload into the same readable local-path context used by the existing text fallback, so an unsupported media type cannot be silently dropped. Text files remain embedded in the message.

Structured Composer submission is request-idempotent. Both browser skins retain the same request id across a disconnect or explicit UNKNOWN response; Farming Code does the same after its bounded admission timeout. An ordinary Prompt sent while no turn is active goes directly through this admission path and does not first appear in the visible queued-message strip. The exact draft remains editable until a definite admission ACK; only that matching draft is then cleared, and a late ACK cannot clear newer input or steal focus. Before calling ACP, Farming persists a bounded sidecar record containing the request id and content hash. The provider's `onSubmitted` callback is the admission linearization point: Farming persists `accepted` before acknowledging the browser. A repeated id with the same hash joins or returns the committed result; a different hash is rejected. If provider ownership is possible but the accepted state cannot be proved, the record becomes UNKNOWN and Farming never automatically replays the Prompt or Steer.

For Codex, Farming maps the selected launch profile into the ACP adapter's `CODEX_CONFIG` and `INITIAL_AGENT_MODE`. Switching between Terminal and Chat therefore preserves model, reasoning effort, service tier, and the matching initial permission mode instead of silently reverting to adapter defaults.

Changing a Codex model in a live ACP session first lets the adapter choose a compatible reasoning fallback, then refreshes the adapter's model catalog and reapplies the standard config option. This keeps model-specific capabilities such as Fast mode aligned with the refreshed model metadata even when a long-lived session was opened before the provider or proxy updated that metadata. Related model and reasoning changes can be applied as one profile update. For model families that expose Sol, Terra, and Luna variants, the composer presents one continuous draggable surface for variant and ordinary reasoning selection, a click-operated red Ultra rocker that automatically pulls down when enabled, and a separate `Fast OFF` / `Fast ON` speed button. **Advanced** morphs back to the exact step-by-step reasoning, model, and speed controls without resetting the selected profile. ACP configuration writes are serialized per live session for every provider, repeat requests for an already-selected target are idempotent, and the returned config options must confirm the requested value. The browser applies one optimistic update while that transaction is pending and ignores older refreshes, then reconciles with the confirmed session snapshot or rolls back on failure. The Ultra and Fast positions remain stable while capabilities refresh; a control that the live session does not advertise stays visible, grey, and disabled instead of making the menu jump.

The same controls also update an idle native Codex Terminal instead of changing only its next launch profile. Farming applies the change through the CLI's interactive `/model` selection and idempotent `/fast on` or `/fast off` command. It waits for the actual model and reasoning menus, selects the advertised entries, and confirms the resulting footer before the Composer can submit another message; it does not guess at remote-render timing. Fast is different: it is one non-interactive command, so later Terminal input is released as soon as that complete command is accepted by the PTY while confirmation continues outside the input queue. While a Terminal turn is active these controls stay disabled, because ordinary TUI input can be queued as task input instead of taking effect as an immediate configuration command. New Terminals receive an explicit `service_tier="default"` when Standard is selected, so a Fast value in the user's Codex config cannot make the runtime disagree with Farming's control. The launch profile is persisted after the live Terminal confirms the change, keeping a restarted Agent consistent without showing an unverified selection. These PTY commands are never injected into ACP, legacy JSON, shell, Claude, OpenCode, Qoder, or other non-Codex Terminal sessions.

ACP boundaries remain explicit:

- The active binding object is ACP's in-process generation fence. `agentId` routes the live Farming runtime and the provider `sessionId` scopes protocol messages; every asynchronous completion and Agent-to-client request must still match the current open binding before it can reduce state, emit an update, or schedule a checkpoint. A base prompt reserves admission synchronously before the dirty-checkpoint write, so a second prompt cannot pass the same idle state. Cancellation during that admission window revokes the prompt before it reaches the provider. Detached or closed bindings cancel late permission/input requests and cannot become usable again.
- Base ACP has no concurrent prompt/steer operation. Every submitted Chat message first enters one per-Agent admission sequence and rechecks the exact current binding and Turn when it reaches the front. When the live Codex adapter advertises Farming's versioned steer extension, an active-Turn message is serialized with that Turn's other controls. A definite turn-end or non-steerable-turn rejection keeps the message in its original admission position, waits for that exact Turn to settle, and then starts the next prompt; a later message cannot overtake it, and an ambiguous transport failure is never replayed. A message admitted while cancellation is in progress likewise waits for the cancellation's proven terminal result. Interrupt targets the exact current Turn and may preempt messages that have not reached the provider. Providers without the capability retain the visible, discardable queued-follow-up behavior.
- Each observed child Session has a binding-local control owner with its own generation and single-flight cancellation. Duplicate child stops join one provider request, parent cancellation also cancels every child still proven active, and an old binding's completion cannot mutate a replacement binding. Late child transcript notifications may still be reduced as evidence, but cannot reopen a child whose cancellation has already reached a terminal state.
- Goal and Plan are explicit composer request modes. ACP Chat sends Goal as a portable prompt until a provider negotiates a native protocol capability. Terminal uses each verified provider path: Claude receives `/goal <condition>`, Qoder receives `/goal set <condition>`, while OpenCode receives the portable Goal prompt because its TUI has no native Goal lifecycle. Provider session modes, model, reasoning, speed, and other runtime settings are still shown only when the Agent advertises the corresponding ACP mode or config option.
- A context-window percentage needs both used and maximum tokens. Codex uses its exact provider-session token event when available; ACP providers that expose only cumulative usage get a token count instead.
- The composer accepts images and audio, but native blocks are capability-negotiated independently. Incoming embedded resources and resource links are rendered, while arbitrary outbound resource-link construction is not exposed as a composer control.
- Editing an old prompt with a repository checkpoint and truncating later turns is not part of base ACP. Farming does not present that optional client-side capability as protocol support.

## Permissions And Failure Behavior

`full` permission mode selects an advertised allow option automatically. `ask` selects an advertised reject option. The normal approval mode exposes the full pending ACP permission request and waits for an explicit response through the backend API.

ACP startup, initialization, history restoration, prompt, protocol, and adapter-exit failures are reported as runtime errors. Bounded control requests fail with actionable timeouts; a normal long-running prompt is not assigned an artificial wall-clock timeout. Farming does not silently replace a requested ACP Agent with Terminal or JSON CLI mode. Chat / Terminal switching is rejected while a turn is active. A new Terminal with no user input may start a fresh ACP session when provider history has not been materialized yet; after Terminal input, the switch requires the saved session to remain discoverable. After the turn is idle, the switch stops the old process and starts the requested runtime; if that startup fails, Farming immediately resumes the same provider session in the original runtime and reports the failed switch.

## Backend API

- `GET /api/agents/:agentId/acp-session` returns the normalized session and negotiated capabilities. Add `?includeEntries=0` for the lightweight controls/usage snapshot. Add `?includeUpdates=1` only for protocol debugging when the bounded raw ACP update stream is required.
- `GET /api/agents/:agentId/acp-transcript?maxTurns=N` returns a sanitized view projection of the canonical entry stream for the existing Chat UI. Live readers add `sinceRevision=R` to receive only the affected suffix.
- `GET /api/agents/:agentId/acp-media/:entryId/:mediaId` serves one explicitly negotiated, authenticated, immutable transcript image or audio payload whose content hash still matches the authoritative entry.
- `GET /api/agents/:agentId/acp-tool-details/:toolCallId` loads expandable tool detail and exact structured ACP patches on demand.
- `GET /api/agents/:agentId/acp-sessions` calls ACP session listing for the live provider connection.
- `PATCH /api/agents/:agentId/acp-session` changes one negotiated mode/config option, or accepts `configOptions` for an atomic model-and-reasoning profile change.
- `POST /api/agents/:agentId/acp-permission` answers a pending permission request.
- `POST /api/agents/:agentId/acp-elicitation` answers a pending form or URL elicitation.
- `POST /api/agents/:agentId/acp-session/authenticate` starts a negotiated authentication method, including managed terminal authentication.
- `POST /api/agents/:agentId/acp-session/logout` logs out only when the Agent advertises ACP logout.
- `POST /api/agents/:agentId/acp-session/fork` forks a session when advertised.
- `DELETE /api/agents/:agentId/acp-sessions/:sessionId` deletes a session when advertised.
- `POST /api/agents/:agentId/acp-session/close` closes the current session when advertised.
- `POST /api/agents/:agentId/acp-terminals/:terminalId/input|resize|kill` controls an ACP client terminal.
- `POST /api/agents/:agentId/acp-subagents/:sessionId/cancel` stops a known ACP child session without cancelling the parent session.
- WebSocket `start-agent` accepts `agentRuntimeMode: "acp"`, optional `acpHistoryMode: "load" | "resume"`, and standard `additionalDirectories` / `mcpServers` session inputs. `POST /api/control/agents` accepts the same ACP session inputs.
- WebSocket `acp-permission-response` answers the same permission flow without HTTP.

Farming Code's Chat control now selects ACP for Codex, Claude Code, and OpenCode. Switching between Chat and Terminal restarts the Agent runtime and resumes the same provider session; the replacement preserves an already-visible composer instead of unexpectedly applying the default collapsed-Terminal preference. Legacy JSON Chat sessions remain readable but are no longer the new Chat launch path.

Fresh OpenCode Terminals pre-create an exact provider session through one bounded ACP process before native Terminal launch. Fresh Codex Terminals launch immediately with a temporary correlation id and keep user-owned metadata on the stable Farming session record, including across native-host recovery. Farming promotes that temporary id only when Codex history contains one unclaimed Agent Home/canonical-workspace match with a trustworthy creation time inside the bounded launch window; the identity scan reads only rollout headers in the launch-date directories, and concurrent scans for the same Agent Home share one in-flight result. Ownership is rechecked at commit, and ambiguous or linked-worktree-only candidates remain unresolved. A confirmed provider id is attached to the same Farming record for later Chat/Terminal resume and Fork. Submitted Terminal input is fenced before awaiting its PTY response; after that fence, Chat, permission restart, and Fork require the exact provider id. A native-host runtime rotation also aborts and resumes the old host while such a used Terminal remains temporary, because relaunching `codex` would silently replace its conversation.

Terminal mode continues to use `NativeSessionEngine`. ACP is a structured runtime selected for a newly launched or restarted Agent; it does not duplicate a Terminal process.

## Verification

`backend/tests/test-acp-runtime.ts` runs an actual official-SDK client and a deterministic fake ACP subprocess. It verifies new sessions, full history replay during load, prompting, permission selection, stable tool updates, session listing, and the normalized session snapshot. `backend/tests/test-acp-checkpoint-store.ts` proves reducer round-trip, identity isolation, dirty fencing, and durable atomic replacement. `backend/tests/test-acp-checkpoint-recovery.ts` proves fail-closed cold/warm load, revision reset, complete child/patch-fence serialization, uncertain-failure fencing, bare-resume fencing, workspace validation, and Agent Home isolation.

`npm run test:performance:transcript` exercises a production-shaped 942-entry transcript with 498 tools and the observed large-media distribution, enforcing bounded response size and a material parse-time improvement. The ACP human-case browser suite verifies negotiated media delivery and bounded read-only transport recovery, while the shared Agent-view-cache and scaling suites cover retained/evicted Chat and Terminal views through fifty live Agents.
