## 产品目标

打开支持的文件后，立即提供有用的结构着色，自动发现语言项目和运行环境，
并提供运行与调试入口，不要求用户自行拼接 Shell 命令。
Python 是第一个完整实现；某个可选服务不可用，不应让整个语言支持失效。

免配置是默认验收路径：项目已有兼容环境时，打开文件后点击 Run 或 Debug 即可使用，
不要求选择解释器、创建运行配置、编写 JSON 或输入命令。发现环境后必须自动应用
推荐结果，不能只填充选择器。手动覆盖是可选项，不作为首次使用的必经步骤。
缺少 Farming 管理的分析/调试工具时，在对应生命周期契约内自动准备，展示进度，
不把安装步骤交给用户。

首个验收场景是嵌套作业目录中的 Python 包：解释器位于上层 `.venv`，
以模块方式运行，带命令行参数，能在循环内停住并单步调试。
发现项目与解释器不等于依赖已经齐备，也不保证程序执行成功。

## Zed 的行为与 Farming 的取舍

参考 Zed 提交 `bc6dd34d4c91632680df02355c2381c5f53ea73f`。
以下是行为分析，不表示 Farming 首期承诺完整复刻 Zed。

| 层次 | Zed 的行为 | Farming 设计 |
| --- | --- | --- |
| 语言识别 | 文件名、扩展名、shebang、语言配置 | 语言适配器贡献识别规则，保留编辑器手动覆盖 |
| 结构理解 | Tree-sitter 查询支持着色、大纲、缩进、括号、嵌入语言和运行位置 | 保留 Monaco，引入有资源上限的 Python 结构分析 Worker，支持后续语法扩展 |
| 语义服务 | LSP 提供诊断、导航、补全、重命名、代码操作及可选语义 token | 复用现有托管 LSP，首期聚焦阅读辅助与环境一致性 |
| Python 服务 | 默认 basedpyright 与 Ruff，分析与格式化分工 | 首期一个分析服务；格式化与编辑操作分别声明能力 |
| 环境 | 子项目级工具链、自动推荐、手动选择、远程主机发现 | 后端按 Config、工作区、语言、子项目管理选择 |
| 运行 | 结构查询识别入口和测试，任务解析参数与环境 | 同一结构化目标解析一次，供 Run 和 Debug 共用 |
| 调试 | 通用 DAP、语言调试适配器、上下文配置、集成终端、断点和变量 | 通用 DAP 会话服务与 Python debugpy 适配器，使用原生 PTY |
| REPL | Jupyter kernel 发现、行内输出、单元格、kernel 安装 | 后续独立能力，不作为 Run 或 Debug 的依赖 |

Zed 默认的 `semantic_tokens` 为 `off`，丰富的 Python 着色不能仅靠安装
Pyright 来复现。结构着色与语义分析有不同的状态归属、延迟和失败行为。

Zed 使用 Python Environment Tools 的 locator 发现环境，按项目距离、环境类型等
排序，选中的工具链供语言服务、任务与新终端使用。项目清单搜索可能偏向带锁文件的
上层目录；默认模块任务也会从相对路径推导模块名。这些行为并不能保证任意嵌套项目
或 `src` 布局都会正确运行。

REPL 选择器推荐与当前工具链匹配的环境。缺少 `ipykernel` 的环境仍能运行脚本、
使用 debugpy。Zed 允许选中缺少 kernel 的环境后安装 ipykernel；Farming 首期
不需要 kernel，也不需要因此修改项目依赖。

参考证据：Zed 的[工具链](https://github.com/zed-industries/zed/blob/bc6dd34d4c91632680df02355c2381c5f53ea73f/docs/src/toolchains.md)、
[Python 适配器](https://github.com/zed-industries/zed/blob/bc6dd34d4c91632680df02355c2381c5f53ea73f/crates/languages/src/python.rs)、
[Python 语法查询](https://github.com/zed-industries/zed/tree/bc6dd34d4c91632680df02355c2381c5f53ea73f/crates/grammars/src/python)、
[默认设置](https://github.com/zed-industries/zed/blob/bc6dd34d4c91632680df02355c2381c5f53ea73f/assets/settings/default.json)、
[调试器](https://github.com/zed-industries/zed/blob/bc6dd34d4c91632680df02355c2381c5f53ea73f/docs/src/debugger.md)与
[REPL](https://github.com/zed-industries/zed/blob/bc6dd34d4c91632680df02355c2381c5f53ea73f/docs/src/repl.md)。
Zed 主要采用 GPL-3.0-or-later，部分组件另有标注。本设计借鉴行为与标准协议，
不复制其实现或查询文件；引入语法和运行时依赖时单独核对许可证。

## 打开文件后的体验

1. 立即显示文件与本地语法着色。结构解析与有时限的项目、环境发现并行进行。
2. 显示紧凑环境控件，例如 `Python 3.12 · .venv`。选择器展示版本、类型、路径、
   推荐理由与不可用原因；打开时重新读取当前状态，刷新和手动选择是可选操作。
   自动应用最合适的兼容环境；发现多个解释器本身不应迫使用户选择。
3. 编辑器顶部提供 Run 和 Debug。识别到 `__main__` 时，在 gutter 中增加入口，
   主操作直接运行/调试自动推导的目标，目标选项放在次级入口，不先弹配置框。
   运行入口和断点使用独立点击区域。
4. 启动前保存受影响语言项目中已修改的打开文件。保存冲突或准备期间出现新编辑时，
   阻止本次启动。操作显示“保存并运行/调试”，不让用户无意中运行旧文件。
5. 打开编辑器工具面板，显示任务终端；调试时增加继续/暂停、逐过程、单步进入、
   单步跳出、停止、调用栈和按需展开的变量。断点命中后显示源码和当前执行行。
6. 随时可查看目标、环境、参数和工作目录。结束后保留退出状态与终端输出；
   再次运行使用新的执行身份。

工具面板复用公共布局、菜单、焦点仲裁、主题以及禁用、加载、错误状态。
窄屏时移到编辑器下方，与语言导航面板和 Agent 侧栏协同，一次展示一个主要工具内容，
不堆叠多个完整面板。关闭面板或切换文件只改变展示，不改变进程生命周期。
快捷键限定在编辑器/调试界面，遵守 Monaco、终端输入、IME 与共享 Escape 规则。

## 架构与归属

```text
Monaco 模型 ── 结构分析 Worker ── 着色 / 可运行位置
     │
     └── 编辑器操作与工具面板
                  │ 鉴权、版本化协议
                  ▼
             语言工具协调层
         项目上下文 / 环境 / 目标解析
             │           │           │
         现有 LSP     执行服务     DAP 服务
             │           │           │
          语言服务       └── 原生 PTY ──┘
                                  调试适配器
```

语言工具作为内置 Extension 能力。后端负责发现、环境选择、启动准入、会话生命周期
和能力状态；浏览器负责未保存模型、结构解析投影和展示。浏览器发现的运行位置只是
提示，执行前由后端验证已保存目标。LSP 与 DAP 分别管理协议和进程。

最小契约包含四类：

- **语言上下文：**语言、授权工作区根、子项目根、清单证据、环境选择版本、能力状态。
- **环境：**稳定选择身份、启动路径、环境前缀、版本、类型、发现来源、兼容性与探测状态。
- **目标：**文件/模块/测试身份、源码版本、参数、工作目录、环境引用、明确的启动策略。
- **执行：**精确资源所有者、会话 id 与 epoch、不可变解析目标、终端 id、状态版本、
  结果以及可选的调试器状态。

适配器贡献语言识别、项目/环境发现、目标解析、分析配置和调试启动转换。
能力可选且有类型边界，区分不支持、准备中、可用与失败。通用 UI 和生命周期代码
不写 Python 名称分支，也不接受浏览器任意传入可执行程序或 DAP 请求。
这是内部适配边界，不新增公共插件 SDK。

复用现有 LSP manager 与运行时准备机制，协调层不再实现第二套 LSP manager。
Python 评估 basedpyright 作为托管默认值，包括实际 semantic-token 能力；
保留显式配置的现有服务，展示能力差异，不隐式运行多个竞争的分析服务。
Ruff 格式化、重构、补全和草稿实时 LSP 同步作为后续能力，不作为本流程前置条件。

## 项目与环境解析

授权工作区、语言项目根、环境前缀、模块导入根和运行工作目录分别记录。
只在授权工作区内向上查找，读取清单元数据，不执行项目脚本。
全局只读文件浏览器不会因为打开文件而获得执行权限。

Python 首期发现相关上层目录中的 `.venv`/`venv`、显式选择、继承环境候选和主机
Python，结合版本约束与 workspace 成员关系排序。uv、Poetry、Conda 等通过有界
locator 扩展；locator 不可用要明确报告，不能当作“不存在环境”的证据。
不递归扫描用户主目录，也不在发现阶段创建环境。

选择优先级：仍有效的手动选择；声明项目/workspace 关联的兼容环境；最近的兼容上层
环境；兼容主机候选。确定性排序不掩盖多个同样合理的项目环境。
按 Config + root + language + subproject 保存选择。手动选择的环境消失时，
标记不可用，不能悄悄用另一个解释器启动。

区分自动选择与用户覆盖的来源。刷新可以重新计算自动推荐，但不能覆盖用户选择。
展示备选项与当前推荐理由，不打断正常执行。只有证据冲突导致无法解析有效目标，
或缺少没有默认值的用户特定信息时，才请求用户补充。

候选探测限制并发、输出大小与耗时。venv 解释器可能链接到共享的基础二进制，
必须保留调用路径与环境前缀；只按可执行文件 realpath 去重会误合并不同虚拟环境。
工作区外的工具路径单独校验，不能与项目源码访问授权混为一谈。

选定环境用于语言分析和新执行。切换时使受影响的分析绑定和目标解析失效，
用 generation 拦截旧结果。运行中的会话保留启动时的环境快照。
不兼容解释器仍可列出，并精确说明哪项能力不支持；不能仅凭版本标签推断 debugpy
一定兼容。

## Python 目标与依赖准备

结合语法、项目清单和包结构识别独立脚本与模块入口，明确支持常规包与 `src` 布局。
确定导入根时采用模块方式，确认独立脚本时采用文件方式。先充分使用支持的项目清单
和包约定，仍无法解析时才针对缺失信息提供纠正入口，不让用户走通用配置向导。
不根据 Git 相对路径猜模块名，也不通过导入用户包来发现入口。

例如 `assignments/basics/example_pkg/bpe.py` 可以解析为模块 `example_pkg.bpe`、
cwd `assignments/basics`，解释器来自上层 `.venv/bin/python`。
默认不添加额外参数，使用程序自身的默认行为。明确运行项目已有任务时，复用该任务
声明的参数。`--trace` 等可选参数可在次级目标选项中添加并记住，但不是 Run/Debug
的前置条件；不能从入口图标臆造应用参数。

直接使用选定解释器与 `uv run --frozen` 是不同启动策略。`--frozen` 阻止更新
锁文件，但仍可能准备或同步环境；打开文件不能触发这些操作。
通过支持的项目元数据自动识别 uv 项目，不要求用户编写 uv 命令。
uv 目标包含可见的准备阶段，让 Run 与 Debug 使用同一解析后的解释器、参数、
环境与 cwd。缺依赖时显示可操作的错误，不以偷偷切换解释器来“恢复”。

Run 与 Debug 消费同一解析目标。Debug 将文件/模块入口转换为 debugpy 配置，
不再单独猜命令。参数使用数组，环境变量值不公开。Shell 命令是独立的显式目标类型，
不尝试把任意 Bash 解析成 Python DAP 配置。

Farming 管理的分析/调试工具存放于已校验、带版本的私有目录，与项目依赖分离。
安装需要有时限的进度、完整性校验、原子发布与精确临时目录清理。
固定工具遵守 Package Image 安装契约；可选按需工具遵守明确的 Extension 准备契约。
必须验证 debugpy 能使用目标解释器，并且无需装进项目环境。Python 本身由主机/项目提供。
没有可用环境时，精确报告缺失前提，并提供支持的准备操作与进度；
不能把这种恢复变成要求用户编写运行配置。

## 着色与模型版本

### 优先对齐编辑器展示

第一个可见里程碑是打开 Python 后立即获得丰富、稳定的阅读层次，独立于运行与调试。
对齐 Zed 的信息层次，同时保留 Farming 的视觉风格。

当前 Python 词法器主要通过关键词表与统一的 `identifier` 规则分类。
函数、普通方法、关键字参数、属性和用户定义类型通常使用默认文字颜色。
现有主题虽提供类型、函数、变量和枚举色，但没有被识别为函数的 token 不会命中函数色。
基础着色已经存在，问题是分类粒度不足，不能据此认为文件被当成纯文本，或 Monaco
无法展示丰富信息。

现有 LSP semantic token、悬停、符号高亮和 inlay provider 已接入，但需要运行中的
服务真正提供对应能力，目前也只对已保存文件生效。Python 服务缺失会让这一层不可用；
仅安装服务不能补齐结构层，打开 semantic highlighting 开关也不会凭空产生语义 token。

以 `parser.add_argument("--input", type=Path, default=DEFAULT_INPUT)` 为例，
按以下信息角色展示；不要求每个角色都使用不同颜色：

| 信息 | 展示契约 | 依据 |
| --- | --- | --- |
| 关键字与控制流 | 统一关键字强调色 | 本地语法 |
| 函数定义与调用 | 同一可调用对象色系，包含方法调用 | 本地语法；LSP 可补充符号身份 |
| 类型与类型注解 | 明确的类型色系 | 显式语法；推导/导入类型需要语义证据 |
| 属性与关键字参数 | 与接收对象/局部变量形成区分 | 本地结构上下文 |
| 常量与内置对象 | 一致的常量/内置对象角色 | 字面量语法或声明的命名约定；LSP 可修正 |
| 字符串与 f-string | 文本保持字符串色，插值内部按代码解析，边界有区分 | 本地语法 |
| 局部变量、标点、注释 | 正文中性可读，标点克制，注释弱化但清晰 | 本地语法与共享主题 |

大写名称只是着色约定，不证明 Python 对象不可变；调用表达式只证明它处于调用位置，
不等于知道目标函数的真实类型。类型签名、文档、推导类型、诊断和符号身份由语言服务
提供证据，不能为增加颜色或提示而臆造。

结构上下文也需要展示：在路径面包屑后增加当前类/函数，复用解析范围改善折叠和当前
作用域引导线，通过现有符号导航面板按需展示大纲。当前面包屑只显示文件路径。
Monaco 已经可用的引导线与折叠继续保留，改善信息来源，不叠加第二套装饰。
这些投影都绑定同一当前模型版本。

Light、Dark、Paper 使用少量一致的语义色系，不直接照搬 Zed 色值，也不把每个变量
都染成亮色。同时检查选区、符号引用高亮、诊断下划线和未来执行行叠加后的可读性。
Inlay hint 保持次级层次，只展示服务真正提供的信息，不靠猜测类型制造丰富感。

同一段代表性 Python 同时验证“分类正确”和“实际颜色正确”。关闭 LSP 后，打开、
输入、保存、切换文件仍应保留结构层次。覆盖嵌套调用、带装饰器及多行定义、f-string
表达式、Unicode、不完整语法与作用域面包屑，验证全部三种主题。随后验证 LSP 信息
准确叠加，不随服务启动更换整套基础色系，也不恢复过期 token。
视觉对照使用同一代码与可比视口，不只比较两张内容不同的编辑器截图。

### 结构提供器接入

保留 Monaco。Python 结构提供器拟使用按需加载的浏览器 Worker 和固定版本的
Tree-sitter grammar，自行编写到共享主题 token 的映射。
正式引入前验证 Monaco token 接入、增量编辑、UTF-8/UTF-16 位置转换、Worker 销毁、
大小限制以及打包/CSP 行为。不新增第二套编辑器，不使用海量逐字符 DOM decoration。

由一个 token 合成者合并结构结果与可用 LSP tokens；注册两个竞争的语义提供器
不等于合并。本地语法描述当前草稿；LSP 契约正式扩展前仍只描述已保存文件。
编辑后清除旧 LSP 覆盖，本地着色继续工作。每项结果绑定模型身份与版本，
迟到结果不能覆盖替换后的模型。

## 执行与终端集成

执行作为 Project/workspace 资源；工作区权限属于某 Agent 时，归属精确的 Agent。
从 Agent 导航过来不意味着转移 Project 资源的归属。不创建假 Agent。
停止/删除所有者 Agent 或移除其工作区时，停止对应执行；Project 任务不随无关
Agent 的生命周期变化。

现有终端路径以 Agent 为键，包括浏览器挂载与 checkpoint 授权。
需要在共享协议边界引入有类型的终端引用，区分 Agent 终端和执行终端；挂载、输入、
resize、清理前都解析真实所有者。迁移时兼容形状只留在边界，新代码不传假 Agent id。
Code 与 CRT 继续使用同一套 checkpoint/delta 实现和原生 PTY host。
这需要协议与回归工作，不能只在编辑器下面放一个终端组件。

Agent provider 的活动观察器不用于执行终端。任务退出由原生 host 的进程结果决定，
不通过提示符或输出静默推断。调试器 `exited`/`terminated` 事件与 PTY 退出可能以
任意顺序到达，由一个所有者汇合状态并精确清理子进程，分别保留程序退出码与适配器
错误；任意一端消失时也有明确的结束时限。

打开终端只显示兼容的用户 Shell，不执行命令；新建终端创建新的 Shell。
插入命令只填写用户命令输入区，不提交；Run 将明确目标提交到独立执行。
不向 coding-agent 终端注入命令，也不从终端文本猜测 Shell 空闲。
VS Code 的聊天代码块插入同样使用不执行的命令操作；Codex 命令执行/轮询会话是另一种
生命周期契约，不能用它改写 Farming 的持久终端语义。

## 调试协议与源码状态

DAP 服务负责协议帧、有界请求、请求/事件顺序、能力协商、会话状态和适配器反向请求。
Python 适配器负责 debugpy 准备和启动配置。`runInTerminal` 创建归属明确的原生 PTY
执行并返回进程身份，不打开浏览器所在机器的外部终端。

初始化适配器，开始 launch，接收 initialized 事件，设置断点，支持时发送
configurationDone。launch 响应可能晚于配置；等待 launch 完成后才处理初始化会
造成死锁。控件按适配器声明的能力显示。

断点意图按工作区/文件与源码版本保存，运行时验证属于具体调试会话，保留适配器修正
后的行号。待验证、已验证、禁用、拒绝分别显示。编辑时重定位草稿断点，但不能声称
运行中的代码也跟着移动。调试期间保存源码发生变化时，显示源码不一致；在获得有效
映射或重新运行前，不显示误导性的执行行/已验证断点投影。

暂停快照有 stop revision，调用栈、作用域和变量引用仅在该版本内有效，恢复运行后
立即失效。变量子项按需、有界读取；迟到响应不能恢复上一次暂停的值。
首期支持行断点与验证、调用栈、变量、暂停/继续和单步。
Attach、表达式求值、条件/日志断点与多进程调试作为后续能力。

源码导航经过现有文件授权服务。适配器返回工作区外路径不等于获得读文件权限。
首期可展示外部调用帧的路径与函数信息，并明确源码不可用；库源码浏览需要单独的
只读授权边界。

## 最小状态模型

| 所有者 | 状态与触发 | 守卫、副作用与终态 |
| --- | --- | --- |
| 上下文服务 | unresolved → discovering → ready / needs-input / failed | 自动应用有效默认值；只有缺少必需信息时进入 needs-input；文件/root 与 generation 必须匹配；打开选择器刷新证据 |
| 工具管理器 | absent → preparing → ready / failed / cancelled | 同一工具身份合并准备；取消一个订阅者不取消其他订阅者；不发布半成品 |
| 执行服务 | preparing → starting → running → exited / failed；活动状态 → stopping → stopped / cleanup-failed | 副作用前验证权限、保存、选择版本和目标；创建进程前持久化身份；Stop 硬杀精确归属的进程集合 |
| DAP 服务 | initializing → configuring → running ↔ paused → terminated / failed | 握手按事件推进；只接受匹配暂停版本的单步；终止使请求和变量失效 |
| 浏览器挂载 | detached → attaching → attached / failed | 快照与有序 revision；关闭界面仅解绑；重连读取状态，不重启程序 |

初始时限：发现 10 秒，工具准备 120 秒，执行启动/DAP 握手 30 秒，普通 DAP 请求与
停止对账 10 秒。各所有者负责取消或隔离超时工作并发布终态；交互程序运行本身没有
任意总时限。可根据测试调整数值，不能取消有界要求。

启动操作携带绑定所有者和目标摘要的客户端 operation id。重复准入返回同一已记录
操作；同 id 不同内容拒绝。持久化终端身份支持 create 响应不明确后的对账。
浏览器超时后查询操作，不重放命令。串行准入防止重复点击意外创建多个会话；
用户明确的并行运行使用不同 operation id。

Step/Continue 按会话和暂停版本串行处理。不明确的响应不自动重发，而是结合
适配器事件与有界状态读取对账。无法确定状态时，使调试会话失败并清理精确进程集合，
不猜测它是暂停还是运行。

浏览器重连不停止后端任务。仅 Server 丢失时，可按现有恢复协议重新挂载精确验证的
存活 PTY。DAP 控制连接已经丢失时，不声称可恢复：终止并对账孤立调试执行，
保留断点/目标配置供重新运行。完整 Farming stop 硬杀所选归属进程；重启不自动重新
执行用户程序。清理失败可见，保留归属证据，供有界恢复使用。

所有读取和修改均校验所有者与工作区权限。只读分享不能发现可执行能力、准备工具、
选择环境、运行、调试或写入终端。快照与事件按精确资源、epoch、revision 隔离。

## 交付顺序与验收

先用可清理的临时 fixture 验证三个架构接点：Monaco 结构 token；非 Agent 原生终端
及 checkpoint 恢复；debugpy 通过 runInTerminal 使用独立目标环境。
这些是可行性验证，不是用来代替最终产品的实现。

随后按依赖顺序交付：环境/上下文归属和选择器；Python 着色与环境一致的分析；
解析后的 Run 目标和终端资源；DAP 与断点/单步界面；组合失败与恢复验证。
Python 特有逻辑始终留在适配器内，用第二种假语言适配器验证公共契约无需 Python 字段。

- 全新 Config，没有解释器覆盖、运行配置或 launch JSON：打开嵌套 Python 文件，
  运行、打断点、调试、单步，全程无需打开配置界面。存在多个解释器本身不能打断

  Unicode 路径、venv 符号链接身份、`src` 布局、显式 uv 准备。

  LSP 缺失/延迟不能抹去本地着色。Light、Dark、Paper 共用主题语义。
