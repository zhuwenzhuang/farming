# 交互性能

> English version: [interaction-performance.md](./interaction-performance.md)

性能诊断通过现有权威状态所有者观测用户操作，不确认 Terminal 输入、不重放修改、
不改变选择，也不拥有文件或 Agent 状态。前后端各自使用单调时钟计算耗时；墙钟只用于
对齐事件窗口，不能直接相减推算单向网络延迟。

## 观测状态模型

一次观测从 pending 收敛到完成、失败、取消、被替代、超时或隐藏/不可观测状态。
每条观测都有截止时间和容量限制；迟到回调不能完成被替代的观测。页面隐藏会终止待完成
的展示观测，不能将后台标签页限速计为交互卡顿。诊断失败不得改变产品操作结果。

Terminal 分别记录输入派发、后续输出、渲染器完成和后续帧机会。输出只是时间关联：
并发输出、不回显程序、输入法和多个写入者都使下一段输出不能被认定为按键回显。
没有输出记为 unobserved，不代表输入慢或失败。帧机会也不等于 GPU 已完成呈现。
首批覆盖 Farming Code 的 Terminal 输入和 Terminal 视图 Agent 切换、Monaco 文本文件
打开与编辑、文件保存，以及共享 Workspace / Language Server 请求（包括目录树和搜索）。
这不代表已经覆盖 CRT、Chat 消息发送、二进制预览或精确的像素呈现时间。
编辑器区分模型变化、草稿传递和帧机会；程序设置模型不能计为打字。
保存记录本次捕获版本的结果，不能用更新草稿是否干净来判断旧保存是否成功。

## 开销、隐私与诊断

内存观测有界，普通结果采样，慢操作和失败在明确容量限制内保留，异步批量写入有界日志。
必须报告丢弃条数和持久化错误。不记录按键、命令、文件正文、路径、凭证、任意错误文本
或 DOM 快照。目标标识使用页面或服务端启动周期局部的不透明散列。诊断属于 Config，仅 Owner 可访问，
不发送给外部服务。

浏览器通过 `window.farmingPerformance.snapshot()` 提供最近 512 条观测。Owner 可访问
实例 base path 下的 `GET /api/diagnostics/performance`，读取服务端最近 512 条观测及
丢弃和写入失败计数。快照按前后端和请求种类分别汇总数量、结果与 P50/P95/最大耗时；
服务端的浏览器统计仅代表上传样本，不能作为总体的无偏分位数；隐藏、不可观测结果不进入
延迟分位数。同一路径接收有界浏览器批次。只读分享不能读取或提交诊断；关闭
认证的实例沿用其他 Owner API 的本地 Owner 语义。

日志位于 `<config>/logs/performance/interactions.jsonl`，保留三个历史分段（`.1` 到 `.3`），
在新批次将使文件超过 2 MiB 前轮转。浏览器至多每秒上传一次，每批 32 条，结果不确定时
不重试。普通成功观测采样 1/20；慢操作（输入 100ms、浏览器操作 500ms、服务端 Workspace
请求 200ms、长任务 50ms）和非成功结果不采样，但仍受容量限制。待完成观测最多 128 条，
浏览器上传队列 128 条、服务端写入队列 256 条，实例接收额度为每秒 128 条。丢弃计数
明确暴露损失；这不是无损审计日志。输入路径不等待日志 I/O。

Terminal 前后端通过 `id` 关联，Workspace 传输通过 `requestId` 关联。浏览器样本落盘时，
若匹配的服务端观测仍在内存中，也会将其补入日志，即使服务端操作很快而未被采样。
读取时按 `(bootId, source, id)` 去重。服务端 received 到 dispatch 表示排队等待，dispatch
到 service 表示执行完成（Terminal 是 native write RPC，不是 shell 命令执行结束）。
每五秒的运行时样本包含事件循环延迟、进程 CPU 时间、堆内存与输出量，以及有界的各 Agent
输出分组。这些是背景窗口，不证明某个 Agent 造成卡顿。跨机器墙钟可能有偏差，应使用
关联后的各端本地耗时，不能将前后端墙钟直接相减。

已有业务健康探测记录为 `connection.probe`，不新增探测、不改变恢复行为。它的往返耗时
包含网络/代理和两端调度，并非纯网络延迟。这些低频观测不受普通成功采样限制。

远程浏览器到实例的交互是主要优化目标。本地测试仅建立回归基线，不代表远程验收。
应在同一远程访问路径、同一前台操作下，对比有无并发 Agent 负载，报告访问路径、可见
界面、负载数量、样本数、延迟分位数与丢失计数。不能将隔离测试的清理逻辑指向用户的
在线 Config。在线实例启用新采集器需要正常且已授权的部署；本地构建不会自动给远端
服务安装埋点，也不能还原记录启用之前的故障。

分析时对照同一窗口内的前端长任务与帧等待、服务端排队/执行/事件循环延迟/发送积压，
以及各 Agent 的输出活动。时间相关不是因果归因。后台工作即使未展示仍需计量。
验证覆盖有界开销、取消、迟到完成、隐藏页面、持久化失败和多个后台输出源下的前台输入。
固定布局与 Agent 数量增长的开销需要和受网络影响的端到端延迟分别衡量。
