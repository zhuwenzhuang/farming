# Farming Code UI 设计协议

> English version: [ui-design-protocol.md](ui-design-protocol.md)

Farming Code 的导航、Chat、Composer、Files、Review、Settings、Dialog、Menu，以及
Farming 拥有的扩展控件，共享一套设计契约，独立打开的 Code 页面也包含在内。
Light、Dark、Paper 是同一套 UI 的不同外观。Farming CRT、Farming Net 保留各自文档定义的
产品皮肤；嵌入的第三方内容保留自己的 Renderer，但不能接管 Code 外层控件的设计。

本协议拥有元素等价关系、共享控件规格和验收规则。[外观契约](../products/code/appearance-themes.zh_cn.md)
拥有调色板与表面角色，[交互协议](ui-interaction-protocol.zh_cn.md)拥有事件仲裁与焦点转移，
产品文档拥有业务语义和领域行为。这些边界共同生效，不能在没有明确产品理由的情况下，
利用某份文档为另一份契约制造局部视觉例外。

## 元素等价关系

设计或修改控件前，先确定其**语义家族、层级、尺寸/密度变体和状态**。同一外观下，
分类相同的元素必须使用相同规格和共享实现，不因所在页面、Project、Agent Provider 或
Extension 不同而改变。

规格包括字排、图标、布局槽与对齐、间距、控件及点击区域几何、表面、边框、圆角、浮层
层次、动效和交互反馈。只使用相同颜色 Token 不代表设计统一；应比较最终计算样式和可见
结果，而不只是 CSS 声明是否相同。

变体必须表达用户可理解的角色或约束。主操作与辅助操作可以不同，双行 Resource Row 与
单行 File Row 可以不同；但从 Project 打开的上下文菜单，不能仅因入口不同就成为另一类
菜单。不得为了保留偶然差异而发明页面专属变体。角色不同时，共有的 Label、Icon、Action、
Status 部分仍应复用相同规格。

表单选择器与数字输入共享表单字体和外轮廓。工具栏选择器使用明确的紧凑无边框变体，
但不能改变弹出菜单规格。窄屏中嵌入父菜单的子菜单作为内联组，共用父级外表面，
不再绘制第二层浮动外壳。丰富选项可以增加说明行，但不能另改命令文字和状态颜色。

## 语义家族

这是一份分类契约，不要求制造一个万能组件。重复结构和行为使用共享组件；语义标记必须
不同时，可以使用共享 CSS Recipe。Recipe 指在一个所有者中定义的某类控件及其变体的
完整样式。

| 家族 | 常见使用者 | 共享规格 | 合理差异 |
| --- | --- | --- | --- |
| 导航项 | Project、Agent、Settings 导航 | 前导身份、Label、尾部操作、选中和焦点 | 层级、具名密度、状态内容 |
| 内容行 | Open Editors、文件树、Changes、Search/History 结果、Resource | 文字角色、布局槽、操作显露、Active 与 Focused 表面 | 树深度、单/双行内容、领域元信息 |
| 分组标题 | Files、Open Editors、Resource 分组、面板 Section | Chevron、标题、计数与操作对齐 | 层级、能否折叠、可用操作 |
| 按钮 / 图标按钮 | Toolbar、Composer、面板标题、行操作 | 具名尺寸、图标几何、点击区域、主次与状态反馈 | 主/次/辅助操作、破坏性语义 |
| 菜单 / 菜单项 | Project、Agent、文件、Review、扩展操作菜单 | 行密度、字排、Icon/Check/Shortcut 槽、圆角、浮层层次 | 命令集合、Checked/Disabled/Destructive 状态 |
| 表单字段 / 选择器 | Settings、Dialog、Filter、Workspace 选择器 | Label、Value、Placeholder、帮助/错误文字、字段几何 | 输入与选择、单/多行、校验 |
| Tab | 文档及同类视图集合 | Active/Inactive 表现、关闭操作、溢出与焦点 | 与文档连贯的 Tab 与独立导航，由角色文档解释 |
| 浮层外壳 | Menu、Popover、Dialog、Drawer | 表面/浮层角色、标题和操作约定 | 模态性、锚定与宽度策略；它们是不同浮层角色 |
| 反馈 | Loading、Empty/Error、Badge、Notification | 状态含义、Label/Icon、进度和恢复操作层级 | 阻塞与行内反馈、严重程度、业务文案 |
| 内容表面 | Transcript、Markdown、Code、Diff、Editor、Terminal | 文字/表面角色、外围控件、滚动条 | 正文/代码字排、语法/Diff、Renderer 特有行为 |

例如，同一文件名在 Open Editors 与目录树中，若密度和状态相同，就使用相同的 Label
字排；树缩进不能成为使用另一种字体规格的理由。菜单命令与 Combobox Option 可以共享
视觉部分，但分别保留 Menu 与 Listbox 语义。

## 每个设计决策只有一个所有者

| 层 | 拥有什么 | 不得拥有什么 |
| --- | --- | --- |
| 语义 Token | 调色板角色，共享字排、间距、几何、浮层与动效尺度 | 页面专属 Selector，或每个使用者各复制一份相同数值 |
| 家族组件 / Recipe | 布局槽、具体 Token 选择、变体、组合交互状态 | 从视觉样式反推业务状态 |
| 产品组合 | 放哪些控件、内容、层级、布局、领域操作 | 覆盖共享家族的字体、图标、圆角或状态表现 |
| Runtime / 交互所有者 | 权威操作状态、Selection 和事件所有权 | 每个页面重新解释公共视觉状态 |

不随外观变化的尺寸规格放在单一共享所有者中，不在不同主题调色板里复制。现有 Appearance
Registry 继续作为颜色权威。外观可以对表面角色作不同映射，但不得改变家族的字排、几何、
可用操作集合或交互语义。共享尺寸必须同时被渲染和依赖它的几何计算消费，包括虚拟行、
Sticky 区域和 Hit Testing；不得再维护一份独立的 JavaScript CSS 尺寸常量。

具体数值属于这个共享所有者及其验收预期。本协议不把现有局部像素值逐一升级为标准。
已经记录的密度决策，例如 [Project Files 契约](../products/code/project-files-section-design.zh_cn.md#视觉与交互规则)，
在其所有者被明确修改前继续作为约束。

领域样式可以摆放组件、选择已有变体，但不得通过继承的 Custom Property、Inline Style、
更强的 Selector 或 `!important` 暗中重定义公共规格。缺少变体时修改共享规格并验证同类
使用者。Reset 在 Cascade 中应低于组件字排；全局 `font: inherit` 不能抹掉按钮明确规定的
字号、字重和行高。设计结果不得由懒加载或样式导入顺序决定。

## 字排、图标与组合布局

- 文字角色包含完整的字体、字号、字重、行高和字间距。标题、主 Label、次 Label、元信息、
  Placeholder、操作与 Code 的层级保持稳定。辅助操作不能因字体继承或无关强调而意外
  压过所属 Label。
- 同一操作使用同一 Glyph、视觉尺寸和描边/填充规则。已有公共操作图标时，不得用文字
  圆点、Emoji、Unicode 叉号或私有 SVG 替代。图标绘制尺寸与点击区域尺寸分别定义。
  Provider/文件身份及语义状态图形保留外观契约定义的例外。
- 显式划分前导、Label/元信息、尾部操作槽。常显操作参与宽度分配，文字在它们之前截断。
  Hover 覆盖层不能挡住必需状态、让文字混入图标或造成点击目标重叠。长名称、本地化及
  可选操作出现后，仍保持对齐，并能获取完整身份。
- 连续表面的基础层、状态填充和操作层共享同一外轮廓。大 Dialog 与小按钮不必使用相同
  圆角，但两个同类菜单必须一致。菜单宽度可以随内容变化，行密度、字排和圆角规格不变。
- 用表面与浮层角色表达结构层级；Border、Shadow、Focus、Selection 不得分别围住同一
  控件叠加装饰。动效共享用途和时序，遵守 Reduced Motion；发现或完成操作不得依赖动效。

## 状态组合

领域状态保持权威。样式只消费状态，不能推断操作成功、能力存在或某行被选中。Selection
由所属集合拥有；指针位置和键盘焦点是独立输入，不是 Selection 的替代所有者。

| 输入 / 转换 | 设计不变量 |
| --- | --- |
| Hover 进入/离开 | 只改变临时反馈，不改变 Selection 和布局 |
| Selection / Active View 改变 | 给新所有者绘制共享选中效果，不能选中容器 |
| Selected 同时 Hovered/Focused | 组合为一个表面，保留适当键盘提示，不叠加填充 |
| 按下 / 操作开始 | 显示真实 Pressed/Pending 状态，不改变控件几何、不丢失 Label |
| 操作成功、失败或结果不确定 | 使用对应语义反馈；不确定不等于成功，重试仍由领域拥有 |
| Disabled | 禁止激活及 Pressed 反馈，保持可读，保留仍有效的 Selection/Status |
| 外观或密度改变 | 只重算展示，保留身份、Selection、Expansion、查看意图及操作可达性 |

Availability 控制能否激活，Selection 提供持久导航反馈，Hover/Focus/Pressed 与它组合，
Status 仍清晰可读。组合规则由该家族的共享 Recipe 定义一次，覆盖适用的
Selected+Hovered、Selected+Disabled、Pending+Focused 等情况。未规定的组合必须在该
所有者处明确，不能交给偶然获胜的 Selector 决定。

按外观契约为控件角色选择焦点表现；文本输入、导航与非文本控件的 Focus 不能互换。
禁止左侧选中线、Hover/Selection 表面一致、容器不伪装选中项等规则在整个 Code 中适用。
关闭、焦点返回和模态边界使用交互协议；视觉复用不意味着合并不同键盘语义。

## 响应式与输入契约

Density 是由共享布局策略选择的显式家族变体。同样视口和角色不能通过各自的 Pointer
Query 得到无关的几何。输入能力可以改变操作如何显露，不能改变已有操作或资源能否访问。

每个只在 Hover 时显示的重要操作，必须有明确的键盘与触摸路径：常显控件，或可访问菜单
中的明确命令。隐藏桌面操作组时，必须保留这些能力。验收既覆盖从宽屏 Resize，也覆盖
初始即窄屏的加载；手机使用不能以事先在宽屏执行一次操作为前提。

视觉边界与点击边界可以不同，但相邻点击目标不得重叠。主触摸导航可按已有契约保留比密集
明细行更大的点击区域；这不能成为另做一套菜单，或让同家族同密度 Label 不同的理由。
扩大点击区域不能撑高相邻行或遮挡其文字。响应式改变必须保留虚拟几何、滚动位置和当前
交互所有权，不能只保证表面行高。

## 采用与例外

新增或修改控件时：

1. 修改前确定家族、角色、变体、状态与已有同类使用者。
2. 复用共享所有者；还没有时，随实现从代表性使用者中提取最小且已验证的公共规格。
3. 按家族跨相关产品区域迁移，不给每个页面分别重做设计；迁移时删除被替代的局部覆盖。
4. 通过下面的家族与组合界面验收；共享尺寸或变体改变时，覆盖所有受影响的使用者。

有意差异必须在对应正式文档中记录产品理由、语义范围、拥有的组件/Recipe 及验收场景。
临时迁移例外还需要可跟踪的移除条件和有限的使用者范围。Selector 名、旧截图或“这个页面
以前长这样”都不是产品理由。不得只为了让检查通过而扩大例外名单。

这是迁移目标，不代表所有旧控件已经符合协议。新工作不得再增加已知家族的重复实现；
已有违规在迁移前保持可见，写下协议或更新截图不能将其关闭。不得建设没有使用者的万能
组件框架，也不得把不同角色批量改成同一个像素值。

## 验收关卡

每个采用协议的家族，必须在仓库常规检查中具有可执行的所有权和渲染检查，不能只有可选的
手工 Gallery。

| 关卡 | 必需证据 |
| --- | --- |
| 源码所有权 | 调色板与尺寸定义只有一个所有者；使用者不私自分叉公共几何、Glyph、状态 Recipe。适当检查解析后的声明/结构，不对所有布局代码笼统禁止像素值。 |
| 最终等价性 | 真实 DOM 中，同家族/变体/状态的使用者，其字体、行高、间距、布局槽、圆角、表面、点击边界符合公共规格并彼此一致。既比较同类，也比较预期尺寸，避免两处同样错误也通过。 |
| 行为等价性 | 操作反馈、键盘/触摸可达性相同；覆盖 Disabled/Pending/Error、展开、长 Label、可选操作、嵌套/Portal、初始窄屏及断点切换。 |
| 组合视觉验收 | 在接近生产的 Code 场景中比较同类控件，覆盖 Light/Dark/Paper、常规/紧凑布局及支持的鼠标/触摸/键盘路径。检查同时出现的状态、截断、重叠、对齐；使用确定性截图并准确清理 Fixture。 |

共享 CSS 变量不能证明最终等价，继承和 Cascade 可能覆盖它；单个组件的截图不能证明跨
页面一致。不得分别更新各页面的基线来接受设计分叉。不同浏览器/字体环境可需要独立像素
基线，但同一环境中的语义角色和 CSS 几何仍须可比较。

报告必须区分协议接入、已实现家族覆盖、视觉/交互验收。列明未迁移的使用者、未验证的主题
或输入路径，不得把部分迁移描述为整个 Code 已统一。
