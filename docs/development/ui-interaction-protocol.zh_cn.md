# UI 交互协议

> English version: [ui-interaction-protocol.md](ui-interaction-protocol.md)

Farming 的界面不仅共享外观 Token，也共享交互所有权。组件声明边界和产品动作，公共机制
负责关闭事件的仲裁。[UI 设计协议](ui-design-protocol.zh_cn.md)拥有公共控件的等价关系和
规格，[外观契约](../products/code/appearance-themes.zh_cn.md)拥有调色板与表面角色。
共享视觉部分不意味着合并不同的交互角色。

## 区域所有权

一个交互区域包含完整滚动容器、留白、滚动条、触发按钮和通过 Portal 渲染的内容。仅内容列
不能代表交互边界。通过元素引用和事件的 Composed Path 判断归属。区域内的滚动条按下、
触摸或手写笔操作不得被当作外部点击。滚动和调整大小由接收起始 Pointer 事件的区域拥有；
在其他位置释放手势不构成第二次关闭动作。

## 关闭状态模型

组件拥有 View、Menu、Popover 或 Dialog 的 Open 状态；共享 Interaction Layer Registry
拥有每个 Document 内的事件仲裁。

| 状态 / 触发 | 条件 | 效果 |
| --- | --- | --- |
| 打开 / 挂载 | 组件启用交互层 | 注册当前边界和动作 |
| 重渲染 / 刷新 | 同一次打开期间 | 更新回调与边界，不改变激活顺序 |
| 内部 Pointer Down | 事件路径包含拥有的区域 | 保持打开，保留原生操作 |
| 外部 Pointer Down | 最上层允许外部关闭 | 仅关闭该层，保留目标控件的点击和焦点 |
| Escape | 最上层允许 Escape 关闭 | 消费一次，关闭该层，恢复返回焦点且不滚动 |
| 忙碌时 Escape | 最上层禁止关闭 | 消费事件，不关闭，也不传给父层 |
| 输入法 Escape | 正在组合输入 | 交给输入框取消组合 |
| 重复 Escape | 用户持续按住按键 | 消费事件，不连续关闭底层区域 |
| 关闭 / 卸载 | 存在注册 | 删除注册；无交互层时移除 Document 监听 |

嵌套区域优先于祖先区域，即使 React 先挂载子组件。独立区域按激活顺序仲裁。每个事件最多
关闭一层。注册的触发按钮属于内部，因此其点击由自身 Toggle 处理，不能先被外部事件关闭
又被 Click 重新打开。隐藏、已脱离 Document 或 Inert 的区域不得拦截其他区域的输入。

关闭是同步的本地 UI 状态变化，不是后端 Mutation，不得重放保存、删除、启动或网络动作。
异步工作保留各自的 Generation、取消、超时和错误契约。重渲染不得重启工作或改变下次交互
的所有者。

## 焦点与区域差异

Escape 使用 `preventScroll` 将焦点交回仍连接且可交互的触发控件。外部 Pointer 不恢复
旧焦点，由新点击的控件持有焦点。延迟的焦点重试不能覆盖用户后续的鼠标或键盘意图。

菜单保留方向键和选择语义；模态对话框还拥有焦点循环与背景隔离，保存期间禁止关闭不能让
Escape 穿透到底层。完整页面保留导航与滚动所有权，不引入模态焦点陷阱。编辑器与 Terminal
保留领域键盘协议。这些是明确的角色差异，不是分别实现外部点击判断的理由。

只有最上层模态区域拥有 Tab 循环。多个模态层共同持有背景隔离；关闭或卸载其中一个不能提前
恢复背景，最后一个 Owner 释放后才恢复。其他模态层仍打开时，不得将焦点恢复到 Inert 背景。

## 接入与验收

新的可关闭区域使用共享交互层。已有领域 Hook 将关闭行为委托给它，而不是再安装独立的
全局 Pointer 或 Escape 监听。每个组件只有一个关闭 Owner。全局快捷键在交互层拥有 Escape
时必须让出处理权，不依赖监听器注册顺序。

迁移是渐进的。统一关闭行为不代表所有焦点循环、拖拽控制器、选择模型、Hover Timer 或异步
操作已通过统一验收。保留其明确的 Owner，通过各自状态模型与验收证据逐步迁移，不把所有
行为塞入通用事件处理器。

验收覆盖原生滚动条拖拽、留白、触发按钮 Toggle、对话框内的嵌套菜单、Portal 区域、Pointer
焦点转移、输入法 Escape、按键重复、打开时重渲染以及卸载清理。真实组合界面在 Light、Dark、
Paper 中执行相同交互。测试滚动条命中区域时，浏览器自动化必须显示原生滚动条。
