# 实现一个小功能

小功能最适合建立稳定的 Agent 协作方式：范围清楚、反馈快，也容易判断结果是否真的完成。

## 写出最小状态模型

在开始实现前，说明：

- 权威状态由谁拥有；
- 什么触发功能；
- 允许和禁止的状态；
- 成功、失败、取消和超时如何结束；
- 并发或重连时会发生什么；
- 用户如何看到反馈。

示例：

```text
为 Agent 完成通知增加一个“仅当前 Project”过滤选项。
保持默认行为不变。设置由后端保存，界面保存失败时必须显示错误。
补设置读取、写入失败和刷新恢复测试，并更新对应用户文档。
```

## 让 Agent 先提出计划

计划应列出受影响的权威文档、代码边界和验证，而不是文件数量清单。检查计划是否把 Provider 差异留在 Adapter，把权威状态留在后端。

## 分阶段实现

建议按以下顺序跟进：

1. 边界和状态契约；
2. 后端行为与测试；
3. 前端交互与可见失败；
4. 生产形状验证；
5. 用户文档。

每个阶段完成后都可以在 Chat 中要求简短证据，再决定是否进入下一阶段。

## 控制范围

如果 Agent 顺手重构无关模块，要求它说明与目标的直接关系。一个小功能不应借机引入没有被当前需求证明的新抽象。

## 验收

完成时检查：

- 正常路径可用；
- 非法输入被边界拒绝；
- 加载和失败有明确反馈；
- 取消、超时或重连不会卡在永久中间态；
- 测试和文档与行为一致。
