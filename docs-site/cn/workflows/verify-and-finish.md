# 检查、验证与收尾

Agent 说“完成”只是一个需要核对的结论。收尾阶段要确认真实文件、命令结果和用户可见行为都支持这个结论。

## 阅读最终结果

最终说明应该包含：

- 达到的结果；
- 修改范围；
- 运行过的验证；
- 没有运行或无法证明的内容；
- 仍然存在的风险。

只有“代码已修改”而没有验证的结果，不足以完成任务。

## 核对真实文件

使用 Files 打开关键修改，检查：

- 是否改在权威源文件；
- 是否夹带无关格式化或重构；
- 错误路径和边界输入是否被处理；
- 文档是否描述当前行为，而不是实现过程。

## 核对命令结果

在 Chat 的活动记录或 Terminal 中确认精确命令和退出结果。

验证范围应与风险匹配：

- 文案或小文档修改：构建、链接或局部检查；
- 单模块行为：聚焦测试和类型检查；
- 生命周期、恢复或 UI 交互：状态序列测试和真实界面验证；
- 跨 Provider 改动：等价的 Provider-neutral 验收。

## 处理失败和不确定结果

如果验证超时或连接中断，不要直接当作通过，也不要自动重复有副作用的命令。先读取当前状态和产物，再决定是否安全重试。

## 发送最后一次跟进

发现缺口时给出精确要求：

```text
实现本身看起来正确，但还没有覆盖请求取消后的恢复。
请补这个状态序列的测试，运行聚焦检查，并在最终说明中区分已验证与未验证内容。
```

## 整理任务

确认结果后：

- 设置可搜索的 Agent 标题；
- 记录需要后续处理的残余风险；
- 归档已经结束的 Agent；
- 对值得长期保存的结论更新权威文档。

需要稍后继续时，可以从 [Search 与 History](../code/search-and-history) 找回相关 Session。
